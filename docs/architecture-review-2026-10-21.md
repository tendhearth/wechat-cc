# 架构复查(2026-10-21)—— 对照 10-20,定第三批

> 主人 10-21:「再看看整体 app,架构是否清晰」「你做决定。要有设计理念,和同类产品比」。
> 做法:五个只读审查各管一块(组装、单一声明、档位与执行者、主动开口与存储、分层与文档),对着 [10-20 那份](architecture-review-2026-10-20.md)逐条量。数字都是 dev `0209cada` 上量的。

## 一句话结论

第二批把「四张表」立起来了:路由、命令、错误码、执行者事实,核心消费者都只读一份。但架构还不清晰。原因不在缺表,在于**规矩靠注释和行数撑着,机器不管**。表外的频道照样手抄,关机顺序看谁先登记,CC 什么时候开口每条路各判各的。第三批的目标是把规矩交给机器执行:守卫测试和依赖规则。不再加新的约定。

## 设计理念(以后所有架构决定照这五条判)

1. **一处声明,处处推导;推导关系由测试证明。** 一类东西只有一张类型化的表,别处的清单要么从表生成,要么被守卫测试逐条比对。手抄一份、不受守卫的清单就是 bug,哪怕现在内容是对的。
2. **权限跟着入口走。** 一个令牌能碰什么,等于它那个入口实际调用了什么,由机器扫出来,不靠人逐条判「这条算不算私事」。入口删一页,权限自动跟着收。
3. **CC 开口只有一道门。** 每一条没人要它说的话,都经过同一个 `SpeechPolicy`:熄火开关、免打扰、频率、网络守护、微信降级走 App。各条路只负责产出「想说什么」,能不能说、走哪条通道由这道门定。这条是「CC 不骗人」的孪生:**CC 不该开口时不开口**。
4. **功能是能整块拔掉的模块。** 一个功能 = 一份清单(要什么、提供什么、路由、命令、定时、怎么停)。关掉就是不接线,不留残肢。新加子系统只有一种写法。
5. **规矩交给机器,不量症状。** 分层用依赖规则判(core 不碰 `node:*`),不用行数上限。行数上限会把代码挤成一行两千字符,这次已经量到了。

## 和同类产品比:它们怎么解决同一个问题

| 我们的问题 | 同类产品的做法 | 我们照哪条 |
|---|---|---|
| 执行者、路由、命令散在多份清单 | **VS Code** 的 contribution points:扩展只在 `package.json` 里声明命令、菜单、设置,宿主从声明生成一切。**Home Assistant** 每个集成一份 `manifest.json`(依赖、需要的配置、能力) | 理念 1、4:`ExecutorDescriptor` 和 `DaemonModule` 各一份清单 |
| 档位判断散在五处以上(工具闸、派发拒绝、各家沙箱翻译、提示词开关、委派) | **Codex** 把权限编成两个正交轴(`sandbox_mode` × `approval_policy`),执行时只认编译结果。**Claude Code** 的 allow / deny / ask 规则一份配置,所有工具调用经同一个判定 | 理念 1:`Policy = compile(档位, 权限模式)`,每家执行者只声明「我能执行哪几维」,做不到的维度在派发时拒 |
| 九条主动开口的路各判各的闸 | **iOS 专注模式 / 通知摘要**、**Android 通知渠道**:应用只管发,系统一处决定此刻能不能打扰、合不合并、走哪种提醒。OpenAI dots、Meta Muse 这类常驻助理的核心也在这里:**主动的分寸是产品,不是每个功能自带的细节** | 理念 3:`SpeechPolicy`,主人亲手要的(提醒)标 `requested` 明确绕过 |
| 新加一个子系统有五种写法 | **Home Assistant** 的 `async_setup_entry` / `async_unload_entry` 成对出现,卸载是一等公民。**Claude Code** 插件:一个目录,内含 hooks / commands / skills,装上即接线、拔掉即无 | 理念 4:`init` 和 `stop` 成对声明,关机顺序 = 启动顺序倒过来,由容器保证 |
| 链接令牌能读什么靠逐条判 | **浏览器扩展**的权限声明 + 商店审核:没声明的权限,运行时直接拿不到 | 理念 2:链接令牌的范围 = /m 页面源码里扫出来的调用 |

## 第三批:顺序和理由(我定的)

排序按「会不会伤到主人」×「对以后开发的帮助」。每一步单独合。

**3a. `SpeechPolicy`:CC 开口只有一道门(理念 3)——我**
- `request({kind, chatId, origin}) → {allow, channel} | {defer, until} | {drop, reason}`。九条路都改成只产出候选,发送原语收成一个。
- **怎么分「主人要的」和「CC 自己想说的」**(以前没人定,我定):
  - **准绳:看这一句的*内容*是不是主人点名要的,不看开关是谁打开的**(整合者评审 #507)。晨报的开关是主人开的,但内容是 CC 自己挑的,所以算 initiative;定时任务「每天 9 点看邮箱」的内容是主人点名的,所以算 requested。以后加新类型,先按这条归类。
  - `origin: 'requested'` 是主人亲手定了时间的:提醒、他建的定时任务。绕过 care 档;提醒连免打扰也绕过,时间本身就是他要的。
  - `origin: 'report'` 是主人交办的事做完了来回报:不看 care 档,但遵守免打扰(往后推)。
  - `origin: 'initiative'` 是 CC 自己想说的:晨报、周报、信、伙伴、来访、贴纸、记忆通知。care off ⇒ 不说;免打扰 ⇒ 往后推;按类、按天限频;记一本外发账。
- 微信降级:一律交给 `proactive-channel` 选 App,不再有「直接调 ilink」。
- 守卫:扫 `ilink.sendMessage` 的调用点,只允许出现在 SpeechPolicy 和「回复」这条路里。
- 顺带:`tick-bodies.ts`(1303 行)按生产者拆文件。

**3b. `DaemonModule`:一种写法,启停成对(理念 4)——我**
- `{name, needs, provides, init(c) → {stop?}, routes?, commands?, ticks?}`。容器按依赖排序初始化,关机严格逆序。后绑定只剩容器懒取这一种。
- 先修三处漏停(yi WebSocket、知识库定时器、空闲清扫),这是 bug,不等重构。
- 守卫:main.ts 不再出现 `Ref` / `{current}` / 后 set;每个 `init` 有 `stop` 或明说不需要。
- 社交、画室走这条路做成可选模块,对上收敛清单 ①。

**3c. 执行者一份描述(理念 1)——我**
- 显示名下发(⑥,在做)。
- 端点 host 一处:等真机抓到连接后再定,不猜。网络检查(`net-probe`)和网络守护(`call-classifier`)一起对上,两边必须从同一份描述读。
- 注册只在一处:`providers.ts` 和 `wire-workbench.ts` 两边重复的注册收成「描述里的 detect / build」。
- `Policy` 编译器把 Codex / agy / Cursor 的翻译层纳入证明。`guestSafe` 改成必须显式写。

**3d. 微信命令一种写法——我**
- admin / mode / control 三个大入口拆成命令表里一行一条。`KNOWN_SLASH_COMMANDS` 和 /help 从表生成。

**3e. 存储——整合那一路认领或我接**
- `writeJsonAtomic(path, schema)`:唯一的 tmp 名 + rename + 读时校验,30 个直写逐个换掉。
- 记忆定「源」:库和 `memory.md` 是源,其余标生成物。
- `db.ts` 一版一个文件,老夹具从真迁移起步,删掉九个迁就测试的守护。

**3f. 分层交给机器(理念 5)**
- depcruise 加「core 不碰 `node:*`」。现有 53 个列成基线,只许少不许多(数违规条数,不数行数)。
- 删掉三个行数上限,换成依赖规则。
- 桌面接 `@wechat-cc/protocol` 的类型化客户端,客户端路径对表。

**3g. 文档一个入口**
- AGENTS.md → `docs/maintainer/README.md` 是唯一入口。INDEX 降为目录。`architecture.md` 重写成一页现状图。maintainer 里补三份「怎么加」:命令、页面、执行者。
