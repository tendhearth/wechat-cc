# 做法清单:怎么干活

[`rules-from-real-machines.md`](rules-from-real-machines.md) 记的是**代码里的**坑(协议字段、进程超时、路由登记)。这一份记的是**干活的**规矩:动手前看什么、怎么证明、什么时候问主人。两路会话这些天靠记忆和笔记撑着的那些,写在这里,CC 自己跑开发时(规划者、开发者、评审者)读的就是它。设计见 [`2026-10-23-cc-runs-development-design.md`](../superpowers/specs/2026-10-23-cc-runs-development-design.md) §4.3。

每条都带出处(PR 号或日期),守卫 `scripts/practices.guard.test.ts` 查。新加一条走 PR,写清是哪次吃的亏。

## 动手前

- **每条命令都显式进自己的工作区**,别在主检出里跑 git;两个执行者不写同一个工作区。(2026-10-22 一次在主检出 `checkout --detach`)
- **执行者不碰在跑的 daemon**:不 launchctl、不 kickstart、不换 sidecar;临时 HOME 隔离不了 launchd。重启和部署归整合者。(2026-10-04)
- **跑全量前先看负载**:主人在用机器(load 高、前台有重活)就不跑本机全量,以 CI 为准,汇报里照实写「本机没跑」;两个执行者不同时跑全量。(2026-10-22,load 328)
- **仓库文档只引用仓库里查得到的东西**:不写会话名、不写私人笔记的名字;要追溯写 PR 号,写角色(整合者 / 审查者)。(#597、#625)
- **主人看得见的行为要改,先停在设计稿等主人点头**;「你做决定」的授权不外推到主人天天看得见的变化。(Policy 第 5、6 步,2026-10-22)

## 写代码

- **缺省往拒绝 / 藏的方向兜底**:认不出的执行者对访客关门,没记原因的过期按撤回处理。(#556、#581)
- **有风险的能力按需开、不默认开**。(#577 followSymlink 只给两处)
- **显式胜过推断**:能传的参数就传,别从目录名、文件名猜。(#581)
- **新的错误码进那一张表**(`packages/protocol/src/workbench-errors.ts`,名字叫 workbench 但是公共表),别在路由里另起。(#610)
- **自动放行一类命令前,列出它会执行的每一个文件**:测试、make、npm run、eslint、`node_modules/.bin`、连 `git status` 都会执行 agent 改得到的东西。(#606 三轮、#615)
- **CLI 别为读一份配置去链 daemon**:共享的读法放 `src/lib`。(#614,棘轮 39 → 38)
- **加一处主动开口走 `policy.say`**;回主人当面那一句算 reply,基线 +1 要在那一行写理由。(#616)
- **重试要分清「网络抖」和「被拒 / 动过」**:前者指数退避重试,后者停;合并失败先问状态再重试(回应丢了不等于没合)。(#624)
- **被服务方拒绝的调用不原样重试**:按指数退避,成功一次清零。(#627,回忆两天问了 agy 28 次)

## 证明

- **守卫写好以后,先故意把被守的东西弄坏,看它红了才算数**。(几乎每个守卫 PR,#541 起)
- **守卫读源码先把 CRLF 统一成 `\n`;去注释按行判**,别用跨行正则(字符串里的 `/*` 会吞代码、静默少报)。(#541、#568)
- **证明「重构是逐字搬家」用 TS 解析器取源文本逐字比**,或者非空行多重集比;`fn.toString()` 会被 Bun 按缩进重排。(#582)
- **推之前跑整个目录,别只挑「相关的」**;本地用 `bun run verify`(牵连到的 + 全部守卫),整合者合进去以后 `--full`。(#569、#621)
- **加了子命令,`cli.test.ts` 的子命令表和 help 快照一起改**;`verify` 的 import 图看不见根目录那份枚举。(#623)
- **偶发红先读抛错的那行代码再说成因**;「与本 PR 无关」要有证据。(2026-10-21 worktree_not_git 说错过一次)
- **满载套件里的超时不是代码慢**:先看 `uptime`,load 几十上百时跑出的红不作数,单独重跑或看 CI。(2026-10-22)
- **子 agent 的结论先核再用**。(#501,一次 489 行手写光栅化被换掉)

## 合并与部署

- **叠起来的一串 PR:只看最上面那个的 CI,绿了从下往上合**(`wechat-cc ci land <最上面那个>`);合完推 dev 那一次(三平台)才是正式闸门。(#620、#622、#623)
- **别在还有 pending 检查时合;一条都没跑的 rollup 不算绿**。(2026-10-21;#623 jq 的 all 对空列表是 true)
- **已经进 `dev` 的迁移一字不改**,要改走 `[migration-edit]` 并写理由。(#583)
- **部署稳不稳看信号,不死等**:`wechat-cc self soak`;改到开机 / 关机顺序的要 `--min-restarts 1`。(#626)
- **代码和设计稿对不上时,改设计稿并在 PR 里写明偏离**。(#566、#587)

## 跟主人说话

- **CC 不骗人**:坏了不说成关了,没核实的写「没核」,已知限制写进稿子和测试;一句话只在它为真的时候说。(#617 agy 照实说被拒;#627 daemon 开着不说「要先开守护进程」)
- **汇报说「对主人意味着什么」**,不讲 PR 号和文件名;问主人时写清选项和推荐。(2026-10-22)
- **修 bug、重构直接做,事后用人话汇报;看得见的变化逐条问;发版永远问**。(主人 2026-10-23)
- **不按预算挑活,按价值**:影响面 × 确定性 × 方向(AI native、多平台、CC 大总管)。(主人 2026-10-23)
