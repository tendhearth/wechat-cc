# 任务内的同命令批准

工作台权限卡可选「本任务同命令都允许」；微信同一张卡回 `yt <两位码>`。普通允许只批原请求、原 run、完整命令/cwd 与该次申请范围的一次调用，不生成任务、session 或 execpolicy 规则。只有服务端确认可复用时才显示任务选项，不能由客户端自行指定范围。

临时许可沿用 `Rule`、`RuleWhen` 和 `matchRule`：`surface=workbench`、任务 `scope`、执行者、工具与 `commandHash` 必须相符。建立与复用都必须满足 `EDIT_REPORTING_PROVIDERS`；Cursor、自定义 ACP、未知执行者不能使用。规则只存在于当前运行的 `RunPermissions`，结束、取消、归档或重启后不继承，也不改全局 permission-rules.json。现有规则的拒绝、要求询问以及固定红线优先，规则服务失败时也不提供任务许可。

任务许可的指纹包括实际工作目录、完整字面参数，以及实际程序的绝对路径、文件身份和 SHA-256。只归一引号与 shell 识别的空格/tab；保留参数顺序、大小写和引号内空白。每次建立和复用重新解析并读取程序身份。程序须为 root 所有、用户不可写的原生可执行文件，路径和祖先均不可由用户改写，且在 `/bin`、`/sbin`、`/usr/bin`、`/usr/sbin` 内；跟随系统链接后仍须留在这些目录。

执行适配器还必须确认实际消费该程序的是直接 spawn，使用只含 PATH 的受控环境，不经 shell/RC/alias/function，也不继承动态加载器变量；不能猜 daemon 的 PATH。搜索目录均须受上述保护，避免原本空的可写目录后来插入同名程序。Bash 函数甚至可覆盖 `/bin/ls` 这样的绝对名字，因此仅有绝对路径也不等于实际程序身份证明。当前 CLI 布尔审批桥无法提供该直接执行契约，故暂时只提供单次允许；不能确认身份时四端不显示任务选项。执行器以后具备该契约才可接入这个严格准入。Windows 尚未证明系统目录 ACL，也暂不提供任务选项；这些限制均不影响单次允许。

身份检查通过后仍须在无代码委派入口的固定名单中，再过既有低风险分类及红线，另含 echo/pwd/true/false。脚本参数、解释器、测试运行器、包管理器、git/rg/find/sort 等可加载项目代码或配置的工具不提供任务选项。缺少命令事实、环境赋值前缀、长命令（2000 字及以上）、shell 展开/复合命令、未引用的 zsh `=command` 展开也不复用。红线程序名与 macOS 敏感路径保守识别大小写及引号/转义变体，不合并参数大小写。

脚本通过工作区锚定读取，不跟随链接、不读工作区外文件、FIFO 或二进制；每份最多 128 KiB。`source ./helper` 与 `. ./helper` 的无扩展名入口同样读取。package alias 展示 package.json 与能解析到的实际入口。读取失败时卡片显示原因，脚本文本再过红线检查。

预览只识别解释器的工作区内脚本入口、直接执行的工作区内文件及上述 alias/source 入口；外部程序（含绝对路径和 PATH 命令）、外部脚本参数、普通数据参数和 shell `-c/-lc` 命令文本不生成脚本预览。先检查工作区归属，再生成规范化相对路径，卡片不显示越界的 `../` 链。取消误预览不扩大任务放行资格。

**单次批准是调用授权，不是字节授权。** 当前审批协议没有消费不可变执行树的能力，不承诺“执行的就是批准字节”。卡片明确说明「预览是批准时的快照，运行以当时内容为准」，脚本及运行时依赖可变化。python/bun 脚本、heredoc、多行 git、`bun run verify`、测试筛选、`git status`、环境赋值等请求均可由主人单次批准继续；它们不自动复用，也不能借已有自动 allow 规则绕过这次询问。单次批准不再因文件改动、链接替换或无法绑定字节而失效。

Claude、Codex、ACP 的工作台单次请求保留完整命令；长命令只失去自动放行资格。Codex 额外网络/文件授权仍不向允许规则提供命令事实，主人只批准原 RPC 的这一次 accept，不返回 session/execpolicy 扩权。取消、超时、过期 run、已处理请求和审计失败仍按原安全边界拒绝。执行者本来无需批准的档位路径不由本功能改变。

卡片只携带每份脚本前 2000 字。展开时通过 `GET /v1/matter/permission-script`，以任务、待批请求、路径和 SHA-256 读取同一份内存快照，每块最多 8000 字。接口只给 operator/已配对设备，不给链接令牌；卡片了结后全文也失效，不提供任意文件读取。trusted/FILE 的 pet 与 presence 仅投影安全队列元数据，原始 prompt、活动里的待批说明和脚本文本都不返回。桌面批准卡通过宿主使用 operator 单独读取 admin 的 `GET /v1/permissions/pending`；未获得对应 hash 的授权详情、加载失败、条目消失时不显示可批准卡片，晚到的旧详情也不能覆盖新卡。

通知只带脚本路径、指纹和批准卡查看入口，不携带文件片段。无法绑定字节的内联脚本描述也不进入通知；所有通知入账前调用既有 `redactSecrets`，再按长度截断，发送端消费同一份脱敏后的正文。精确源码只留在内存快照与授权批准卡。

微信码与工作台共享到期时钟。网络守护暂停运行时，两边一起停表；任一端处理、取消或过期后，其他端随之收卡。微信/桌宠登记处在同步服务端回调接受决定后才返回成功并消费卡片；失败不提前显示已处理。桌宠收到 false 时保留失败/重试提示，是否已过期由下一份真实状态清除。图形自动化与原生构建由整合者在 mini 验证，本地只跑单测/组件及离线接线测试。
