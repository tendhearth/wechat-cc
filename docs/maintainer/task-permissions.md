# 任务内的同命令批准

工作台权限卡可选「本任务同命令都允许」；微信同一张卡回 `yt <两位码>`。普通允许仍只批这一步。只有服务端确认可复用时才显示新选项，不能由客户端自行指定范围。

临时许可沿用 `Rule`、`RuleWhen` 和 `matchRule`：`surface=workbench`、任务 `scope`、执行者、工具与 `commandHash` 必须相符。规则只存在于当前运行的 `RunPermissions`，结束、取消、归档或重启后不继承，也不改全局 permission-rules.json。现有规则的拒绝、要求询问以及固定红线优先。

指纹包括实际工作目录、完整字面参数及显式脚本的路径与 SHA-256。只归一引号与 shell 识别的空格/tab；保留参数顺序、大小写、环境赋值和引号内空白。截断命令（现有执行者的 2000 字边界）、shell 展开/复合命令、无法确认入口的包装命令、不可安全读取的脚本不提供复用。package alias 同时绑定 package.json 与实际字面脚本；带 pre/post hook 的 alias 仍逐次询问。测试运行器的间接依赖不递归冻结。

脚本通过工作区锚定读取，不跟随链接、不读工作区外文件、FIFO 或二进制；每份最多 128 KiB。读取失败时卡片显示原因，仍可选择单次批准或拒绝。脚本文本再过现有红线检查；单次批准和任务内批准前都重新核对已展示的脚本指纹，变化则旧卡失效。

卡片只携带每份脚本前 2000 字。展开时通过 `GET /v1/matter/permission-script`，以任务、待批请求、路径和 SHA-256 读取同一份内存快照，每块最多 8000 字。接口只给 operator/已配对设备，不给链接令牌；卡片了结后全文也失效，不提供任意文件读取。

微信码与工作台共享到期时钟。网络守护暂停运行时，两边一起停表；任一端处理、取消或过期后，其他端随之收卡。图形自动化与原生构建由整合者在 mini 验证，本地只跑单测/组件及离线接线测试。
