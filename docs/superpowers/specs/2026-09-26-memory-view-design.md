# 「CC 眼中的你」—— 记忆界面改版设计

- 日期:2026-09-26
- 状态:owner 逐项拍板(对话 + 可视化示意),待审本文
- 前置:`2026-09-25-memory-nightly-design.md`(每晚整理 B 步,已上线)
- 示意稿:`.superpowers/brainstorm/53987-1790434074/content/{direction,cc-motion,page-full,wechat-format}.html`(本地,不进仓库)

## 背景

每晚整理上线后真机首跑两个问题:

1. **颗粒太粗**:模型把每栏塞成一条大杂烩(「身边的人」一条装 5 人),「承诺」空着(欠别人的事被塞进身边的人)。通知说不清改了哪件事,下一步「逐条纠错」也没法标。
2. **界面不符合审美**:手机上的「CC 记得你」只是「回忆」页折叠区里的一串列表;微信「查看记忆」是一整坨。

审美基准:`cc-design/CC_DESIGN_SHEET_V1.png`(温柔·好奇·安静·坚定·陪伴·成长·真实·一直在;纸色、柔光、手写点缀)与手机「此刻」页第二版(`apps/desktop/art/cc-mobile-companion/`)。

## 定案(owner 拍板)

- 范围:手机独立页 + 微信排版(C)。桌面不动。
- 页面方向:A「一封信」。
- CC 动效:呼吸 + 随机眨眼(正式资产)。
- 入口:「此刻」点 CC。
- 微信:A 信的口吻,一条消息发完。

## 1. 内容颗粒:一条一件事

`buildNightlyPrompt`(`src/daemon/memory/nightly.ts`)规则段加:

- 「每条只写一件事。一个人一条;一个偏好一条。」
- 「欠别人的、别人欠主人的、约好的事放进『承诺』,有日期在正文写『(期限 YYYY-MM-DD)』。」
- 「当前记忆里一条写了好几件事时,把它拆开:用 update 把原条目改成其中一件(reversal=false),其余用 add。」

拆分走 update + add,不产生 remove,不触发「一晚删除超过 max(2, 30%) 整批作废」。单条 200 字、全文 3000 字上限不变。

## 2. 手机「CC 眼中的你」页

**入口与导航**

- 「此刻」首屏的 CC(`home-character`)可点,点开切到新的 pane `p-you`(不占底栏);左上「← 回去」回到「此刻」。
- 删除「回忆」页里的「CC 记得你」折叠区(`mem-box`)及其脚本。

**顶部**

- 正式 Light CC 资产(`canonical/lit/front.png`,已嵌在页面里,和「此刻」共用同一份 base64)。
- 呼吸:整体 `scale(1)↔scale(1.025,1.035)`,4.2s,锚点脚底;身后柔光同周期明暗。
- 眨眼:每 3–7 秒随机一次,帧序 `blink-half → blink-closed → blink-half → front`,每帧 70ms。两帧取自 `sprites/lit/blink-{half,closed}.png`,构建期缩到 256px 嵌进 `mobile-presence-art.json`(与现有冻结图同一机制,逐字节校验照旧)。
- 只在 `p-you` 可见且页面在前台时眨眼;`prefers-reduced-motion: reduce` 时呼吸与眨眼都关。
- 手写一句(楷体,`#8a7a66`),按状态:
  - 最近一次整理(36 小时内)有变化 →「昨晚又认识了你一点。」
  - 有记忆但最近无变化 →「这是我眼中的你。」
  - 还没有 memory.md →「今晚我会第一次整理。」,下方五栏不出现。
- 一行小字:「最近整理 · <本地日期/时间的口语化>」;连续失败 ≥3 次时换成「最近几次整理都没成功,下面可能是旧的」。

**「昨晚」便签**(最近一次整理在 36 小时内且有可说的变化时才出现)

- 最多 3 条,顺序同通知:新记下(add 进承诺)、改了(update,附「原来是:…」)、删了(remove,附原因);其余 add / update 也列入但排在后面。多出的写「还有 N 处」。到期归档(expire)不列。
- 标签是小圆角胶囊(「新记下 / 改了 / 删了」),正文照常。

**五栏**(纸面分段,不是卡片;栏名字间加空格作 eyebrow,如「承 诺」)

- 顺序:承诺 → 关于你 → 偏好 → 身边的人 → 近况;空栏不显示。
- 承诺:正文里的「(期限 YYYY-MM-DD)」从显示文字中去掉,改成右侧暖色小字(今天/明天/周X/M月D日)。
- 身边的人:正文含「——」或第一个「:」/「:」时拆成「名字 | 关系」两列;否则整句。
- 最近一次整理新增 / 改过的条目后加小橙点。
- 页尾楷体一行:「不对的地方,直接跟我说。」

**数据**

- `GET /m/api/memory` 响应增加 `changes: Array<{ kind: 'add'|'update'|'remove'; section; text; before?; reason? }>`(取最近一次整理日志、36 小时内,不含 expire)与 `failures: number`;已有字段不变。
- 所有文字用 `esc()` 进 innerHTML;不接受任何 HTML。

**体积**:页面整体仍须满足 512KB 中继帧(现有测试);新增两帧眨眼图约 30KB。

## 3. 微信「查看记忆」

`readCurated()`(`nightly-runtime.ts`)输出改为(纯文本,一条消息):

```
这是我眼中的你 🌙
凌晨 4 点整理的,昨晚改了 2 处。

【昨晚】
· 新记下:…
· 改了:…(原来是…)

【承诺】
· …(周五)
…
【关于你】 / 【偏好】 / 【身边的人】(「名字 —— 关系」)/ 【近况】

不对的地方直接跟我说。在「随身 CC」点一下我,能看到更好看的版本。
```

- 时间口语化:按主人时区,今天/昨天 + 时段(凌晨/早上/下午/晚上)+ 点钟。
- 【昨晚】规则同手机便签;无变化则省略该段,第二行写「最近没有新变化。」。
- 空栏省略。连续失败 ≥3 次时第一行换成失败提示(保留现有文案)。
- 「查看记忆」管理命令在前面加的「🧠 我记得的你:」前缀去掉(文案自带开头)。

## 4. 测试

- 提示词含两条新规矩与「拆分用 update + add」;`applyNightly` 对「1 条 update + 4 条 add」的拆分批次 ok 且无 remove。
- `/m/api/memory`:`changes` / `failures` 形状;无 memory.md 时 `sections: []`。
- 手机渲染(照 `apps/mobile/pairing.test.ts` 的经典脚本跑法):三种状态(无记忆 / 有变化 / 无变化)、期限标签、身边的人两列、所有文字经 `esc`(含 `<script>` 的条目不产生元素)。
- 眨眼帧:`mobile-presence-art.json` 逐字节校验扩到新两帧;512KB 帧测试照旧通过。
- 微信文案:完整格式快照一条 + 无变化 / 失败两种首部。
- 行首不许 `(` / `[`(已有测试)与 `build:mobile` 同步测试照旧。

## 不做

- 逐条纠错按钮(下一步 A)、「我注意到…」(C)。
- 桌面界面;底栏新标签;微信里按栏分页。
- 「翻本子」开场动画(owner 选了呼吸 + 眨眼)。
