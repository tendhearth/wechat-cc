# T4：话题泡泡与睡一觉收起（设计稿）

> 主人 11-06 经整合者审过点头(例外加限制:只算主人看得见的事;最近一排默认 6)
>
> 依据：[方向与主人已定](2026-11-05-one-conversation-topics-direction.md)、[T1–T3](2026-11-05-topics-t1-t3-design.md)、[P3 路由一族](2026-11-05-p3-one-route-family-design.md)、[P2 变化提示](2026-11-02-p1-change-feed-design.md#p2下一步不在本稿)。界面沿用 [U4b](2026-11-05-u4b-desktop-one-language.md) 的状态、行与设计 token。

## 1. 目的与边界

主人聊起旧事时，能看清 CC 想起了什么、上次到哪、还有什么在做。对话是主角，泡泡是收着的背景；一次只展开一个，不另开聊天窗口。

主人已定：话题由 CC 决定；每晚记忆运行就是「睡一觉」，之后泡泡收起，再聊起再打开；输入框上方放最近 5–8 个话题。本文把这些方向落成接口和三端草图，具体可见方案仍 **待主人点头**。

T4 只定义话题泡泡，不合并「一起做 / 此刻」，不搬主导航、不创建新的对话或项目容器。T5 再定义统一入口。已有改名、合并、删除话题的方向不撤销；本次不顺带设计完整记忆管理器，也不把新管理按钮塞进泡泡。

## 2. daemon：状态及转换

### 独立存储

复用 `threads`、`topic_entries`（v104）与 `matter_topics`（v105）。`threads.status = active | dormant | done` 是记忆生命周期，不能拿来表示泡泡开关。

提议下一可用迁移新增 `topic_bubbles`（实际版本由整合者分配，不抢占迁移号）：`thread_id` 主键并外键级联删除、`state: open | closed`、`opened_at`、`last_recalled_at`、`last_opened_by_owner_at`、`activity_revision`、`closed_sleep_id`。初始 closed，历史话题不全部弹开；不改历史记忆。时间用带时区的时间戳，话题 id 保持不变。

另存有限的回忆引用：按主人 turn/request 的稳定 id 去重，记录 topic id、该轮真正注入的 entry ids、相关 message ids。保留最近几轮供展示，不复制消息正文，不把搜索候选当成已回忆。与已存在的 episodes 一起提供消息来源；无法证明关联时宁缺毋滥。

### 转换表（对应可见行为均待主人点头）

| 触发 | 状态与副作用 | 主人看见什么（待主人点头） |
|---|---|---|
| 主人轮次实际采用 T2 recall 的结果 | 对命中的每个 topic open，更新 last_recalled_at 与 activity_revision，保存本轮引用；微信、桌面、手机共用同一写口 | 最近话题行更新，标签可点；不抢焦点、不自动展开详情 |
| 主人轮次实际采用 `topic_search` 的结果 | 搜索 handler 返回成功且非空、结果交回主人当前轮时，经同一写口 open；仅索引候选、后台搜索不触发 | 换种说法想起的旧事也出现在话题行 |
| 主人点话题 | 幂等设 open，更新 last_opened_by_owner_at 与 activity_revision；不发送聊天、不强制注入下一轮提示词 | 当前设备展开详情；其他设备只同步开关数据 |
| 收起详情 / 返回对话 | 只清当前设备的展开选择，不写 closed | 泡泡仍可从标签打开，聊天草稿和位置保留 |
| 夜间成功收尾 | 按下述睡眠边界批量 closed；不删话题、条目或消息 | 无阻塞事项的泡泡收起，标签仍可再点 |
| 相关事项开始 / 等批准 / 等回答 | 提议设 open；包含刚建立关联时已在运行的事项 | 有活的话题保持可达，状态跟随事项 |
| 最后一件阻塞事项结束 | 保持 open，下一次成功睡眠才 closed | 先能看结论，不突然消失 |
| 话题合并 / 删除 / 私密性改变 | 合并引用到保留 id，去重并保留较新的活动；删除级联；权限变化立即失效缓存 | 被合并的选中项换到保留话题，删除项退出详情；不会残留旧标题 |

泡泡失败不能阻塞正常回话；记录失败并可重试。重试同一轮不重复加引用，也不因迟到的重复请求把昨晚已关的泡泡重新打开。读取列表、详情、hub 订阅都是只读，永不隐式开泡泡。

### 睡眠边界与例外

挂在 `src/features/memory/wire.ts` 已有 `afterSleep` → `consolidateTopics` 后面。不是独立按墙钟 04:00 关，也不是每 15 分钟 tick 就关。沿用夜间调度与成功运行的语义；手动整理若进入同一个成功 afterSleep，也算一次睡眠。

开始时取 sleep id 和候选泡泡的 activity_revision；记忆真正完成、话题 consolidation 无失败且未被网络守护中断，才执行收起。当前 consolidation 只有汇总结果、没有逐话题成功证明，因此第一版保守地整批成功才关；失败、跳过、进程中断均保留原状，下次成功再处理。零条目、无需模型的正常完成也能关，不依赖「合并了几条」。

收起事务里重新检查候选 revision 和当前关联事项：睡眠期间新聊起、主人刚点开或事项刚变化的泡泡不关。相同 sleep id 可幂等重试，重启不补关一次未成功的睡眠。跨存储状态变更必须串行校验并有后续事项变化重新 open 的兜底，不能只相信睡前快照。

**例外：待主人点头。** `matter_topics` 下任何主人有权查看的事项仍在运行、等批准或等回答，话题就保持 open。以统一 Matter/轮/待响应投影判断，不用 `threads.status`、标题关键词或一张任务表的旧状态猜；同一事项跨多个话题时都保留。已结束、失败、取消、归档的历史事项不阻塞；delegate 的无 matter 引用不当成永远运行。事项状态暂不可读时保守保留，待恢复后下一觉再判。

## 3. 泡泡内容与层级（全部待主人点头）

1. **标题、description、一行现状**：description 表示「它是什么」，现状沿用 consolidation 生成的 summary，不另让模型编。缺失就不占位。运行 / 等你回应使用统一 matter 状态词与记号；泡泡 closed 只表示收起，不写成「事情完成」。
2. **相关事项**：先等批准 / 等回答，再在做；每行标题与状态，点进现有事项详情。待响应时主要动作是打开那件事，批准与回答继续走现有入口及 runId 校验，不新增泡泡批准口。
3. **CC 记得**：默认最多 4 条 live 条目，未兑现承诺、最近相关决定与进展优先。该轮确实注入的条目标「这次想起」，与普通相关条目区分；最多沿用 T2 的 6 条预算，已失效条目不冒充本轮记忆。点条目展开已有 body、来源与时间；不在卡面展开长文。
4. **最近聊到**：默认最多 4 条可验证关联的消息，显示说话者、时间和短摘录，点回原对话位置。新轮用保存的引用，旧记录可用该话题 episodes 在主人 chat 内取；重叠区间只是相关记录，不声称每句话都只属于这个话题。agent 过程仍去事项详情看。

「更多」按区分页，默认各区不超过上述数量，事项先取 3 行再给总数与更多入口。消息只渲染安全文本，附件只显示授权后的已有入口。空区直接省略；全部为空显示「还没有记下内容」。读取失败显示「暂时读不到，重试」，保留可用内容；断线显示「尚未同步」，不能把旧缓存标成刚更新。以上文案、入口、数量均 **待主人点头**。

快速切换行（**待主人点头**）：默认 6 个、允许布局在 5–8 个内选择，按 `max(last_recalled_at, last_opened_by_owner_at)` 降序、id 稳定打破同时间并列；不足不补空位。记忆抽取、条目写回和事项心跳不挤乱顺序。closed 话题仍可占最近标签，点击会重新 open。进行中但不在最近 8 个内的话题保留在完整列表，沿用原事项提醒，不把整条标签行变成任务栏。「更多话题」入口可查看其余历史并点开；没有历史时整行隐藏。

## 4. 一族路由与实时 frame

以下是待实现契约，不宣称代码已存在。沿用现有 `/v1/memory/topics/search`，新增同一家族；桌面、App、网页同形状同处理器，不新增 `/m/api` 别名。

| 路由 | 输入与结果 |
|---|---|
| `GET /v1/memory/topics` | `view=recent|all`、有界 limit/cursor；返回 `{topics, nextCursor}`，每项有 id/title、bubbleState、最近活动、事项状态摘要；recent 上限 8 |
| `GET /v1/memory/topics/detail` | `id`，可带区名和分页 cursor；返回 `{topic, entries, matters, messages, pages, revision}`；默认内容预算见 §3 |
| `POST /v1/memory/topics/open` | `{id, requestId}`；返回 `{id, bubbleState, revision}`；仅主人主动点击使用 |
| `GET /v1/subscribe/topics` | 桌面长轮询，`since` 和有界 `wait_ms`；返回与 hub 相同的小摘要，不带正文 |

在 `packages/protocol/src/routes.ts` 一处登记档位、operator、宿主与 `phone`，schema 在协议包定义一份，生成客户端调用及桌面宿主白名单。手机设备可走 `phone: {link: 'none'}`；不为这项功能放开短期链接令牌。沿用 P3 分发、模块门、帧预算与稳定错误码；无权限 topic id 与不存在统一 404，非法参数 400，模块不可用 / 暂不可读沿用项目既有码。分页 cursor 绑定主人、topic 和区名，不可信客户端不得凭 cursor 越权。超帧先截短摘录并分页，不静默丢掉待响应事项总数。

hub 新增订阅主题 **`topics`**（此处 topic 指传输主题，区别于记忆话题）。提议帧：

```text
{ topic: "topics", epoch, seq,
  data: { revision, recentIds: ["…"], openIds: ["…"] } }
```

这是有界小摘要：recentIds 最多 8；openIds 只取有界首批并带 `hasMoreOpen`，全量按列表分页拉。revision 随所有影响列表或详情的变化递增，即使 id 列表未变，条目正文、状态、消息引用变了也触发。客户端收到新 revision 重拉当前列表与已展开详情，合并在途读取；不在帧里搬历史。桌面长轮询读取同一投影；App、网页走现有加密订阅通道。序号 epoch/seq 沿用 hub，重连拿当前快照、epoch 变就失效重取，不把 seq 当 MatterLog cursor 或持久业务版本。

沿 P2 扩展 `src/lib/write-hints.ts`：在 threads / entries / matter_topics / bubble / 回忆引用的唯一写口发按 Db、主人 chat 作用域的 `topics` hint。回调只 poke，不同步读写；微任务合并，回滚导致的空提示由快照去重。MatterLog 变化和 matter 行提示通过关联表影响 topics；主人消息写入只在关联记录更新或命中 episodes 时影响相关摘要。详情读取与 hub 读取共用投影函数。30 秒安全重算兜漏信号，无订阅者不轮询；快照不得放每次变化的当前时间。投影失败不发布空列表掩盖错误，恢复后补推当前快照。

## 5. 私密性

私密话题只出现在主人自己的桌面、已配对 App 和已认证设备网页中。桌面 operator 也必须确认是主人操作入口；file/trusted、非主人 admin session、执行者、来访会话、federation 与 link 令牌均不能通过这些展示接口获取私人内容。内部 admin 权限本身不等于「主人表面」。主人未配置时不给数据。

列表、详情、open、订阅准入与每次重算都走相同 owner scope 校验；只查主人 chat 下的话题及消息，关联事项再走各端现有可见性检查。返回前过滤，不能先在全局帧广播再靠 UI 隐藏；openIds、计数、revision 也不得泄露其他范围的存在。设备撤销、主人配置或 private 标记改变时清缓存并重验订阅，登出清本地缓存；私密标题不进推送、共享链接、诊断日志。沿用 T1 入库脱敏，T3 私密话题永不进执行者简报的规则不变。

## 6. 三端草图（全部待主人点头）

只在现有主人对话输入框上方挂行；不另添一级导航。桌面宽屏把选中泡泡放在对话旁的可收起面板，窄屏使用覆盖面板。统一暖纸、字体、间距、状态映射与细线控件，不给每个话题发一种颜色；不用动画自动挤动正文。

桌面草图（**待主人点头**，示例均为虚构）：

```text
┌─ 现有主人对话 ─────────────────┬─ 服务器             收起 ─┐
│ 你：那台机器后来怎么样了？      │ 家里的服务与备份          │
│ CC：上次已经……                 │ 现状：正在检查备份        │
│                                │ 在做  检查备份    查看 →  │
│                                │ CC 记得                   │
│                                │ · 每周核验一次  这次想起  │
│                                │ · 备份留在本地            │
│                                │ 最近聊到                  │
│                                │ 你：上次的备份……  回看 → │
│ [服务器] [旅行] [菜谱] … [更多] │                           │
│ [跟 CC 说一句……          发送] │                           │
└────────────────────────────────┴───────────────────────────┘
```

原生 App（**待主人点头**）：输入框上方横向可滚动的同一排标签，逻辑仍最多 8 个；点开底部 sheet，长内容可展开全屏，返回保留草稿、键盘和对话位置。仅一个选中话题，事项跳转复用原生详情，回看返回原对话定位。

```text
┌─ CC ─────────────────┐   ┌─ 服务器       收起 ─┐
│ 你：那台机器……       │   │ 家里的服务与备份    │

│                      │   │ · 每周核验一次      │
│ [服务器][旅行][菜谱]…│   │ 最近聊到            │
│ [跟 CC 说……    发送] │   │ 你：上次…… 回看 →  │
└──────────────────────┘   └─────────────────────┘
```

网页/PWA（**待主人点头**）：`apps/mobile` 复用同一字段和横向标签，小屏用可返回的详情层、宽屏用侧面板；不照搬原生手势。仅设备身份展示，只有 link 身份时不展示话题入口。三端保证键盘可达、可读选中态、屏幕阅读器标题与状态；不只用颜色表达开关。加载、空、断线与错误按 §3 同一语义。

桌面与原生 App 都需要发版才能出现以上界面；daemon 升级不能代替客户端发布。网页随 daemon 发布资产更新。新客户端用明确的 topics 能力声明控制入口；`ServerHello.routes: 'v1'` 只说明路径族，不能证明 T4 已支持。老 daemon 不支持时隐藏新入口、保留原对话；新 daemon 对老客户端不强推未知主题。能力字段与具体发布构建号在实施时登记，不编造已发布版本。

## 7. 实施顺序、验收与风险

1. **先提交本稿供点头**：主人看到的是草图及规则，没有产品变化。重点确认未完事项例外、最近行、泡泡层级和三端打开方式（均 **待主人点头**）。
2. 点头后做 daemon 存储、统一开泡泡写口及睡眠收尾；沿用 recall、topic_search、consolidation，不新增模型调用。离线库验证开关、幂等、睡眠竞争、失败不关、事项例外与迁移；改动尚不等于主人已看到泡泡。
3. 做共享 schema、`/v1` 处理器、owner 授权和 hub 接线；用假凭据与临时库验证三端返回一致、private 全路径隔离、撤销订阅、漏提示兜底、帧分页、重启恢复及新旧版本兼容。
4. 分别实现桌面、App、网页，保持 T5 入口调整在范围外。主人将看到 §6 的标签、详情、状态、回看和更多入口（均 **待主人点头**）。在 Mac mini 的离线包、假接口及独立图形会话验收窄宽屏、夜间收起、跨端同步、辅助功能和草稿保留；本机不跑 UI 控制、截图或重型构建。
5. 整合者在集成 dev 上复验并串行安排 daemon/网页、桌面、App 发布，登记实际构建号和回滚包。上线前先 mini 通过，再走现有发布门；本设计交付不部署、不推送。

| 风险 | 约束与验收证据 |
|---|---|
| 关泡泡被误读为活做完 | closed 与话题生命周期/事项终态分离；夜间不删除标签历史，做完先留结论到下一觉（待主人点头） |
| 睡眠与新聊天、审批并发 | sleep id + activity_revision 条件更新、事务内重查事项，覆盖临界点测试 |
| 错记忆看起来很确定 | 标出真正回忆条目与来源，superseded 不当 live；不生成额外摘要模型；纠错继续走现有记忆路径（展示待主人点头） |
| 未完事项过多导致长期不收 | 不挤占全部最近标签、不以心跳排序，更多列表可达；未知状态保守留开，记录可定位的非正文诊断 |
| 相关消息误挂或漏挂 | 新回忆记录稳定引用；旧 episodes 明示为相关记录，无来源不凑四条 |
| 私密信息由列表、事件或缓存泄露 | 同一 owner 授权投影、准入与持续重验、无正文广播、撤销清缓存；负向权限用例覆盖 |
| 三端发布不同步 | 单独能力声明、兼容隐藏入口；记录桌面和 App 发布依赖，不能只部署 daemon 就宣布完成 |

本稿完成的边界：定义可评审方案。所有可见细节和整合者例外仍 **待主人点头**，不代表已获实施或发版批准。
