# 微信与桌面共用工作任务

2026-09-13。延续统一任务入口目标；本设计属于后台与通道的架构扩展。用户已授权自主推进，不再请求逐步确认。

## 用户路径

微信发送「任务 项目」列出已登记项目和当前 owner 的历史任务目录。每个项目显示名称、目录、可复制的稳定编号和默认执行者；没有目录时明确说明先在桌面选一次文件夹。项目编号由 owner、规范目录和目录实体身份共同确定，不采用会随排序变化的序号，不使用全局 current project。

发送「任务 新建 <项目编号> <要求>」沿用这个项目最近的可用执行者；「任务 新建 <项目编号> 用 Claude/Codex <要求>」明确选择执行者。其他正文原样传递，不用 LLM 猜测路由。回复包含任务编号、选定目录和执行者。重复投递或回复丢失后重投，返回原任务回执，不重新执行。

从微信创建的任务在原账号和原聊天接收完成及待处理提醒。已有桌面任务可以通过「任务 <编号> 提醒我／静音」设置提醒。普通聊天不自动绑定工作任务；工作信息继续排除在陪伴记忆之外。

权限和问题提醒给出任务名及准确请求编号，沿用现有查看／回答命令。已经处理、过期、停止、重启后失效的请求不发送。一次主回复不等于后台全部完成；保留中的原生会话不能被通知层提前宣布完成。最终通知绑定原始 run 和结果，后续开始新一轮不能改写旧通知。

## 存储和执行边界

- 创建回执记录原账号、原 owner、原消息标识对应的请求 ID、完整命令摘要、接受的项目/执行者、任务 ID、首轮 ID、原始回复。任务、首条用户输入、接受的执行设置和回执在同一事务中写入，提交成功后才调度。相同请求 ID 携带不同命令报冲突，先查回执再查已经变化的配置和目录。
- 项目目录来自只读 registry 与 owner 历史，规范化去重。目录被替换、符号链接改指或已不可访问时，旧编号不能指向新目录。不给上一位 owner 的任务授予访问权。
- 通知订阅绑定 task + owner + account；取消后不发送已经排队但尚未发送的通知。重新订阅只接收新的事件及当前仍有效的待处理请求，不补推所有历史。
- 通知 outbox 的不可变身份为 task + run + kind + event/request。消息内容在创建时固定。状态区分 pending、sending、accepted、unknown、suppressed；发送前原子认领，进程重启时 sending 变 unknown，不自动重发可能已送达的消息。
- 只有明确服务器确认才记 accepted。发送前已确认窗口不可用则留 pending，恢复后重试；超时、连接中断、响应不明和发送后落库失败都不冒充成功。不承诺微信跨重启 exactly-once。
- 通知经专用、明确标为 source=workbench 的发送路径；不使用默认 source=live 的陪伴提醒。账号和 owner 变化先核对再发送。通知失败不停止正在执行的工作，查询任务可看到提醒状态。
- worker 有单一发送队列和有界生命周期；启动、关闭及消息更新 context 的唤醒由 daemon 管理。没有真实微信/API 调用的测试必须覆盖同一生产路径。

## 取舍与后续完整范围

采用持久 task outbox。仅内存 callback 会在重启时丢提醒；套用陪伴 reminder 会丢 task/run 身份并污染记忆，两者均不采用。参考 Paseo 的后台会话与客户端分工，CC 自己处理微信消息的耐久性，不把 unread 标记当通知投递证明。

结果文本应能按固定消息版本分段阅读，不能只截 1500 字；结果附件必须从已有 SHA256 校验的不可变快照发送，不能接受任意模型路径。完整文本和附件的微信传输仍属于统一入口要求，交付记录必须明确各自实际完成情况。多电脑执行接管、更多 API 执行者及自动独立 worktree 继续保留在总目标内，本切片不将其判为完成。

## 验收

1. 微信选项目创建后，桌面 API 看见相同 task/run/path/provider/首条要求；桌面补充可在微信查询。
2. 同一消息重投、回复发送失败、重启、配置变化只得到一个任务和一个首次执行；变更正文被拒绝。事务失败没有孤儿任务或已启动执行。
3. 同名目录、旧编号、重绑 owner、错误真实 sender 和并行任务不串；归档历史仍可作为 owner 已知项目来源。
4. 手机收到准确权限/问题，桌面或手机回答后旧提醒失效；旧 run 完成通知不引用新 run 的结果。
5. 明确确认、不可投递、发送中崩溃、响应不明、发送后存储失败分别保持真实状态。无证据时不自动重发。
6. 生产 inbound/service/SQLite/通知 transport 路径以假执行者和假微信服务器进行集成测试；不发真实微信、不重启真实 bot、不改冻结资产。
