# 一个管家:终态方向(2026-11-12,主人与整合者讨论定稿)

状态:**方向已和主人逐条对过**。标「我定」的是整合者按 11-08 授权定的,主人未反对;标「待做」的还没有实现。本稿是 [一段对话 + 话题](2026-11-06-t5-one-conversation-ui-design.md)、[话题就是项目](2026-11-09-topics-are-projects-design.md)、[一件事挂多个 agent](2026-11-12-one-matter-many-agents-design.md) 之上的总纲;与它们冲突时以本稿为准。

## 一句话

对用户只有一个 CC。CC 是管家,Claude / Codex / Gemini 等是它手下的人(园丁、仆人):各自露面干活,但都归管家管;记忆只有管家那一份总账。

「管家」是主人对自己这个 CC 的定位,也是本稿对「CC 统管各家 agent」这层结构的叫法;**CC 对每个用户是什么角色(管家、恋人、导师、朋友)由用户的人设定**,骨架相同。对外文字不把 CC 叫管家。

## 三层

| 层 | 是什么 | 现状 |
|---|---|---|
| **中心:一段对话** | 你和 CC 的关系。问候、闲聊、情绪都在这儿,不需要是「事」 | 已有 |
| **分出去:事** | 聊着聊着需要有人去办时分出去,下面挂一个或多个 agent,办完回到对话 | 单 agent 已有;多 agent 在做(记录本) |
| **沉淀:话题记忆** | 闲聊和做事的都沉在这里;聊到才调出来 | 已有 |

CC 管的不是 agent 也不是项目。agent 是办事的手,项目是办事的地方,都是「事」和「话题」的属性。

## 定下来的规矩

1. **统一入口是完整记忆的前提,不只是方便。**CC 没看到的对话它不可能记得。本机终端会话 CC 看得到;用户在别家网页里的聊天永远看不到。所以目标是让用户习惯在 CC 里说,任何问题对 CC 说,由 CC 决定谁来答。不强制:用户照样可以直接开终端,CC 看得到、记得住、接得上。
2. **做事时直通,不转述。**进入一件事后,用户的话原样给那个 agent,回复原样回来;CC 不插话,只旁听和记录。说完或切走就回到 CC。
3. **谁在回就露谁的标。**直通和代答时显示那一家的 logo(现有圆头像),不写文字。管家不等于什么都由管家开口。
4. **不做 agent 群聊。**群是人用来划分注意力的;agent 之间只经那件事的记录本交接,调度只在 CC。
5. **想起来的东西分三档。**有把握:直接用。没把握:问一句(「你说的是上次迁服务器那件事吗?」)。想不起来:直说,不编。(待做:现在是默默带上。)
6. **闲聊和情绪进同一份记忆,但只有 CC 自己能读**(我定)。派活时给 agent 的只有那件事的记录本和硬规矩,不带闲聊和情绪。

7. **不绑一家**(主人 11-12)。不是所有人都有 Claude,有人只用 Kimi 这类。管家这一层的每项能力——一段对话、话题记忆、记录本、接力、上下文轮换、没把握就问——都由 CC 自己实现,对任何后端(含 OpenAI 兼容网关)行为一致;不依赖某一家自带的功能(例如 Claude Code 的自动压缩、会话间传消息)。强模型只是让管家更聪明,不是前提。落到做法上:
   - 上下文轮换由 CC 在 daemon 里做,各通道同一套;先修最糟的 OpenAI 兼容通道。
   - 调度不能指望模型聪明:拆棒先给主人确认、记录本是结构化的、收备注和产出有不调模型的兜底。
   - 每一步的真流程验收跑两遍:一遍 Claude 当管家,一遍网关上的模型(如 Kimi-Code)当管家。
   - 手下的人也不限 Claude / Codex:走网关的执行者同样拿得到记录本工具。

## 记忆怎么统一

不合并各家内部的记忆(格式随版本变,往里写迟早出事)。分清三种:

| 记忆 | 归谁 |
|---|---|
| 手艺(这个仓库怎么干活) | agent 自己 + 仓库里的 `AGENTS.md` |
| 干过什么 | CC 的总账(agent 干完汇报) |
| 主人是什么样的人、定过什么 | CC 的总账 |

- 往下交代、往上汇报:已有(项目记忆进会话、工作结果进话题、记录本)。
- **翻园丁的笔记本**(待做):agent 自己存在本机的记忆文件,CC 只读地看;属于「主人的偏好 / 定过的决定」的收进总账,以后也交代给别家。只读不改,按来源授权。Codex 的记忆是否在本机可读,做之前先核实。
- 冲突:关于主人和定过的事以总账为准;关于手艺以 agent 和仓库为准;对不上按第 5 条问一句。

## 少给,要用再取

对 agent 和对 CC 是同一条原则。

**派活:**

| 任务 | 给什么 |
|---|---|
| 够具体的一次性活 | 只给任务 |
| 接力的一棒 | 任务 + 记录本(有上限) |
| 开放的活 | 任务 + 一行「这个项目记过 N 条,需要时用工具查」 |

永远带的只有硬规矩(不知道就会闯祸的几条),几行以内。其余全部靠工具按需取。

**CC 自己每轮只该有四样:**最近几轮对话、这次聊到的话题、正在办的事每件一行、关于主人的一小段。更早的对话每晚整理成话题后不再占上下文。活不在 CC 的上下文里干——直通两小时的代码都在 agent 那边,CC 只多几行记录。

## 管家体检(主人 11-12 定,先本机后分享)

不同模型的上下文长度、快满时的记性差别很大,我们测不全市面上的模型,而且后端会被悄悄换掉(11-12 主人网关上的 KIMI 名字没变,背后换成了慢得多的模型)。所以:**CC 把每轮上下文控制在小预算内,让所有模型都只在「很空」的区间工作;预算按用户实际接的那个后端实测。**

**第一步:本机体检,不上传。**

- 何时测:接上新模型时一次;之后定期用很小的量复查(发现后端被换);用户可手动「重新体检」。
- 测什么:只用编造的内容,不碰真实对话和记忆。三项:记性的可靠线(对话不同深度埋事实、填到不同比例再问,看从哪开始答错)、用工具稳不稳、响应快慢。
- 花费:用的是用户自己的额度,开始前说清大概用多少、要几分钟;默认短版。
- 结果:CC 按可靠线决定多久换一次会话;没测过的模型按保守值。
- 给用户看:放在「CC 现在怎么样」页,大白话不放数字(记性:好 / 一般 / 弱;用工具:稳 / 偶尔出错;上次体检时间)。记性弱时附一句「CC 会更常跟你确认」。
- 重要的事当场记账,不等每晚整理(否则白天换会话会「同日失忆」);换会话后开场带最近几轮和在办的事,接不上就问。

**第二步:自愿分享,汇成公共表**(做之前再问主人:要一个接收服务、属于对外功能、隐私说明要加一段)。

- 只汇总直连官方地址的结果;私人网关上的名字是用户自己起的,留在本机。
- 同一模型多份结果取中间值;公共表只当默认值,本机实测永远优先。
- 只传模型名、官方地址、三项分数、CC 版本;不传 key、对话或任何个人信息;默认不传,点了才传。

## 现状核实(11-12,读代码,origin/dev 0537c51d)

**已经符合的**(都有上限):

- 每轮带的:`<recall>` 最多 3 条共 800 字;`<topics>` 最多 2 个话题 × 6 条共 1200 字。其余靠工具取(`topic_search`、`memory_read`、`projects_activity` 等)。
- 开场系统提示里的记忆段各有上限(persona 4000、主人记忆 1500、memory.md 3200、知识 1500)。
- 新终端会话:只在目录对得上唯一一个话题时才带,最多 6 条共 1200 字。
- 交办:固定规矩 + 项目教训最多 10 条 + 话题索引;明确不读陪伴记忆。

**不符合的**(待做,按顺序):

1. **主人对话的历史会一直涨。**Claude 通道是同一个会话反复续接:空闲回收、重启都只杀进程不换会话;真正换新只有 `/reset`、换模型、7 天没用(每轮都会刷新这个计时)。没有每晚轮换,没有长度上限。唯一的刹车是 Claude Code 自带的自动压缩,仓库里既没配置也没关,是否生效未在真机确认。
2. **OpenAI 兼容通道更糟**:每步重发全部历史,进程活着时无修剪,直到撑爆;只有恢复时超过 192 KiB 才另起。
3. **陪伴的定时动作也灌进同一段主人对话历史**,加速上面两条。
4. **交办和新终端会话是「总是推」**,不分任务大小。要改成上面那张三档表。
5. 系统提示里的固定工具说明约 1.5–2 万字无上限(估算),加上约 70 个工具的定义,每次开场都带。先量再决定要不要瘦。

**处理方向**(我定,做之前出小稿;按规矩 7 各通道同一套,不靠 Claude Code 自带的压缩):每晚整理话题之后,把主人对话换成新会话,开场只带「四样」;换之前确认当天内容已进话题,没进的不换。OpenAI 通道同法,另加进程内长度上限。陪伴定时动作改用独立的短会话,结果以一行进主人对话。

## 顺序

1. 记录本 + 手动接力(在做)→ 自动接力 → 终端会话挂入 → 并行。
2. 管家体检第一步(本机)→ CC 上下文轮换 + 当场记账(上面「不符合的」1–3)。
3. 派活三档 + 硬规矩瘦身(4)。
4. 没把握就问一句(规矩 5)。
5. CC 判断「这句该谁答」+ 直通界面露标(规矩 1–3);补 Grok。
6. 翻园丁的笔记本。

每一步都先在 mini lab 用真流程验过再交给主人试。
