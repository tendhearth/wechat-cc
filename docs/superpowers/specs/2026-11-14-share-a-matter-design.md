# 把一件事分享给合伙人(2026-11-14 草稿)

主人 11-14 定:真有三四位合伙人要一起用;排在[自动接力](2026-11-14-auto-relay-design.md)后面做。分享的是**一件事**,不是 CC。

## 分享给谁(主人 11-15 补充)

不限于合伙人:朋友、一起讨论的人、请来出主意的人(比如界面画得不好,找位设计师看看)都算。所以对外的页面和文案不写「合伙人」,用「请你看看这件事」这类说法;重点是**看得到结果、能提意见**,不只是看进度。下文里的「合伙人」泛指被分享的人。

## 为什么不是团队空间

CC 从底层假设只有一个主人:工作内容只有主人的对话和本机能读(来源授权),执行者跑在主人的电脑上、用主人的订阅。让多个真人共用一个 CC,权限、订阅账号安全、本机执行安全三件事同时出问题。

「一件事」已经是独立的单元:目标、分工、记录本、产出、批准。把这一件开给合伙人,上面三件事都不碰:派活和批准仍然只有主人。

以后要真正的团队,方向是每人自己的 CC、事在 CC 之间共享,不是共用一个 CC。团队空间和 Slack 等这一步跑通再议。

## 验证题

不懂代码的合伙人,通过分享出去的这件事:提出一个改动 → 看到改完的结果 → 接着别人的意见再提 → 全程不用主人转述。

## 合伙人看到的

主人给合伙人一个链接。浏览器打开,不用装东西、不用登录。

```
登录页插图                              进行中 · 第 2 棒
──────────────────────────────────────────────────
● [Codex 标]   出三张插图         做完
◐ [Claude 标]  把插图接进登录页    在做
○ [DeepSeek 标] 跑一遍测试        排队

记录
  Codex    图是 1600×900 的 webp,深色那张文件名带 -dark
  小林     第三张的熊再大一点                    ← 合伙人留的
  Claude   用了 -dark 那张做默认

产出
  hero-dark.webp  hero-light.webp  LoginHero.tsx(改动 +42 −7)

[留一句话……]
```

- **看得到**:这件事的标题、状态、每一棒是谁在做什么、记录本、产出(图片和文本可以直接看,代码看改动摘要)。
- **看不到**:主人的对话、记忆、话题、别的事;批准卡的内容(只显示「在等主人确认」);本机的绝对路径;执行者的原始对话。
  - 记录本里有每一棒做完时的结论(执行者没自己写备注时,取它最后那句回复)。这是有意给的:合伙人要知道做成了什么。执行者中途的对话、工具调用不在记录本里,也就不给。
- **能做的只有一件**:留一句话(500 字以内)。

## 合伙人留的话去哪了

1. 记进这件事的记录本,署名是主人分享时给的名字(「小林」)。
2. 主人收到一句通知,带一个按钮:**照这个做**。主人点了,这句话才作为主人批准过的要求交给当前执行者(或排给下一棒)。
3. 主人不点,它就只是记录本里的一条意见。之后的执行者看得到,但标明「合伙人的意见,不是主人的要求」。

为什么要过主人这一道:合伙人的话会进执行者的上下文。不过这一道,拿到链接的人就能指挥主人电脑上的执行者——用主人的订阅、在主人的机器上执行。

## 主人这边

- 详情页多一个「分享」:填一个名字 → 得到链接。同一件事可以分享给几个人,各自一个链接,各自署名。
- 也可以对 CC 说「把登录页这件事分享给小林」;CC 先让主人确认(对外的动作),再给链接。
- 分享列表:谁、什么时候开的、最后一次打开、**撤销**。撤销立即生效。
- 链接默认 14 天过期;这件事归档时全部作废。

## 怎么做

| 部分 | 做法 | 现成的 |
|---|---|---|
| 令牌 | 分享令牌**不进令牌登记处**,不是谁的身份,只是一件事的只读钥匙:面板认出它就交给唯一的分享出口,别的路由拿它一律 401。看哪件事由分享记录定,不听请求里说的;能不能看每次请求重判 | 手机面板的入口、隧道握手的候选令牌 |
| 存储 | 迁移加表 `matter_shares`:事、名字、令牌、过期、撤销、最后打开。重启后仍有效。令牌原样存(不是哈希):中继握手用它派生信道密钥,两边得拿同一个值,和手机设备令牌一样。主人的列表里不带令牌,链接只在开的那一刻给一次 | — |
| 传输 | 走现有中继(端到端加密),daemon 不暴露公网端口。链接是中继壳页加 `#id=…&t=<令牌>&p=/share`;分享流不能订阅事件,页面自己轮询 | 中继 v2、`/m` 页面壳 |
| 读 | 新投影:在现有「只看状态」的基础上加执行者行、记录本、产出清单;文本过现有的脱敏 | `linkMatterStatus`、`ledgerRead`、`ledgerText` |
| 产出 | 只给快照里的文件;图片 / 文本直接给,其余给名字和大小;8 MiB 上限与路径守卫沿用 | 快照读取器 |
| 写 | 一条路由:留话。500 字、每个链接每天 20 条;作者 `partner:<名字>` | 记录本 `note()` |
| 采纳 | 主人通知 + 一张批准卡;批准后走现有的「对这件事说话」 | 批准卡、`/v1/matter/say` |
| 页面 | 浏览器里单独一页,只服务分享链接 | `apps/mobile` |

与既有决定的关系:10-21 定过「网页详情只看状态」。那是主人自己的链接页;分享页是另一页、另一种令牌,只对一件事开放。主人自己的链接页不变。

## 分步

1. **只读分享**:令牌、表、读投影、分享页、分享与撤销。先合 daemon 这一半(存储、读投影、隧道与面板的分享出口、主人侧开 / 列 / 撤三条路由,只给桌面 operator 凭据);分享页和主人的入口(详情页按钮、对 CC 说)随后,页面先给主人看过再开入口。
2. **留话与采纳**:留话路由、署名、主人通知与「照这个做」。
3. **看得到跑起来的 Demo**:见下。

## 待主人点头

主人 11-14 已点头前两项:链接走中继;Demo 先做截图。第 3 项等页面做出来再看。

1. **链接经过中继**。合伙人的浏览器经 Tendhearth 中继连到主人的电脑,内容端到端加密,中继看不到;主人电脑关机时链接打不开。(和手机连接是同一条路。)
2. **Demo 怎么给合伙人看**。验证题里最要紧的是「看到改完的结果」。三种做法:
   - 截图:这件事做完时由执行者截一张图进产出。最简单,合伙人能看不能点。**建议先做这个。**
   - 静态预览:构建出的静态页面经中继给合伙人打开。能点,但只适用于纯前端。
   - 实时预览:把本机跑着的开发服务器经隧道开出去。最完整,也是把主人电脑上一个端口开给外人,要单独设计。
3. **分享页上的品牌**。页面顶上写「Tendhearth CC · <主人的名字>分享给你的一件事」这一类;具体文案和样子上线前给主人看。

## 不做

- 合伙人派活、批准、停止、换人。
- 合伙人之间互相看得到对方的链接或身份以外的信息。
- 把主人的整个 CC、话题或多件事一起分享。
- 合伙人账号体系(名字是主人填的,链接即身份)。
