# 自动接力(记录本第 2 步,2026-11-14)

上游:[一件事挂多个 agent](2026-11-12-one-matter-many-agents-design.md) 的第 2 步。第 1 步(记录本 + 手动接力)已上线。主人 11-12 定:每件事开工前确认一次拆法,之后自动接力;失败或 agent 提问就停在那一棒。

## 主人看到的

主人对 CC 说一句「让 Codex 出三张插图,出完让 Claude 接进去,最后 DeepSeek 跑一遍测试」。

1. CC 把这句话拆成几棒,调 `matter_plan`。主人收到一张批准卡,上面是拆法(谁、做什么、先后)。批准一次。
2. 第一棒开工。详情页里后面的棒显示「排队」。
3. 一棒做完,CC 自动派下一棒,给主人一句话(「Codex 出完图了,Claude 接着做」)。新的一棒只收到记录本,和手动接力一样。
4. 停下的情况:给主人一句话说明停在哪一棒、为什么。
   - 这一棒没做完(失败、中断、自己说没做完):主人说「继续」就续这一棒,做完后照常往下走。
   - 这一棒在等主人回话:主人回了它接着做。
   - 这一棒做完了,但下一棒没派出去(执行者额度用完、被拒、要先确认免审,或这件事暂时不能开工):这一棒记为做完,原因挂在下一棒上。主人说「继续」时重新判一次下一棒能不能派(`decideResume`),不让做完的那位再做一遍。这是主人亲口要的,不再看批准多久、是否自动派过。
5. 全部做完:一句话收尾。

主人中途手动换人(`matter_handoff`)或对这件事另起一轮:拆法作废,之后不再自动往下走。主人接管了就听主人的。

## 该不该派下一棒

判断在 `src/domain/relay-decision.ts`,纯函数,表格测试在同目录。偏向:**拿不准就停**。多停一次主人说句「继续」;错派一棒是在没做完的地基上再烧一轮。

先看结构,再看文字:

| 顺序 | 情况 | 结果 |
|---|---|---|
| 1 | 拆法没批准 / 已取消 / 已走完 | 停 |
| 2 | 结束的这一轮不是拆法里正在跑的那一棒 | 停 |
| 3 | 结束状态不可信、失败、取消、中断 | 停 |
| 4 | 结束时有没回答的提问或批准 | 停 |
| 5 | 主人对这件事说的话还排着没送进去 | 等(那句话是说给这一棒的) |
| 6 | 最后一段话在问主人 / 自己说没做完 / 没有一句结论 | 停 |
| 7 | 后面没有棒了 | 做完 |
| 8 | 这件事不能再开工(归档、工作区没了、写入方没确认退出、在回退) | 停 |
| 9 | 拆法批准超过 7 天 | 停 |
| 10 | 下一棒自动派过一次 | 停(不自动派第二次) |
| 11 | 下一棒执行者没登记 / 额度用完 / 被拒 / 要先确认免审 | 停 |
| 12 | 其余 | 派下一棒 |

读最后那段话(第 6 行)只看开头一段和结尾最后一段正文,跳过代码、引用、表格、纯列表和「还需要我做别的吗」这类客气话。中间的过程叙述(「一开始跑不起来,后来…」)不是结论。同一句里说明已经解决的、假设和预防的说法(「如果失败就重试」)、带失败字眼的好消息(「0 个失败」)不算没做完。

不让模型来判。便宜模型判这一步会把「该停」变成概率问题,而且每家后端答得不一样;规则判错了可以加一行表格修。

## 数据

迁移 v113:

- `matter_plans(matter_id 主键, state: approved|cancelled|done, approved_at, created_at)`
- `matter_plan_legs(matter_id, position, executor, brief, state: pending|running|completed|stopped, run_id, auto_dispatches, stop_reason, 主键(matter_id, position))`

拆法 2–6 棒。第一棒建事时即 running。棒与记录本里的执行者行靠 `run_id`(记录本的棒号 id)对应;主人续同一棒不换棒号。

## 不做

- 并行(第 4 步)、终端会话挂进来(第 3 步)。
- 中途改拆法:要改就取消了重说。
- 让 agent 自己决定叫谁。
- 自动重试失败的棒。
