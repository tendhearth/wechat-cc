# 一件事里的并行（2026-11-28）

沿用[一个管家](2026-11-12-one-butler-direction.md)和[一件事挂多个执行者](2026-11-12-one-matter-many-agents-design.md)。主人说「Codex 和 Claude 各出一版」，CC 出一张批准卡，标明同一棒里的执行者、共同要求和独立工作区。批准一次，后面的顺序继续按这张卡走。

- **拆法**。`matter_plan.legs` 仍是 1–6 棒。单人棒是 `{executor, brief}`，并行棒是 `{parallel: ["codex", "claude"], brief}`，名单只接受 2–3 个不同的已接入执行者。并行必须有 Git 项目，自动用独立工作区。首棒各版从同一提交出发。前面已有棒时，从接力工作区的同一提交分出各版。前一棒的改动需要先提交，免得新版本漏掉它。
- **存储**。原拆法和棒继续落原表，新表记录并行成员、执行任务、状态、对照素材和选中结果。版本复用「另做一份」的交办和 Git 工作区，每个版本有自己的执行任务，经主事项里现有的任务详情入口打开；事项列表只列主事项。拆法和记录本挂在主事项；每位的备注按执行者和运行编号署名。各执行者沿用自己的准入、执行令牌和权限卡，记录本按可信的任务绑定查找。给成员的记录本不带同组其他版本的工作区和交付指针。
- **进度**。启动失败、执行失败和停下都只记在该成员上。提问只挂住该成员；如果它在结束时交代还有问题，记为已停。收到全部成员的终态才出对照。微信、桌面和 App 沿用事项详情，按棒显示并行人数和每位的进度。
- **对照与采用**。CC 在原对话回报每位的文件和增删行、收尾状态行、执行者给出的测试结果（有才显示），并指向各自任务的「合回项目」入口。主人可以用现有入口，或对 CC 说「用 Codex 那版」。有工作区的未完成版本也由主人判断是否采用。沿用只快进的合回动作。合不回时保留待选状态和原有错误，主人处理后可重试。没选时后续棒不启动；合回成功后，下一棒从选中版本的原工作区接着做，开场带该事项的记录本。其余工作区继续保留。
- **范围**。没有自动选择、评审打分、自动合回、跨工作区互看、三位以上或群聊。复用已有详情和工作区操作。
