# 普通任务的项目隔离与逐文件撤回

日期：2026-10-05。状态：设计草案，待主人评审；尚未实施。

基线：`dev b2ef0c71`。负责人及整合者：本轮 Codex；工作区为本聊天已有的独立工作区，分支 `codex/workbench-isolation-review`。

## 目的与已知要求

主人接受按「项目隔离与可撤回审阅 → Qwen 完整执行 → 浏览器操作」推进。本设计只覆盖第一批，使用户可以把同一 Git 项目的不同要求交给 CC 独立完成，查看改动，并明确撤回一段已关闭执行会话对单个文件产生的修改。

成功条件：普通新任务有自己的执行目录；原项目的工作文件不因正常任务执行或本批撤回而被改写；审阅记录与真实文件操作分开；撤回具备原始版本、执行者退出和文件版本核对证据。已有任务、历史导入与仍在运行的会话继续沿用它们已有的目录。

待反馈的偏好是新任务默认使用副本还是原目录。本文按「Git 新任务默认独立副本」拟定，并保留明确选择原目录的入口。此项是设计假设，主人选择原目录默认时，只调整创建策略默认值，下面的隔离与撤回边界不变。

产品名称、语气和界面动作遵守家族规范与 `docs/reference/product-naming.md`。界面先说明工作发生在哪里，技术分支与提交信息放在可展开的详情中。

## 方案选择

| 方案 | 收益 | 代价与边界 |
|---|---|---|
| **固定本地提交创建 Git linked worktree，推荐** | 文件副本独立、无需复制 Git 对象，可利用已有 Git 审阅 | 仍共享 Git refs/config；原目录的未提交内容与忽略文件不自动带入 |
| 完整私有 clone | Git 元数据也独立 | 本地未推送提交、配置、凭据与后续回收更复杂 |
| 复制当前脏工作树 | 接近用户当前编辑现场 | 必须可靠冻结 staged/unstaged/untracked/ignored 与原始字节，首次范围显著增大 |

第一版选择固定提交的 worktree。原项目必须有 HEAD、工作树和索引干净，没有 merge/rebase 等未结束操作；子模块和无法确认目录身份的项目暂不提供隔离创建。遇到不支持的状态，保留要求与附件，说明原因，由用户选择原目录或处理原项目后重试。失败不会自动改为原目录执行。

非 Git 项目继续现有创建路径。`self change` 的专用工作树和人工维护者工作树不受本批创建策略接管。

## 第一批交付范围

1. 普通 Git 新任务从冻结的 HEAD 分配独立副本；桌面、手机、PWA、微信和现有内部创建接口使用一致的服务策略。
2. 同项目多个副本可以并行。续接、复核、修订和额度接手使用原工作副本，不重新创建空副本。
3. 新隔离任务保存以执行会话开始和确认退出为边界的不可变文件恢复记录。在执行者确认退出后，用户可以逐文件撤回受支持的文本修改、新增或删除；不把多回合的全部改动伪称为最后一回合的撤回。
4. 界面说明原项目与执行目录，支持打开副本及导出当前项目范围内的完整 Git 补丁；成果留在副本和既有成果存储中。归档保留工作副本和分支。

本批不自动将改动写回原项目。导出的补丁包括索引和工作文件相对于固定基线的变更，任务内提交及项目范围内的非忽略未跟踪新文件也应计入；保存导出版本及摘要，不能把受限预览 diff 当完整补丁。无法完整导出时明确失败，提供打开副本的入口。应用到原项目、自动合并和可恢复的副本删除另做后续闭环。

逐 hunk 接受、重命名成对撤回、二进制恢复、非 Git 通用恢复、Qwen 写文件/命令/MCP 与浏览器操作不属于本批。已有接受/打回行为继续保留；「打回」仍是让执行者修改的续接要求。

## 项目身份与执行目录

保留 `Task.path` 作为实际执行目录，不改变执行者、文件工具、成果、diff 和租约已经依赖的语义。新增可空 `gitWorkspaceId`：旧任务为 NULL，不回填，不移动目录。

新增工作副本记录，至少保存：

- workspace UUID、owner、创建请求编号及输入指纹；
- 原项目 canonical path 与目录身份、Git 根与 common-dir 身份、项目相对仓库根的子路径；
- 冻结的 base commit、原分支说明、唯一任务分支 `codex/cc-task-<UUID>`；
- 副本根、实际执行目录及身份；
- 分配状态 `reserved / provisioning / ready / failed / needs_recovery`，失败原因及核对信息。

工作副本与任务允许一对多关联，复核与接手任务共享同一副本。项目列表、名称、搜索、项目执行者偏好和 matter 的 `projectPath` 使用原项目投影；执行者 cwd、文件权限、成果位置、API 会话绑定和 scheduler 使用实际执行目录。

原项目是仓库子目录时，执行目录必须映射到副本内相同子目录。界面和导出范围不能悄悄扩大到整个仓库。

工作副本放在 CC 管理的 Tasks 下的独立 GitWorkspaces 区域，位于原仓库及 daemon 私有状态目录之外。目录和分支归属必须可核对，不能仅凭名称前缀认定为 CC 所有。

## 创建、重试与重启

当前创建入口是同步契约。新分配必须使用异步 Git 执行器，所有调用点同步改为 await；不得在 SQLite 事务中运行 Git 或用同步子进程堵塞 daemon。

新创建协议增加 `executionMode?: 'auto' | 'isolated' | 'project'`，并使用稳定 `requestId`。省略位置按 `auto` 进入 canonical 输入指纹，第一次解析出的实际位置另外持久冻结；重试不因默认设置改变而换目录。显式位置变化属于新请求，同编号异内容拒绝。CC 自带桌面、手机、PWA、微信及 selftest 创建调用点全部使用有编号的统一入口。

旧 `/v1/workbench/create` 接受新增编号和位置字段并复用同一回执域。为保持兼容，无 requestId 且未指定位置的旧调用继续按原目录创建，不承诺断线去重；请求隔离或 auto 位置时必须有编号。旧入口不能在无编号时悄悄开启隔离默认。外部客户端要获得重试去重需使用有编号的协议，响应明确返回执行位置与请求编号。

流程为：

1. 解析新建任务的意图、执行者、附件和要求，冻结创建请求；按原有 requestId 规则拒绝同编号异内容。
2. 核对源目录、Git 身份、HEAD 和干净状态，保存独立的 workspace 预留记录。
3. 在 repo-common-dir 的短时分配锁内执行 `git worktree add -b <唯一分支> <目录> <固定SHA>`；不 fetch、不切换原分支、不使用 `-B`。
4. 再核对来源和分配结果：Git 登记、分支、base commit、目录身份和源项目状态都必须与冻结记录一致。
5. 用短数据库事务提交任务、项目投影、matter、workspace 关联和 accepted 回执，再进入既有调度流程。

Git runner 使用 argv，有明确超时，清除不应继承的 `GIT_*`，关闭 hooks、fsmonitor、交互凭据及自定义 filter/smudge 的隐式执行。工作副本分配不会自动安装依赖；依赖安装留在执行者已有的权限流程内。

Git 已成功但 accepted 回执未落盘时，重试核对同一预留对象后接回。陌生目录、分支冲突、目录身份变化或初始现场不一致进入 `needs_recovery`，不覆盖或强删。重启恢复不得创建第二棵副本，也不得将结果未知的创建认定为成功。

创建期间显示正在准备副本；要求和附件持续保留。断线后使用原请求编号核对结果，重复点击不会再派一项任务。

## 原生配置与权限

配置解析必须分别传递原项目 `configSourcePath` 和实际 `executionPath`。创建准入从 source 核对该执行者的模型/端点、项目规则、MCP 定义、授权和相对路径；执行仍以副本为 cwd。只有这些配置能通过副本内随提交带入的文件及已有全局配置安全重现，才允许隔离创建。

项目相对路径只允许在确认语义等价时映射到副本。原目录专属授权、忽略的项目设置、需要原目录 cwd 的 MCP、指向原项目的绝对路径或无法验证的配置差异，使隔离准入失败；保留要求与附件，说明差异类别，允许用户明确选择原目录。不能仅显示遗漏提示后照常开跑。配置差异反馈不包含凭据值。

原目录忽略的 `.env`、依赖、`settings.local` 和按原 cwd 保存的项目授权不自动复制或迁移。不得为了兼容而把原项目加入新的额外可写目录、把原目录权限自动提升到副本或复制任意凭据。

CLI 仍使用自己的工具和权限模型；API 工作台的只读/新成果范围不扩大。Windows Codex 工作台现有拒绝仍生效，工作副本分配成功不代表该执行者已解锁。

linked worktree 隔离正常的工作文件操作，仍共享 Git 元数据；它不是操作系统沙箱。执行者跨目录操作继续受现有权限约束，不能向用户承诺禁止一切越界行为。

## 可撤回的恢复记录

现有 `GitBaseline.initial` 是内存对象，公开审阅成果只有 diff 和哈希，不能可靠重建原始文件。新增恢复记录独立于公开成果，使用私有内容寻址的原始字节存储，读回核验哈希；不把项目开始版本作为普通可下载成果公开。

公开审阅仍按回合生成。可靠恢复只在没有 writer 时、开新执行会话前冻结 before，并在该会话确认 close 后冻结 after；保留会话的普通续接和自主唤醒不重置 before。新增不可变 `restoreRunId` 表示一次 writer 生命周期，区别于现有可能按回合变化的 runId，关联该生命周期涉及的任务和公开回合。

关闭后生成独立的恢复审阅快照，内容对应这段会话从 before 到 after 的完整文件差异，标注开始/结束时间及「这段会话的全部改动」。撤回只引用此快照，不在仅显示最后回合 diff 的记录上执行更大范围的恢复。无法证明无 writer 的边界不补造前像，该段会话不可撤回。

记录包含 workspace/task/restoreRun 身份、workspace generation、审阅 artifact、项目内相对路径、基线 HEAD、目标路径基线 index 条目指纹与 before/after。before/after 为明确的 `absent` 或普通文件版本 `{blobSha, size, mode, type}`。after 还保存叶子身份以及工作区根到父目录的身份链；absent 路径也保存父目录身份。真实目录被替换为另一棵真目录时，同样拒绝恢复。不能把「不在 Git 候选名单中」当原先不存在：ignored 文件变为 unignored 是现有采集的盲区。

每个恢复生命周期保存受限的存在性清单，包含忽略文件的存在事实和已完整枚举的目录范围。内部/敏感目录、未完整扫描的目录和超限范围标记未知；未知前像不能用于删除新增文件。初次干净 worktree 的完整 checkout 和已登记 seed 也可提供初始存在性证据。保存新版本时不跟随链接。

第一版额度为单文件 256 KiB 原始字节、每个 before/after 阶段最多 16 MiB 原始内容及 50,000 项存在性记录。达到限制或读入失败只使相应路径不可撤回，任务与审阅继续；不能存截断字节后声称可恢复。内容寻址去重，但额度仍按本恢复生命周期实际覆盖内容核算。

| 文件变化 | 撤回行为与前置条件 |
|---|---|
| 普通 UTF-8 文本修改 | 当前字节、存在性、类型、mode 与 after 一致，恢复 before 原始字节与 mode |
| 新增文本文件 | 有 before=absent 的确切证据，当前与 after 一致才删除 |
| 删除文本文件 | 保存完整 before，当前确切 absent，父目录仍可安全锚定，以不覆盖已有路径的方式恢复 |
| 重命名 | 现有模型是删除与新增两条记录；分别处理，不显示一键重命名撤回 |
| 二进制、非 UTF-8、超限或前像缺失 | 可查看已有审阅或导出，实际撤回不可用，并说明原因 |
| 链接、junction、硬链接或特殊文件 | 不提供撤回；普通文件写入口要求 nlink=1 |

CRLF、BOM、空文件和执行位均按原始版本保存。删除文件的父目录已经消失、变成链接或身份不可信时，第一版拒绝恢复，不自行重建整棵目录。

## 执行者退出与文件操作占用

「已答复」不等于执行者退出。用户先通过已有动作结束后台会话；撤回接口不会偷偷停止任务、丢弃补充或杀掉其他接手任务。

撤回只在持久运行记录证明 writer `closed` 时开放。记录 `active / closing / closed / uncertain` 与确认关闭证据；重启后内存没有 Active 不能当退出证明。正在运行、保留会话、后台子任务、等待退出、网络暂停和未投递的补充都阻止撤回。

scheduler 扩展为运行占用或短时文件 mutation 占用。撤回在同路径与父子路径冲突检查下原子取得 mutation reservation；期间 start、continue、submitInput、另一撤回和回收不能进入该目录。共享副本的复核/接手任务必须一起纳入检查。

每个路径保留当前 changeId/version。每次允许新的 writer 生命周期进入，先推进 workspace generation，使旧恢复计划失效；关闭时生成该 generation 下的路径版本，一次成功撤回推进目标路径版本。旧审阅即使哈希偶然相同，也不能再次覆盖当前文件。同一保留会话的回合不会产生虚假的新恢复边界。

撤回还要求副本 HEAD 与持久恢复基线一致、目标路径 index 的 absent/条目指纹与基线一致，且目标路径相对该 HEAD 没有 staged 差异。基线前已经暂存的文件也不可撤回；任务已经提交或暂存了该文件时返回 `git_state_changed`，保留现场。第一版只恢复工作文件，不重写 Git refs/index，不把 HEAD 当作 before，不使用 `reset --hard`。

## 撤回操作与崩溃恢复

新增 `revertReviewFile(id, {artifactId, path, changeId, requestId})` 和管理员路由 `POST /v1/workbench/review-revert`。请求只引用已存记录，不携带任意磁盘路径或恢复字节。按现有内部路由、token registry、Tauri allowlist 与桌面 proxy 的完整登记规则接入。

服务先核对任务/副本/运行/审阅归属和最新路径版本，再核对目录链、原始 blob、Git 状态及当前文件字节、类型、mode。缺少任何证据都返回明确原因，零写入拒绝。

文件效果前先持久保存 operation 回执及其输入指纹，状态为 `prepared / applying / reverted / conflict / needs_recovery / resolved_keep_current`。重复 requestId 返回原回执；同编号异参数拒绝。普通修改使用同目录临时文件及安全替换，新增文件撤回使用安全删除，恢复删除使用排他创建；不得通过原 inode 改写硬链接别名。

`prepared / applying / needs_recovery` 是持久 workspace 阻挡条件，不仅是内存 reservation。启动恢复完成前，start、continue、submitInput、pump、另一文件操作及回收均不能进入；不能先开新 writer，再按偶然相同的内容重放旧操作。恢复协调必须重新核对 workspace generation、路径版本、身份链、writer 退出与 Git 基线，再按磁盘状态处理。

崩溃恢复在重新取得独占操作占用后，按记录和磁盘 before/after 核对现场：

- 仍是 after：可安全重新验证后完成原操作；
- 已是预期 before：核验操作身份后补齐回执；
- 两者都不是、临时状态不明或身份变化：进入 `needs_recovery`，保留文件与记录，不猜测、不自动覆盖。

`needs_recovery` 不是只能手改数据库的终点。桌面展示本次撤回、当前观察和不确定原因，提供「保留当前文件并结束此次撤回」。管理员通过独立 resolve 接口提交 operationId 和当前观察指纹；服务在 writer 关闭及独占占用下重新核对观察，发生变化则要求重新查看。观察一致时仅记录 `resolved_keep_current`、推进路径版本并解除操作阻挡，不修改当前文件，也不显示「已撤回」。工作副本根身份已失效时仍保持 workspace 不可执行，用户可保留记录并从原项目另建任务。

成功回执、路径新版本、任务事件及 seq 更新须一致提交。撤回状态独立于 accepted/returned；只有成功回执才显示「已撤回」。下一次续接明确提供哪些文件已被撤回的事实，不能让执行者沿用旧文件状态而不知情。

目录占用只协调 CC 内部任务，不锁用户编辑器或外部 CLI。现有纯 JS 文件守卫没有跨进程文件 compare-and-swap；本批承诺拒绝已观察到的后来修改和路径替换，不承诺与任意外部写入同时发生时绝不覆盖。实际撤回仅在 CC 的独立副本开放，原项目不在本批文件操作范围。

## 界面与入口

创建页保留一个主要交办动作。Git 项目在执行位置处显示「独立副本」或「原目录」；详细分支信息按需展开。隔离创建不可用时，解释具体原因，保留正文与附件，原目录执行需要明确选择。

任务页仍按原项目组织，显示在独立副本里做；可打开执行目录、查看技术详情或导出改动。归档动作说明副本仍保留，不把归档当删除。

改动面板在关闭时的恢复快照里为每个受支持文件增加独立「撤回」动作，并说明撤回的是这段执行会话对该文件的全部改动。保留会话时显示需先结束后台会话；文件已变化、Git 状态变化、快照未覆盖等原因显示在文件行内。撤回先确认目标文件与显示的影响范围，失败保留展开位置和用户输入。旧快照与普通回合记录不补造恢复记录，继续支持已有审阅和打回。

后台返回 executionMode、来源项目、执行位置、恢复资格及原因。手机/PWA/微信能准确说明在哪里执行和创建失败原因；逐文件实际撤回的交互首版放在桌面，不把原生手机还没有的改动界面宣称已交付。

|---|---|
| Git workspace 分配、目录/分支归属、重试核对 | 新工作副本模块；参考 `managed-workspaces.ts` 的身份规则，提取中立的异步 Git runner |
| 任务与 workspace 关联、项目投影、运行关闭记录 | `store.ts`、运行存储、`src/lib/db.ts` 追加迁移 |
| 新建任务的异步预留与 accepted 回执 | `service/entry.ts`、`service/execute.ts`、HTTP/手机/微信创建调用点 |
| 原任务副本继承、复核与额度接手 | `service/native.ts`、handoff 与 continuation 路径 |
| 原始恢复 blob、存在性覆盖与路径版本 | 新私有恢复存储；与 `git-review.ts` 的公开审阅关联 |
| writer 关闭与 mutation reservation | `service/lifecycle.ts`、`service/state.ts`、`scheduler.ts` |
| 撤回及操作回执、重启协调 | 独立文件 mutation 服务；由 `service/review.ts` 调用 |
| 改动导出 | 对固定 base commit 生成完整、范围受限的二进制 Git 补丁；复用已有保存成果流程 |
| 桌面执行位置、撤回资格与反馈 | task-entry、workbench、review-panel 及其 structural signature |
| 跨入口一致的创建与说明 | 内部 API、Tauri proxy/allowlist、PWA、原生 Backend、微信控制 |

不把新状态机塞进现有大文件；目录分配、恢复存储、文件 mutation 与回执各有独立职责。数据库迁移只追加，按维护手册更新迁移相关测试。

导出先确认共享副本的全部 writer 关闭并取得同一 mutation reservation，冻结本次完整文件版本；用 CC 私有的临时 index 生成固定 base 到冻结结果的补丁，明确包含非忽略的未跟踪新文件。真实任务 index、refs 和原项目不参与写入；Git runner 仅为此受控步骤允许指定已验证的私有 index，仍禁用隐式 hooks/filter。忽略文件、内部目录（含 `.cc-workbench`、`.cc-workbench-inputs`）和项目范围外的变化不自动装入补丁，导出回执列出这些未覆盖类别。超限、无法读取或 snapshot 不一致时不交付部分补丁。

## 必须通过的验证

- 同一项目两个隔离任务真并行；原目录与分支不变；项目子目录映射正确；同副本的复核/接手仍遵守原租约。
- 既有任务、原生历史、非 Git 创建与普通原目录执行不迁移；各入口只分配一次，超时、断线和 daemon 重启不会重复建副本或重复派发。
- 脏树、无 HEAD、子模块、merge/rebase、陌生目录/分支、源身份变化、Git 配置隐式执行或配置无法安全重现均明确失败，失败不回退原目录。
- 修改/新增/删除的原始字节、CRLF/BOM、空文件和 mode 正确；ignored→unignored 旧文件不误删，未知覆盖与超限文件不推断 absent。
- 后来修改、类型/存在性变化、旧 changeId、错任务/错 artifact、链接/junction/硬链接、路径别名和 Windows 特殊路径零写入拒绝。
- retained、自主唤醒、后台子任务、close 延迟/失败/晚到、重启未确认、未发补充，以及撤回与 start/continue/input 竞争遵守同一占用；不将不可靠回合伪称恢复点。
- HEAD/index 改变拒绝；成功撤回不改原项目、Git refs/index 或其他文件。
- requestId 幂等、默认位置变化、旧无编号调用、原始 blob 损坏、磁盘满、文件效果后回执前崩溃、回执落盘后断线有诚实且可恢复的结果；未决操作阻挡新 writer 直到恢复完成。人工保留当前文件只写回执，观察过期则拒绝，根身份失效不解开执行限制。
- 完整补丁包括任务内提交、未提交变更与非忽略的未跟踪新文件；导出范围与版本固定，真实 index/refs 不变，不使用截断审阅 diff，不泄露恢复 blob。
- 桌面只有成功回执显示已撤回；失败保留阅读/输入；手机创建和失败说明真实；Windows 不据此开放未验执行者。

实施后走 Bun、Node、类型与模块边界闸门及相关桌面/手机接口端到端。真执行者验收在独立测试项目完成，原项目哈希和 Git 状态前后核对；实际支持与未实测平台分别记录。
