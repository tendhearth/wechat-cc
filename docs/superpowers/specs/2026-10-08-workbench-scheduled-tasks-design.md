# 一起做：定时交办（每天 / 每周让执行者做一件事）—— 设计草案

> 2026-10-08 · 状态：**待主人拍板**。拍板之前不写代码。

## 为什么

对标对象里，Codex app 有「Automations」：按时间表让 agent 在某个项目里做一件事（每天早上查依赖更新、每周整理 issue、每晚跑一遍测试并汇报），做完结果进收件箱。Paseo / Orca 目前没有。CC 已经有这几样现成零件：一起做（任务 + 独立工作区）、提醒（v29，定时 + 退避 + 量控）、每晚整理记忆（无人值守的模型调用先例）、微信 / 手机推送。

## 和红线的关系（这是要主人定的核心）

全景导图里有一条：**无人值守的自动外呼一律不做**（起因是网络不稳时随意探测可能导致封号）。定时交办就是「无人值守地叫执行者干活」，比探测重得多：会花额度，会改文件。

已有的先例：每晚整理记忆是无人值守的模型调用，走网络守护，主人同意过。所以问题不是「能不能无人值守」，而是**这一类要不要开、开到什么程度**。

## 提议（如果做）

1. **只能主人亲手建**：桌面或微信「任务 定时 <项目> 每天 9:00 <要求>」。CC 自己不建、不改时间表。
2. **每次到点都是一件普通的事**：在独立工作区里做（不碰项目目录），做完按现有规则推送；结果只是一个分支，合不合由主人定。
3. **闸门全部沿用**：网络守护不安全 ⇒ 这次跳过（不补跑）；执行者额度用完 ⇒ 跳过；上一次还没做完 ⇒ 跳过；电脑睡着错过 ⇒ 醒来不补跑，只记一行「错过了」。
4. **量控**：每个定时最多每天一次；全部定时合计每天最多 N 次（默认 5）；连续失败 3 次自动停用并告诉主人。
5. **只用免审之外的执行者**：免审执行者（agy / Cursor 编辑免审）不许挂定时，避免没人看着时一路放行。
6. **权限卡照常**：执行者要权限 ⇒ 停在那里等主人，推送提醒；不自动允许。

## 不做（这一版）

- 由事件触发（「有新 PR 就审」「CI 红了就修」）—— 那要接外部服务，另议。
- CC 自己提议定时任务。

## 要主人定的

1. **做不做**。这碰红线的边，主人说不做就不做，这份草案留档。
2. 如果做：
   - 每天合计上限默认几次？（提议 5）
   - 错过的要不要补跑？（提议不补）
   - 免审执行者能不能挂定时？（提议不能）
   - 入口先做哪个：桌面 / 微信 / 都做？（提议微信先，最轻）
