# T5：一段对话的界面

> 2026-11-06 · 仅设计，未实现。本文全部可见选择（包括文案、入口、布局、数量、动作和草图）均为 **待主人点头**；这是评审标记，不印在产品里。主人已定的是统一入口、大管家、无 chat/cowork 分割、无群、话题如朋友想起旧事的方向，具体界面仍须点头。本稿不授权实施或发布。

## 先请主人决定的五件事

1. **待主人点头：打开就和 CC 说话。** 桌面、App、已配对网页直接进入唯一主人对话；撤掉首页事项清单与「全部」目的页。仍保留生活、记忆与设置工具入口。
2. **待主人点头：派活是一条可展开的 CC 消息。** 「交给 Codex 检查备份了」下面看真实进展、成果与「等你决定」；点进去看过程，不另找工作台。
3. **待主人点头：话题行与泡泡承接找事。** 输入框上方默认六个最近话题（T4 的 5–8 个范围），泡泡可打开关联事项；找旧事通过搜索对话/话题与 CC 消息中的事项引用，不保留独立事项列表页。
4. **待主人点头：网页补成能对话的设备入口。** 需要新增此前收敛掉的主人对话和必要响应能力；短链接仍只提供已有受限后备页，不开放私人对话与话题。
5. **待主人点头：CC 留在身边，正文让给对话。** 主界面大问候与大形象收为页头的小 CC；桌面可选浮宠继续存在，点它回到同一段对话。

## 依据、现状与边界

依据：[主人方向](2026-11-05-one-conversation-topics-direction.md)、[T4 泡泡](2026-11-06-t4-topic-bubbles-design.md)、[U4b 一套语言](2026-11-05-u4b-desktop-one-language.md)、[旧层级](2026-10-05-now-together-hierarchy.md)、[命名规范](../../reference/product-naming.md)。家族规范已读；CC 继续使用正式发光小团资产，不重新画动物、不改外网地址或底层标识。

核对基线为 `t5-design` 的 `20581a83`。现状不能按旧稿标题猜：桌面 `apps/desktop/src/index.html` 主导航是「此刻 / 回忆」，「全部」才打开 workbench；App `src/ui/HomeScreen.tsx` 已是无标签栏主页，经 `/chat` 进对话、`/all` 进历史；网页 `apps/mobile/src/phone.html` 已只有一个主页，包含状态列表和原地详情，仍无完整对话。`mobile-presence.md` 顶部的收敛说明优先于其后历史能力描述。

T5 取代旧层级中「对话在此刻、交办在一起做」的入口分工，保留「每样东西只有一个家」：消息在主人对话，执行记录在原事项，记忆在话题/记忆工具。CC 是中枢，执行者不是聊天成员；项目是文件夹资源，不变成新的聊天容器。T1–T3 负责记忆和事项关联，T4 负责泡泡数据与睡眠；T5 不重新定义这些状态，也不承诺无限模型窗口。

## 三端导航（全部待主人点头）

**桌面：** 主导航「CC / 回忆」，「生活与工具」及设置沿用；「CC」默认就是对话，不先经过 hero。宽屏中间对话、右侧一次只显示一个泡泡或事项详情；看事项时保留返回该泡泡的面包屑。窄屏推入详情，返回恢复阅读位置、草稿与选中话题。没有常驻事项侧栏、「全部」按钮或交办页一级导航。搜索是对话上的临时层，关闭回到原处。

**App：** 保持无标签栏；index 与 chat 合成同一主人对话，页头 CC、连接、更多/设置，底部原生输入框。最近话题行在输入框上方，点开 T4 底部 sheet，必要时扩展全屏。事项从泡泡/消息推入原详情，返回逐层回到原话题/消息位置。旧 `/all`、`/together` 转对话搜索层；`/chat` 转 index，避免来回压入第二份聊天栈。通知响应结束回原页面，冷启动则回对话。

**网页/PWA：** 设备认证后同一对话；宽屏侧面板、小屏可返回详情层，浏览器返回先关当前层再离开；草稿隔离到设备身份，撤销/登出清私人缓存。沿用 `/m`、`/set` 与既有传输，不新增公开站点。只有短链接时显示原受限状态页和配对入口，说明「连接这台设备后和 CC 说话」，不显示私人标题、话题计数或历史。统一界面不等于提升短链接权限。

T4 最近行默认六个、最多八个，按其主人实际聊到/打开时间排序；运行心跳不顶排序。「更多话题」含旧话题搜索，夜间 closed 不删历史标签。点标签只开泡泡，不切聊天、不清草稿、不强制把下一句话绑到该话题。睡眠后未完事项保留泡泡的例外沿 T4，仍待主人点头。

## 在对话里看 CC 做事（全部待主人点头）

目标是主人喜欢的 dots 式「派了一个 agent，看着它做」，不依赖外部产品实现，也不另造群。示例均为虚构：

1. 你：「查一下备份有没有问题。」CC 用正常消息回应，并在真正收到交办回执后显示「交给 Codex 检查备份了」的事项引用；排队时只说排队，未派出不装作开工。
2. 引用内一行「在做 · 正在核对备份文件」，可见执行者名与头像、最后更新时间、「看过程」。阶段变化原位更新，普通工具输出不刷屏，不编百分比；事件断流显示「尚未同步」。原始输出可在过程展开，代码审阅与终端仍用已有工具。
3. 需要主人时更新为「等你决定 · 需要读取这个文件夹」，点开动作层。你在看旧消息时只显示轻量新变化提示，不抢滚动、不自动弹批准。
4. 完成后 CC 发一条结果消息，带原事项和成果引用；过程卡保持可回看。失败说明最后已知一步与可重试动作；取消写「停下了」，不冒充完成。

同一事项仅一个稳定引用身份，可被多条消息/多个话题指向；状态来自同一投影，不复制任务。状态更新不会冒充新聊天消息；阶段/完成事件按 matterId、runId 和事件序号去重，重连补拉后可纠正。并行多件事各自成引用，默认收起，等你优先的定位器可逐件跳转；不把所有事项常驻屏幕顶部。

首次升级不把几百件旧事注入近期聊天。仅在搜索或打开旧链接时显示历史引用；未关联话题的事项仍可检索。新活应先落稳定事项引用，再渐进补话题关联；话题服务失败不影响正常交办与批准。主人问「上次那个备份呢」，CC 按 T2/T3 找记忆并给原事项链接，不能仅凭生成文字宣称找到了。

## 终端与批准（可见交互全部待主人点头）

主人↔CC 输入区只发送给 CC。进入事项/终端才有明确目标的补充框；离开未发送先保存目标和草稿。终端输出默认只读，展开后沿用已有发送、停下、恢复与结束确认；外部程序是否仍在跑未知时不自动接管。电脑已有会话接进来前，保留原程序已关闭声明、路径、执行者和费用确认；「看过程」不是任意远程桌面接管。

批准层展示原请求、目标/影响范围与有效期，沿用「先不做 / 允许这一步」、回答、脚本与自改各自规则。不提供「全部允许」，不因在聊天里说了一句「好」就跳过现有授权。提交必须核对当前 runId/requestId；重复点幂等、过期禁提交、另一端已处理立即同步。网络失败显示「结果待核对」，先查询回执再允许重试。卡片可展示提示，真正动作只由原受保护写口执行。

W 新增审批必须逐类型完成 owner/设备准入、一次性/轮次验证和断线回执测试；未覆盖类型给 App/桌面路径及明确说明。未经配对的 link 身份不能经 UI、请求或订阅得到审批正文；T4 的 owner scope 与私密话题过滤全路径沿用。

## CC 与宠物（全部待主人点头）

小 CC 是同一个助手的在场标识，点它聚焦输入/回对话；连接详细状态单独可达。明暗只依据真实信号，不把正在派活当作明亮依据。对话空态可用正式 CC 与一句邀请；有消息后不保留占半屏的问候和第二张「最近一句」。状态词与 U4b 同表、暖纸与控件使用现有 token，不另加彩色话题体系。

桌面浮宠继续可选，保留拖动、尺寸、位置、开关和原权限能力；双击/原打开动作归一到主人对话，待批准只提示并定位，不在宠物上绕开审批。App 使用现有 CCFigure，网页用冻结正式资产，不新增后台常驻宠物、奖励或陪伴要求。减少动态效果与辅助技术下仍能读出连接、执行者与状态，不能只靠亮暗或动画传达。

## 风险、验收与待定项

以下补救中所有可见行为亦 **待主人点头**。

| 风险 | 主人看见的处理 | 必须取得的证据 |
|---|---|---|
| 取消清单后旧事无处找 | 对话搜索带项目/归档/状态筛选，未归话题事项也能找 | 旧 task/terminal/act 有无话题、有无消息引用均可打开、返回；没有孤儿功能 |
| 对话变成刷屏任务台 | 稳定卡原位更新、工具日志折叠、完成才给结果消息 | 多事项并行、旧消息阅读不跳、分页回看不重复消息 |
| 普通聊天误当交办、补充发错对象 | 原授权门及明确目标补充框；派出前有真实回执 | 发送/切换/取消竞态、同一 requestId 重试不重派 |
| 失联像仍在工作，批准重复/过期 | 尚未同步、结果待核对、已处理态 | 重连补拉、跨端审批竞争、runId 变化、撤销设备/私密性变更负向测试 |
| 话题误归、睡后找不到活 | 来源与纠错可达、搜索兜底；T4 未完例外需点头 | T4 睡眠竞争和私密过滤不回归，未归类事项仍可响应 |
| 网页能力扩张过大或泄露私人内容 | 设备才见对话；暂不支持的工具明确转 App/电脑 | link/非主人/撤销设备对读取、写入、订阅、缓存全路径隔离 |
| 三端不同步、旧通知开空白页 | 能力回退及旧链接映射；正文/草稿仍可恢复 | 新旧 daemon × 三端客户端矩阵、冷启动/通知/分享与 SW 旧缓存验收 |
| 浮宠/键盘挤掉正文 | 小 CC、可收起面板、可读焦点与返回 | mini 宽窄屏、软键盘、长文本、读屏/减弱动态与浮窗回归 |

验证执行：仅在 Mac mini 独立离线数据与假接口中跑 UI、模拟器、截图与构建，按 [lab 规矩](../../maintainer/macmini-ui-lab.md) 持锁，不复制私人状态。异步发送后的效果用 `expect.poll`；期望路径用 `path.join` 或归一化。保留全部原测试，变更视觉 golden 必须说明为本稿批准的布局变化，未涉及的字节不变。开发提交跑 `bun run verify`；全量在低负载 mini 上跑 `bun run verify --full`，不能用构建通过代替 UI 通过，更不能用设计提交宣称已发布。
