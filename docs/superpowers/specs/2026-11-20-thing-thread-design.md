# 点进一件事：右边是它自己的那条线

**状态**：方向已定（主人 2026-11-20：「行，我相信你的判断。但要把交互和页面做好」）；样子见原型 https://claude.ai/artifact/4zmehbrzrkzQSPS5suy4Kz ，主人看过后再定细节。
**接在**：[CC 的两面](2026-11-18-cc-two-sides-design.md) 之后。本稿改掉其中「点上面某一行 = 把这条记录筛成那件事，不换页」这一条。

## 为什么

主人 11-20 第一次认真用桌面 1.8.4 之后：

- 他把左栏每一行叫「会话」，要后退 / 前进，点进 melu 看到空的觉得不对。
- 「从一件事情的连贯性来说，我不否认现在的 codex 这类方式是好的。一个文件夹下可以有不同上下文的内容，但对于整体而言是割裂的，还需要人去把控。」
- 「想把确定的做好，不确定的变成类似于 experimental 的感觉。」
- 「对于 llm 的记忆期望也没有那么绝对。」

现在点一行，右边是「和 CC 的对话」筛成这件事，外加几张引用卡；要看某次会话干了什么，得再点卡片，在另一个面板里只看得到最后一句摘要和一个输入框。主人主要的用法是自己在终端里开 Claude Code / Codex，所以大多数行背后是终端会话，点进去近乎是空的。

## 定下来的（确定的那一层）

形式跟主流（Codex、Claude 桌面版）走，不发明：

1. **左边一行是一件事**（现在 = 一个项目文件夹）。位置固定，不展开，不嵌套。
2. **点一行，右边是这件事的那条线**：你说的、agent 回的、它做的几步，从上到下，停在最新。不再是筛过的 CC 对话。
3. **一件事下面有好几次会话 / 交办时**，线的上方一排可以换（agent 标记 + 标题 + 状态点）；只有一次时不出现。默认是最近动过的那一次。
4. **输入框接着正在看的那一次说**，前面写明对谁说（带那家的标记）。说不了的时候写明原因：正在跑、在等你定、已经结束。
5. **等你定的那一件**在这条线的最下面，紧挨输入框（批准 / 回答就地做）。
6. **和 CC 的对话是最上面那一行**（「CC 在家」）。点它回去；后退 / 前进记的是「哪一行 + 哪一次会话」。
7. 每条线顶上有 CC 的一句现状（先用现有的那一句，也就是左栏显示的；CC 自己写的版本是实验）。
8. 窄窗口（< 900px）：同一套逻辑，版式另排，本稿先只做宽窗口，窄窗口保持现状。

## 做法里选了哪一种

| 做法 | 样子 | 取舍 |
|---|---|---|
| 维持现状再补卡片 | 筛过的 CC 对话 + 引用卡，点卡片去另一个面板 | 改动最小；但看一次会话要两步、两个面板，是这次要解决的毛病 |
| 一件事的所有会话接成一条长线 | 各次会话按时间一段一段排下去，最新的展开 | 最像「CC 把整体接起来」；但并行的会话会互相穿插，线很长，输入框对谁说不清楚 |
| **每次会话一条线，上方一排换着看**（选这个） | 见原型 | 每条线自己连贯（主人认可的 Codex 式连贯）；整体由顶上那一句和（实验里的）图来担；切换一下就到 |

## 现在的数据够不够（2026-11-20 读代码核过）

**终端会话**（主人自己开的 Claude Code / Codex / Cursor，经钩子登记）：

- daemon 每次钩子事件、停下 3 秒后、以及有人看的时候，增量读这次会话的记录文件，把「你说的 / 它说的 / 它做的一步」存成这件事的步（`matter_items`，重启不丢）。`GET /v1/cli/activity` 给最近 40 步。
- 存的时候就截了：你说的、它说的 600 字，一步 120 字，一步的细节（diff / 输出尾巴）1500 字。第一次读只从记录文件最后 256 KB 开始。
- 往会话里说话：有开着的窗口时随时能送（经窗口中继）；否则要它停着、没在等批准、30 分钟内动过、在本机，daemon 用 `--resume` 续一轮（上限 10 分钟）。回复不随这次请求返回，而是之后成为新的一步。
- 结束的会话会从名单里消失（`cli_sessions` 7 天后清）。

**CC 派出去的活**（工作台任务）：完整的事件流、权限卡、提问、产物、diff 都有（`GET /v1/workbench/task`，长轮询）。桌面上只有一个工作台详情实例，靠把它挪到不同的宿主里显示。

## 要补的

**daemon（看不见，先做）**

- 你说的、它说的存全文（上限和工作台任务一致，4 万字）；一步的短句和细节的上限不变。已经存下的旧步不回填。
- `GET /v1/cli/activity` 能往前翻：`before`（上一页最早那一步的游标）+ `limit`（缺省 40，最多 100）；回 `earlier`（没有更早的就是 null）。不带参数时和现在一模一样。手机经旧中继一帧 512 KiB 的限制照现有的「每步文字上限减半直到放得下」处理。
- 结束的会话在名单里留 7 天（归在「回来了」那一组，标明已结束），这样它的线还翻得到。

**桌面（看得见，等主人看过原型）**

- 主区域的「一件事」页：标题行、会话那一排、线、输入区、等你定的那一件。终端会话的线用上面的步来画；工作台任务用现有的那一个详情实例，挪进主区域。
- 「CC 在家」那一行有选中态；点地方行不再筛 CC 的对话。右侧停靠面板不再从地方行打开。
- 后退 / 前进的记录里，「开着哪件事的详情」换成「看着哪一次会话」。

## 实验（不确定的那一层）

规矩：

1. 有固定的归处：「⋯」里单独一组叫「实验」，每项一个开关、一句话说明在试什么。
2. 关着时主路一个像素都不变。
3. 能整个删掉：只读主路的数据，主路不依赖它写的任何东西。
4. 可以不完整，但不能错到让人不信 CC。
5. 每项有去处：用一阵子之后，要么进主路，要么拿掉。

先放进来的候选（都还没做）：

- **把一件事画成图**：一件事分方面铺开；从一件事走到连着的另一件事（换中心）。主人：「思维导图想用想看的原因是一个是很帅，感觉被梳理的清晰。」
- **CC 写的现状句**：左栏那一句由 CC 写，而不是 agent 的最后一句话。
- **捡回来**：主人说的惊喜是「我忘了，但它其实是重要的。被捡回来」和「当时我就这么想过！」；没意思的是「以前的东西给过来一堆，然后发现要整理和梳理」。所以一次一件、已经理好、用他当时的原话和日期。
- LLM wiki 式的「每件事一页，CC 来养」是上面三样背后的那层，做不做、怎么做，等前面的试过再定。11-20 看过 Karpathy 的原文和几个实现（原料不动、页面另写；来一份新的改一片旧的；目录加流水账；定期体检）：它们解决了「整理累」，没有一个会主动把东西递给人；常见的坑是页面越写越多、摘要丢细节且引用出错、反复改写磨掉人的原话。

## 不做

- 不在左栏里嵌套会话列表（11-18 试过就地展开，主人：展开拉长、切换要滚）。
- 不把记忆做成「每句话都指回出处」的重机制作为前提。像朋友的记忆：可以记岔，但别装作确定，要紧时找得到原话。
- 手机网页不跟（只留说话和「现在」）；App 另排。

## 还没定的

- 结束的会话留几天、留在哪（本稿先按 7 天、留在那一排的末尾）。
- 正在跑又没开窗口的会话，要不要做「排队，等它停了再送」。
- 「⋯」里现有的画室、待办、觅食、后厨，哪些算实验，要问主人。
