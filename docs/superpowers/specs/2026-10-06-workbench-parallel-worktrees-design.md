# 一起做：同一个项目并行做几件事（独立工作区）—— 设计草案

> 2026-10-06 · 状态：**待主人拍板**（见文末「要主人定的」）。在拍板之前不写代码。

## 为什么

「一个文件夹一个活会话」（[定 2026-09-21]）让同一个项目里的第二件事只能排队，等第一件收工。对标对象都把「并行」当核心卖点：

- Paseo：Parallel agents —— run many simultaneously, each in separate worktrees。
- Orca：Parallel Worktrees —— multiple agents in isolated git worktrees；还有 `worktree create` CLI。
- Codex app、Conductor 同理。

这条规矩本身没错：两个执行者同时写同一个目录，就会互相踩。要解决的是「同一个**项目**」不等于「同一个**目录**」。git worktree 能给每件事一个独立的目录和分支，同时共享同一个仓库。

## 现状（读代码得到的事实）

- 交办入口 `EntryTarget = {kind:'managed'} | {kind:'project'; projectId}`。任务的 `path` 就是执行者的 cwd，占用、冲突、快照都按它算（`scheduler.findPathBlocker` 比路径包含关系）。
- 任务表有 `workspace_kind: 'project' | 'managed'`。
- 「改动」快照 `git-review.ts` 按任务目录取 baseline。worktree 本身是 git 工作树，可以直接用。
- `self change` 已经在用「一次运行一棵 worktree」（全景导图 92 行），回收用的是显式 `--abandon`。可以照搬它的经验。

## 提议（MVP）

1. **入口**：交办时多一个开关「在独立工作区里做」，只在项目是 git 仓库时出现。桌面、手机交办页、微信 `任务 新建 <项目> 独立 <要求>` 三处都有。
2. **建工作区**：daemon 执行 `git worktree add -b cc/<任务编号> <位置> HEAD`。
   - 任务的 `path` 是这个工作区，新增 `workspace_kind: 'worktree'`，并记下 `source_project_id` 和分支名。
   - **起点是 HEAD**：项目里还没提交的改动不会带进去。界面上要明说这一句。
3. **并行**：工作区路径和项目目录互不包含，`findPathBlocker` 一行不用改，自然就并行了。同一个项目的普通任务（在项目目录本身里跑）仍然和其他普通任务排队。
4. **做完以后**：任务页显示「这件事在分支 `cc/<编号>` 上」。「改动」面板照常可以看、接受、打回、撤销（快照基于工作区）。
5. **回到项目**：MVP **只提供**一个「提交到分支」按钮：daemon 在工作区里执行 `git add -A && git commit`，提交信息取任务标题，作者沿用仓库配置。之后给出一行可复制的 `git merge cc/<编号>`，由主人自己在项目里合并。**不自动合并**：合并冲突、项目目录里未提交的改动，都是主人的判断。
6. **清理**：归档任务时问一句「同时删掉工作区？」，执行 `git worktree remove`，**分支保留**。删分支由主人自己来，因为分支里可能有没合并的东西。工作区目录被手动删掉的，复用 #228 的规则（目录不在 ⇒ 占用解除）。

## 带上本地文件（2026-10-08 已做）

新工作区从 HEAD 检出，`.env`、本地证书这类被 git 忽略的文件不在里面，执行者一跑就缺配置。沿用 Claude Code / Conductor 的约定：仓库根放一个 `.worktreeinclude`（gitignore 写法），列出的文件里**同时被 git 忽略的**，建工作区时从项目复制过去。只复制、不执行；符号链接跳过；最多 1000 个 / 100 MB（`node_modules` 之类让执行者自己装）。

## 归档时收拾（2026-10-08 已做）

不问，直接按规则办：工作区干净（提交过的都在分支上）⇒ 归档时删目录、分支保留；有没提交的改动 / 会话还开着 ⇒ 留着，时间线说一句，不拦归档。

## 拒绝与边界

- 项目不是 git 仓库，或有未完成的 rebase/merge（`.git/MERGE_HEAD` 等）：开关不出现，或拒绝并说明原因。
- `cc/<编号>` 分支已经存在：拒绝，不覆盖。
- 工作区位置所在的盘空间不足：git 自己会报错，原样转成人话。
- 子模块、LFS：MVP 不特别处理，交给 git 的默认行为，在说明里写清楚。

## 不做（这一版）

- 自动合并、自动开 PR（Paseo / Orca 都有 PR 管理，那是另一件事）。
- 远程 / SSH 工作区（Orca 有）。
- 把普通任务迁进工作区。
