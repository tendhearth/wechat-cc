# CC 自己跑开发:主人只说要做什么(设计稿)

2026-10-23 · 状态:设计稿,**重构(第三批)做完再开工**(主人 10-23 拍板:「先写设计稿,重构做完再开工」)

## 1. 为什么

主人 10-22:「希望以后我可以直接用 cc 而不是通过 claude / codex 下达任务。」

现在的开发是这样跑的:主人在 Claude Code / Codex 终端里开两路会话,一路写代码,一路当整合者(审、合、部署、汇报),两路之间用会话消息协作。主人只在要拍板的时候出现。这套做法这两天(10-21 到 10-23)合了 #497–#587 将近一百个 PR,抓到过一串真问题。但入口是终端,而且主人得自己开会话、自己当调度员。

目标:主人在微信 / App / 桌面对 CC 说一句「把 X 做了」或者「继续做重构」,CC 自己拆活、派执行者、互相评审、过闸门、合进 `dev`、部署、真机核对,只在真要主人拍的事上问他,其余用人话汇报。

这正是 CC 的定位:agent 之上的编排 + 多端(见 `positioning-replace-paseo`、`overseer-direction`),不是让主人去当编排者。

## 3. 缺什么(两路会话做了、自改做不了的)

按这两天真发生过的事列,每一条后面是它挡下来的东西:

1. **拆活。** 「继续重构」要变成一串有先后的小 PR,叠着走(父 PR 合了,子 PR rebase、改 base、关掉再打开才跑 CI)。自改一次只认一条需求。
2. **并行开发,一个整合者串行合。** 两条线同时写,合并只有一个人按顺序做;撞了 BASELINE 谁后合谁 rebase。自改一次只跑一条,也没有队列。
3. **互相评审,而且两个方向都有用。** 整合者审出开发者的:#542 start 段上游坏了、下游照样开动;#546 社交状态拿现在的配置算,跟状态页(开机时的模块状态)对不上;#576 写主人家目录配置会把 dotfiles 的符号链接换成普通文件;#579 / #580 设计时指出被撤掉的那句会经总览在串门时说给外人听(落在 #581 的 added / retracted 和 #586 的「更正在哪儿都算数」)。开发者也纠正过整合者:#542 上游坏了下游应跟着 degraded、不能标 off(我原来说的「跟着 off」是一句假话);#564 我把快照里 trusted 的 codex 格读成关网;#577 我建议的「一律跟随符号链接」会给 CC 自己的状态目录开一个重定向口子。自改的评审是同一家(Claude)的另一个会话,没有这种互相纠正。
4. **判读 CI。** 什么是 flake、什么是真红,要读日志、读抛错的那行代码再下结论。几次真红都是这样分出来的:#569 的两条(Windows 权限位断言、自改遇坏配置会抛)、#546 的 e2e 路由快照、#537 自己写的依赖 git 措辞的测试。也有反过来的:Windows 上工作台测试的 Hook timed out 一天五六次,读日志才发现是测试收尾留着打开的文件(189 行 EBUSY)。
5. **看机器忙不忙。** 主人在打游戏或跑模拟器时(load 100–240),本机全量既拖慢他、结果也不可信 ⇒ 以 CI 为准;部署要等他不用机器。自改不看这个。
6. **部署后真机核对。** 不只是自检 PASS:看关机行顺序、配置文件键数和权限位、有没有残留 tmp、锁等待那一行。每一批核的东西不一样。
7. **知道什么该问主人。** 改了主人每天看得见的行为(Cursor 改成逐条弹卡、桌面总览变只读)要问;纯重构不问;发版、TestFlight 永远问。两路会话里有一次差点按旧授权自己定了(Policy 第 5、6 步),被拦下来了。
8. **用人话汇报。** 汇报说的是「对主人意味着什么」,不说 PR 号和文件名。
9. **做法清单。** 上面这些都靠两路会话的记忆和笔记在撑,CC 自己读不到。

## 4. 设计

### 4.1 一个「开发目标」是一件事

主人说「把 X 做了」⇒ 建一件 `matter`,类型 `dev_goal`,挂在这个仓库上。三端都看得见它的进度:计划、每个 PR 的状态、在等主人拍什么、花了多少钱。主人在任何一端都能说「停」「先别部署」「这条不要了」。

### 4.2 四个角色,只有两个是模型

| 角色 | 是什么 | 做什么 |
|---|---|---|
| **规划者** | 模型(一个执行者会话,只读) | 读需求、读代码、读 `docs/`,产出一份计划:要改什么、拆成几个 PR、先后和依赖、哪些步骤改变主人看得见的行为。大改动先写设计稿(跟现在一样,设计稿本身也是一个 PR) |
| **开发者** | 模型(工作台执行者,独立工作区) | 一个 PR 一个工作区,实现 + 本地验证(看负载决定跑全量还是跑相关目录)+ 开 PR |
| **评审者** | 模型,**跟开发者不是同一家**。谁写谁审**由 CC 每次自己挑**(主人 10-23:「应该让 CC 来决定」):看谁此刻能用(额度、登录、地区被拒 —— 10-23 晚 Cursor 额度用完、agy 在出口地区被拒,能用的只有 Claude 和 Codex),优先让评审跟开发不同家,挑的理由写进计划 | 只读;输入不只是 diff:还有这个 PR 在计划里是哪一步、对应的设计稿、`practices.md`,才判得出「偏离了设计」「漏了规矩」。读周围的代码、自己跑能跑的检查;给 verdict + findings。findings 回给开发者修;两轮修不掉、或者两边意见相左 ⇒ 问主人 |
| **整合者** | **代码,不是模型**(daemon 里的合并队列) | 按计划的先后等 CI、调 `ci triage`、flake 重跑、真红交回开发者、叠着的子 PR 自动 rebase 改 base 重开、按顺序 squash 合 `dev`、一批合完排部署 |

整合者做成代码,是因为这两天它做的事几乎都是确定的:顺序、等绿、重跑、rebase、`--match-head-commit`。模型只在判断处出现:「这条红是不是这个 PR 造成的」交给评审者,读日志和抛错那行代码再说成因(`read-code-before-naming-flake-cause`)。

### 4.3 做法清单:CC 读得到的规矩

新建 `docs/maintainer/practices.md`,一条一条写,每条带出处(哪个 PR、哪次事故)。规划者、开发者、评审者的提示词都引用它。起始清单就是这两天的:

- 跑全量前先看负载,主人在用机器就以 CI 为准;两个执行者不同时跑全量。
- 改到命令路由必跑 `test:e2e`(#546 漏过一次)。
- 推之前跑整个目录,别只跑「相关的」(#569 漏过 `src/lib` 的仓库守卫和 `src/cli/self-change`)。
- 偶发红先读抛错的代码再说成因;「与本 PR 无关」要有证据。
- 改变主人看得见的行为 ⇒ 停在设计稿里等主人;授权不外推到「天天看得见」的变化。
- CC 不骗人:坏了不说成关了,没核实的写 none,已知限制写进稿子和测试。
- 守卫读源码先把 CRLF 统一成 `\n`;去注释按行判,别用跨行正则(#541、#568 两次)。
- 叠着的 PR:父 PR squash 后,子 PR `--onto origin/dev`、改 base、关掉再打开。
- 别在还有 pending 检查时合。
- 已经进 `dev` 的迁移一字不改(#583 由 CI 守)。
- 存密钥的文件每次写都给 0o600;写主人家目录配置要跟随符号链接。
- 守卫写好以后,先故意把被守的东西弄坏,看它红了才算数(几乎每个守卫 PR 都这样证明过)。
- 证明「重构是逐字搬家」要用对方法:`fn.toString()` 会被 Bun 按缩进重排,要用 TS 解析器取源文本逐字比,或者非空行多重集比(#582)。
- 子 agent 的结论先核再用(#501 一次 489 行手写光栅化被换掉)。
- 代码和设计稿对不上时,改设计稿并在 PR 里写明偏离(#566 删 assertSupported、#587 不改老守卫的注释)。
- 缺省往拒绝 / 藏的方向兜底:认不出的执行者对访客关门(#556),没记原因的过期按 retracted(#581)。
- 有风险的能力按需开、不默认开(#577 followSymlink 只给两处)。
- 显式胜过推断(#581 fs-api 的 layout 显式传,不从目录名猜)。
- 每条命令都显式进自己的工作区,别在主检出里跑 git(10-22 一次在主检出 checkout --detach)。
- 执行者不碰在跑的 daemon(临时 HOME 不隔离 launchd;派活时写明禁 launchctl)。

清单本身由守卫检查格式(每条有出处),新增一条走 PR。

### 4.4 闸门:单个 PR 沿用自改的,加一层「一批」

**单个 PR:** 沿用自改的五道(禁改清单 → 本地测试 → 评审 → CI → 合并),只改两处:评审换成另一家;CI 交给整合者的队列,不再每条自己等。

**一批:** 一组 PR 合完以后、部署之前,整合者要做四件事:

1. **看负载**:load 高或主人刚在动机器 ⇒ 不在本机跑全量,也不构建,等;修 bug 的批次例外,但要在汇报里写明。
2. **全量**:机器空着才跑;不空就以各 PR 的 CI 全量为准,汇报里照实写「本机没跑」。
3. **部署 + 自检**:`self deploy`,然后 `selftest workbench` + `selftest chat`。
4. **真机核对**:计划里每个 PR 可以写「部署后要看什么」(比如「日志里有 `stopped knowledge/store close`」「agent-config 键数没变」),整合者照着查。结果分三种,汇报里说法不一样:**核对过**;**发现坏了**(停下来,不继续下一批,必要时回滚);**核不了**(比如要主人真配对一次、要 Windows 真机)⇒ 记成待核对,照实说哪一条没核,不算过、也不挡下一批。

### 4.5 什么时候问主人(准绳)

一律问:
- 改变主人日常看得见的行为(界面、微信里的说法、执行者会不会弹卡);
- 发版、TestFlight、任何对外的动作;
- 碰禁改清单;
- 评审和开发两轮谈不拢。

不问、做完汇报:纯重构、修 bug(行为回到本来该有的样子)、测试、文档、守卫。

问的方式:一张 blocking 卡,写清选项和我的推荐,跟现在两路会话问主人的口径一样。主人不在线时,这一件停在那里,其他件照走。

### 4.6 汇报

- 每合一批:一条 report(人话:「这批之后,你的配置文件不会再因为同时写坏掉」),附 PR 链接,但正文不讲 PR 号。
- 每天一次总结,跟日报合并。
- 卡住了(真红修不掉、等拍板超过一天)单独说一句。

都走 SpeechPolicy:免打扰时推后,断线时排队,不重试风暴。

### 4.7 不按预算按价值;停机、并发

- **不设预算**(主人 10-23:「不能按照预算来,而是发掘高价值任务……花费不用考虑」)。挑什么做看 §4.8 的价值排序,不看花多少。
- 不设预算不等于没有闸。两道闸防的不是花钱,是**在一件注定失败的事上空转**(10-23 晚的真例:回忆两天问了 agy 28 次,次次地区被拒):
  - 同一种失败(同一条测试、同一句错误)连着两次 ⇒ 不再原样重试,换思路或者交回规划者;
  - 沿用自改的 `fail_streak` 停机:连续失败 N 次 ⇒ 停机,`--unhalt` 才能继续。
- 同一个仓库同时最多两个开发者工作区、一个整合者;全量测试同时最多一个。机器上还有第三方:**主人自己**。他在用机器(load 高、前台有重活)时,开发者也不跑全量,整合者不构建不部署;这条比「两个执行者别撞」优先。

### 4.8 发掘任务:CC 自己找该做什么

主人要的不是「说了 CC 才做」,而是 CC 自己迭代自己(10-23:「我希望 cc 可以自己迭代自己」;方向:**AI native、多平台、CC 大总管**)。这两天两路会话做的事,大半是「找活」:对比同类产品、读真机日志、看欠账。这一节把它变成 CC 的能力。

**从哪儿找(四个来源,每条候选都带证据):**

| 来源 | 读什么 | 10-23 的真例 |
|---|---|---|
| 真机信号 | 日志里重复的失败行、意外重启、`self soak` 红、自检失败、`ci triage` 认出的 flake 与它们的频率、TurnRecords 里的错误码 | agy 回忆 28 次地区被拒;拒写那句话 daemon 开着也说「要先开守护进程」 |
| 欠账 | 守卫里还在记账的基线(数字只许降的那些)、roadmap 的欠账段、设计稿里写了「以后」的 | CLI 链 daemon 的棘轮 39 → 38 |
| 同类产品 | Meta Muse、OpenAI dots、Paseo、Claude Code、Codex:它们有什么、CC 缺什么、哪个跟「本机 / 不绑一家 / 微信」的定位相合 | 记忆编辑(对标 Muse / dots)、并行工作区(对标 Paseo) |
| 主人的话 | 聊天里的抱怨、重复提的需求、「又不行了」这类句子;主人改过的记忆 | 「测试和 CI 太多,开发一直在等」⇒ 当晚 CI 提速四件 |

**怎么排:** 每条候选写成「问题 → 证据 → 对主人意味着什么 → 改动大小 → 风险」。价值看三样:**影响面**(天天碰到 > 偶尔)、**确定性**(有日志 / 复现 > 推测)、**方向**(AI native、多平台、大总管 > 别的)。不看花费。

**怎么走:**
- 修 bug、重构、测试、守卫、文档 ⇒ 直接进开发流程,做完用人话汇报(主人 10-23 选的);
- 改变主人看得见的行为 ⇒ 攒起来,**一天最多一条消息**问主人,每条写清选项和推荐;主人不回就不做,别的照走;
- 碰禁改清单、发版 ⇒ 永远问。

**什么时候找:** 每晚整理记忆之后一次(那时日志一天的量刚好齐);部署后 `self soak` 红的当场一次。找活本身只读:读日志、读代码、读本地记的产品笔记 —— **不为了找活去联网**(对比同类产品用的是已经记下的笔记,要更新笔记是一件单独的任务,走正常流程)。

## 5. 不做

- **不自己发版**,不碰 `master`,不传 TestFlight:这些永远要主人点头。
- **不改禁改清单里的东西**,包括这条流水线本身的闸门代码(防止它把自己的护栏改松)。
- **不用免审执行者(agy)当开发者**:它收不住任何工具面(#567 的 confines 全是 none)。
- 第一版只管这一个仓库(wechat-cc 自己)。主人的其他项目以后再说。

## 6. 怎么分步

每步一个或几个 PR,单独能合、单独能停。主人 10-23「我希望 cc 可以自己迭代自己」之后,不再等重构全部做完:跟核心链不碰同一处的步骤(1、2、3、4 的 CLI 部分、5)先做;要动 daemon 主流程的(入口、`dev_goal` 那件事)排在核心链之后。

1. **做法清单成文件**:`docs/maintainer/practices.md` 加格式守卫。只有文档。
2. **评审换人,由 CC 挑**:自改的 review 步改成另一家执行者,按 §4.2 现挑;findings 回路不变。
3. **合并队列(整合者)**:砖已经有了 —— `wechat-cc ci land`(10-23,#623 / #624:只等最上面那个的 CI、从下往上 rebase / 改 base / squash、中断了接着来)。这一步把它接进自改,让自改的一串 PR 走它。**已做**(2026-10-23):自改推 `self/<id>` 时开进 dev 的 PR,拍板后交给 ci land squash 合;CI 改成只认 PR(`self/**` 推送不再单跑),自改的 PR 照旧三平台。
4. **一批的部署门**:砖也有了 —— `bun run verify`(本地只跑牵连到的)、`wechat-cc self soak`(部署稳不稳看信号,不死等一天)。这一步补负载判断,把 deploy → selftest → soak 串成一道门。**已做**(2026-10-23):`wechat-cc self ship`(负载 → 网络守护 → 构建 → deploy → 自检,红了回滚,之后看 soak);自改的 deploy 步过同一道门(`machine_busy` / `network_unprotected`,停在 deploy 可 `--resume`)。
5. **发掘任务**(§4.8):每晚一次,产出排好序的候选;修 bug / 重构类直接进 1–4 的流程,看得见的攒成一天一条问主人。
6. **规划者**:目标变成计划和 PR 列表;碰到「主人看得见的行为」自动停在设计稿等拍板。**CLI 那一半已做**(2026-10-23):`wechat-cc self plan "<目标>"`(只读规划、JSON 计划、代码校验依赖、`visible` 标出要点头的);接进 `dev_goal` 与自动执行在核心链之后。
7. **并行开发**:两个工作区,按依赖图排。
8. **入口**:微信 / App / 桌面「开发 <目标>」,挂成 `dev_goal` 这件事,三端看进度、能叫停。

1–5 做完,CC 就能自己找活、自己做、自己合,得到的是今天两路会话的质量;6–8 才是「继续做重构」这种整件的目标。

## 7. 风险

- **空转**:不设预算以后,真正的风险是在注定失败的事上反复试。⇒ §4.7 的两道闸;找活本身只读、不联网。
- **没有人在看就合了坏代码**:评审换人加 CI 加真机核对是三层,主人看得见的行为仍然要拍板。合进 `dev` 不等于发版。
- **CI 不稳导致白烧**:Windows 工作台超时这类已知 flake 由 triage 认;同一个 PR 重跑两次还红就当真红,交回开发者。修 Windows 超时本身(工作台测试留着打开的文件)是重构里的一项欠账,要先做掉。
- **改自己的流水线**:流水线代码在禁改清单里,要改走人(主人或终端会话)。

## 8. 主人拍过的(2026-10-23)

1. **谁写谁审**:「这个不急,但其实应该让 CC 来决定」⇒ 不定缺省搭配,CC 每次按 §4.2 现挑。
2. **预算**:「不能按照预算来,而是发掘高价值任务,AI native 多平台,CC 大总管。花费不用考虑」⇒ 不设预算(§4.7),加 §4.8 发掘任务。
3. **合进 `dev` 和部署要不要每次问**:纯重构 / 修 bug 直接做、事后汇报;改变看得见的行为的仍然逐条问;发版永远问。
