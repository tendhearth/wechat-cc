# 「CC 做过的事」时间线(B9)—— 设计

> 2026-10-20 · 状态:**定稿,可以开工**。手机端对标表 B9(Meta Muse 的动态页)。主人 10-20 `/loop`「继续开发,不要打扰我,还有很多功能没实现,可以参考同类产品」。

## 为什么

CC 在主人不看的时候做了很多事:主动说话、跑定时和早报、到点提醒、替他按规则批了权限、一起做的事做完 / 卡住、终端会话收工、每晚整理记忆、寄信、升级 CLI。现在这些散在微信、日报、各页里,没有一个地方能回头翻「它都替我干了什么」。Muse 有动态页;ChatGPT 的 Tasks 有运行记录。这是「CC 是大总管」最直接的证据,也是信任的来源:做了什么都看得见。

**成功的样子**:手机上一页「CC 做过的事」,最新的在上,往下翻能翻到两周前;每条一句话 + 时间,点开能到那件事(任务 / 终端会话 / 信)。电脑睡着时照实说翻不到。

## 不做 / 反目标

- 不做:访客 / 别人的对话内容(只算主人);把这页做成聊天记录(只记 CC **替主人做的动作**,不记每句回复);调模型总结(纯本机、确定性);写操作(只读)。
- 反目标:伪造(没有记录的事不编,读不到的来源标「这一类暂时读不到」);泄露正文(信只给开头一句,定时只给标题,权限只给工具 + 摘要);把路径带到手机(只给目录名)。

## 怎么给手机

- `GET /m/api/activity?cursor=&limit=` —— **只给设备令牌**(LINK_EXCLUDED:里面有主动消息与定时标题)。合并做法照 `mobile-feed.ts`:每个来源各自 try / catch,坏一个只标 `degraded: [来源]`;游标 = base64url(`at|id`);默认 30、最多 100;窗口 14 天。
- 每条 `{id, kind, at, title, ref?: {type:'task'|'terminal'|'letter', id}}`;title ≤ 120 字、一行、无路径。
- 纯函数 `src/core/cc-activity.ts`(合并 / 游标 / 截断 / 成句),来源在 `src/daemon/cc-activity-source.ts`,追加日志 `src/daemon/activity-log.ts`。

## 界面

- 手机网页:「此刻」页底部一行「CC 做过的事 ›」进新页(我做);App 同样一行进 `/activity`(wechat-cc-2a 做)。
- 用词照 `reference/phone-wording.md`;不用颜色区分类型,只用一个前导词(批了 / 做完了 / 寄了 / 提醒了 …)。

## 测试要钉住的

- 合并:多源按时间倒序、同刻按 id;游标翻页不重不漏;limit 封顶;14 天外不出。
- 坏一个来源只进 degraded,其余照出。
- 只算主人:访客的提醒 / 消息不出现;通知只取主人的 owner_chat_id。
- 不泄露:路径变目录名;信只开头一句;title 一行 ≤120。
- 追加日志:写失败不影响动作本身;超长截半;坏行跳过。
- 路由:只给设备令牌(link 令牌 403);过 schema。
