# 管家的屋子:三端主界面重排(2026-11-17)

状态:**主人 11-17 授权整合者按自己的建议定稿并实施**(「都可以改,甚至推倒重来……按照你的建议」)。本稿取代 [T5 一段对话的界面](2026-11-06-t5-one-conversation-ui-design.md) 里的导航与布局部分;T5 的「每样东西只有一个家」「派活是一条消息」「批准走原受保护写口」等规矩继续有效。上位方向是 [一个管家](2026-11-12-one-butler-direction.md)。

## 1. 为什么重排

11-12 总纲定了三层:**中心是你和 CC 的一段对话;聊着分出去的是事,事下面挂一个或多个 agent;沉下来的是话题记忆。** 还定了两条界面规矩:**做事时直通不转述**、**谁在回就露谁的标**。现在的骨架(T5,11-06)早于总纲,接不住三件事:

1. **我在跟谁说。** 三端都只有一个对话输入框;「直通」只能靠事项层里另一个「补充给这件事」框(桌面 `workbench.js` 的 `wb-followup`,App 要先跳到 `/compose`,网页没有)。你得进两层才能跟正在干活的 agent 说一句话。
2. **手下在干什么。** 没有任何主屏常驻地方能一眼看到「Codex 在做备份检查、Claude 在 bx 终端等你、迁移接力到第 2 棒」。桌面 `now-page.js` 其实还会画「在做 / 带回来的」,但 `index.html` 早就没有挂载点,这份能力处于休眠状态。
3. **你最常用的东西没有位置。** 11-08 的真实数据是:两周约 80 个终端会话、12 个项目,微信一周只说 3 句。终端会话在桌面只出现在「等你」行和对话里的只读卡片上;挂进一件事(v116)后,只在事项详情的记录本里露一行。

还有一条反向的证据:**话题行没人用。** 11-06 复核时线上泡泡打开次数 0、回合内调记忆 0。话题行占着输入框上方最显眼的一行,却没有承担实际作用。

## 2. 目标 / 不做 / 反目标

**目标**
- 打开就看得见两样东西:**和 CC 的对话**,以及**手下在做的事**。
- 跟谁说话,就在谁的输入框里打字;不需要切模式,也不需要进两层。
- 多 agent 的事一眼看清接力到哪一棒、现在是谁在答。
- 终端会话(包括没挂进事的)和交办的事排在同一张名单里,用同一套状态词。

**不做**
- 不做 agent 群聊,也不做「同时跟三个 agent 说」。
- 不恢复「全部」目的页;更早的事走搜索。
- 不改协议里的状态表、批准语义、短链接权限、执行者沙箱。
- 不做新功能:并行接力、翻笔记本等按总纲另排。

**反目标**(就算功能都通了,出现下面这些也算失败)
- 右栏变成工作台或终端,满屏工具输出。右栏只放「事」,过程细节仍然折叠。
- 同一件事的进展在对话里和右栏里各更新一份(违反「一个家」)。
- 主人在右栏打的字被 CC 改写或插话。
- 在手机上这排头像挡住对话,或者每次有变化都要去点掉。

## 3. 考虑过的三条路

| 路 | 是什么 | 取舍 | 结论 |
|---|---|---|---|
| A 一条对话 + 输入框选人 | 保持 T5,在输入框前加「对 CC 说 ▾」切换目标 | 改动最小;但 agent 原话会混进和 CC 的闲聊里,「谁在干活」仍然看不见;选错目标的代价高 | 不选 |
| **B 对话 + 「在做」名单 / 直通** | 桌面:对话在左、名单在右,点一件事右栏变成直通;手机:对话顶部一排头像,点了推进直通页 | 直接对上三层;在哪个框打字就是跟谁说;终端会话有了位置。代价:把 T5 撤掉的常驻事项栏放回来一半(只放活着的) | **选这条** |
| C 以项目 / 事为首页 | 首页是按项目分的工作台,CC 陪在边上 | 最贴近现在主要用终端的习惯,但就变成了 Paseo,违背「中心是一段对话」 | 不选 |

B 的代价可以接受,理由有二:名单只放**等你 / 在做 / 24 小时内带回来的**,不是「全部」;而且「手下在干什么」本来就是你用得最多的那一层(11-08 数据)。

## 4. 定下的设计(整合者定,主人授权)

### 4.1 一张名单(daemon 一处算,三端共用)

新增 daemon 投影 **名单(roster)**,每条是「一件事」或「一个没挂进事的终端会话」:

```
RosterItem {
  key            // "matter:<id>" | "terminal:<sessionKey>"
  kind           // "matter" | "terminal"
  title          // 事名;终端会话用项目目录名 + 首句摘要
  project?       // 文件夹显示名(话题 = 项目)
  group          // "waiting" | "working" | "back"(只认 status-table.ts 的映射)
  status         // status-table 里的状态键,词由端上查表
  agents: [{ id, provider, current: boolean }]   // 当前棒 current=true
  relay?: { index, total }                       // 只有计划多棒时有
  waiting?: { kind: "permission"|"question"|"quota", requestId }
  updatedAt, unseen: boolean
}
```

- **哪些进名单**(`MatterKind` 见 `src/ports/matters.ts`):
  - `task` 事:进,`kind: "matter"`。
  - `terminal` 事(终端会话已经是一件事):进,`kind: "matter"`;直通时说话走 `cli/session-say`,详情开终端详情。
  - 挂进别的事的终端会话(v116 `TerminalParticipation`):**不单列**,算进那件事的 `agents`。
  - 既没有 matter、也没挂进事的 CLI 会话(`/v1/cli/sessions` 里 `matter_id` 为空):`kind: "terminal"`。结束了的不列(沿用用词表)。
  - `act`(CC 自己做的事):**不进**。主人 10-31 定「CC 自己做的事不和交办混排」(`apps/app/src/view/home.ts` 现行规则);何况 11-08 数据里 CC 交办的全是自检,放进来会把名单刷满。
  - `chat`(主人对话本身):不进。
- **排序**:等你在前(按等待开始时间),在做其次(按更新时间),带回来的最后(只收 24 小时内,没看过的优先)。
- **`unseen` 用现有数据**:任何一端记过看过(`matter_bindings.last_seen_at`,不分端)就算看过;在桌面右栏打开一件事也记看过(走 S3c 已有的记看过口)。终端会话没有「看过」,`unseen` 恒为 false。所以**不加迁移**。
- **取代 App 的端上分组**:`apps/app/src/view/home.ts` 的 `homeView` 里与数据有关的规则(分组、`QUIET_AFTER_MS`、每行说明文字与详情文字)搬进 daemon 的名单投影;和连接有关的(`known=false` 时藏等你组、`keepStaleWaiting`、「你不在的这 N 小时」改标)留在端上。三端只剩一套分组规则。
- **路由**:`GET /v1/roster`(桌面,operator token)(App / 已配对网页用设备令牌从面板那一口进来,同一条路由;手机一族只用 /v1,不新增 /m/api 别名)。
- **更新**:手机走 subscribe hub,新增 `roster` 频道;matter 变更沿用现有来源戳它,另外**补一个终端会话来源**(会话开始 / 等你 / 歇着 / 结束时戳 `roster`)。现在终端状态变化不推 hub,等你行会落后到兜底轮询。桌面没有 hub(hub 只给已登记设备),窗口可见时每 3 秒轮询 `/v1/roster`,和桌面现有的轮询器一致;用 `etag` 省流量。
- 短链接(非设备令牌)拿不到名单,与现在网页短链接只看受限状态页一致。
- 这是 **只读投影**:不新增状态、不加迁移。

### 4.2 桌面:两栏,去掉左侧导航

```
┌──────────────────────────────────────────┬───────────────────────────┐
│ ◯ CC  在身边          搜索  记忆  回忆  ⋯ │ 在做                    4 │
│                                          │ 等你                      │
│  你:查一下备份有没有问题                  │  ◉ bx · Claude Code       │
│  CC:交给 Codex 了 ── 备份检查 ›           │    等你决定:读 ~/.ssh     │
│  ...                                     │ 在做                      │
│  CC:迁移那件事 Claude 做完第 1 棒,        │  ◉◉ 迁移数据库   2/3      │
│      Codex 接着在做。                     │  ◉ 备份检查               │
│                                          │ 带回来的                  │
│                                          │  ◉ leni 截图对比  完成    │
│ ◯ 对 CC 说…                    ＋   ↑    │                           │
└──────────────────────────────────────────┴───────────────────────────┘
```

- **左侧导航撤掉。** 页头右侧只留「搜索 / 记忆 / 回忆 / ⋯」;「⋯」里是画室、待办、觅食、后厨、设置。七项变成两项加一个菜单。理由:管家总纲里记忆是总账,所以单列;回忆是 CC 的生活(信、明信片、作品),是 CC 之所以不是工具的那一面,也单列;其余都是偶尔去的地方。点进这些页面时,它们**替换左栏**,右栏名单保留不动(名单是全局的「家里现在怎样」)。
- **右栏宽 360px**,进入直通时展开到 400px(要放输入框和拍板卡)(窗口 ≥ 1080px 时),左栏自适应;窗口 < 1080px 时右栏收进页头的「在做 4」按钮,点开从右侧滑出,直通也在这个滑层里。
- **点名单里的一行,右栏变成直通:**
  ```
  ┌ ‹ 在做 ─────────────────────────────┐
  │ ◉ Codex · 备份检查        停下   ⋯ │
  │ Claude ✓ ─ Codex 在做 ─ Claude      │   ← 只有多棒时
  │ ▸ 记录本(3 条)                      │
  │ ─────────────────────────────────── │
  │ Codex:已核对 12 个快照,发现 …       │   ← agent 原话,不经 CC
  │ ▸ 跑了 4 条命令                     │   ← 过程折叠
  │ [等你决定:读 ~/.ssh] 先不做 / 允许这一步 │
  │ ─────────────────────────────────── │
  │ ◉ 对 Codex 说…                 ↑    │
  └─────────────────────────────────────┘
  ```
  - 输入框发到 `matters.say`(任务事;服务端决定走 input 还是 continue,多棒时只发给当前棒,不能点头像换人,沿用 who-answers §2 第 2 条,实现在 `features/workbench/service/relay.ts` 与 `matters.say`);终端会话发到 `cli/session-say`。框左边是那一家的圆标,占位文字是「对 Codex 说…」。
  - 内容复用现有的事项详情(`workbench.js` 任务详情、`conversation-work-detail.js` 终端详情)。不重写,只是挂载点从全屏的 `#conversation-matter-layer` 改到右栏;改动、diff 审阅、回退这些重工具仍然打开现在的全屏事项层(右栏页头的「⋯ → 看改动」)。
  - 「‹ 在做」回到名单;右栏草稿按事保存。
- **对话里的事项卡变瘦:** 只剩一行「交给 Codex 了 ── 备份检查 ›」,带圆标与状态词,不再在卡里展开进展、不再 5 秒轮询;点它就在右栏打开直通。进展只有一个家,就是右栏。完成时 CC 照旧发一条结果消息。
- **撤掉的:** 输入框上方的话题行、「N 件事等你」定位器(都由右栏顶上的「等你」组承担);`now-hero` 大形象(T5 已缩小,这次彻底并进页头)。
- **两个输入框同屏时**,焦点所在的框加强调色的 1px 下划线,另一个变浅;⌘1 / ⌘2 在两框间切换。

### 4.3 手机(App 与已配对网页同一套)

```
┌────────────────────────────┐
│ ◯ CC 在身边        搜索  ⋯ │
│ ◉ ◉ ◉◉ ◉   在做 4 ›        │ ← 名单条:等你的头像带强调色描边
│────────────────────────────│
│ 对话 ……                    │
│                            │
│ ◯ 对 CC 说…          ＋ ↑ │
└────────────────────────────┘
```

- **名单条**:页头下一行,一件事一个头像(多 agent 的事叠两枚,当前棒在前),只放等你和在做两组,最多 5 个;末尾「在做 N ›」(N 含带回来的)打开底部 sheet,里面是完整的三组名单。三组都空时整行不占位置。
- **点头像 → 推进直通页**(全屏,手势返回回到对话原位置):页头「‹ CC  ◉ 在跟 Codex 说 · 备份检查」,内容与桌面右栏同一份(App 复用 `matter/[id]`、`terminal/[id]`;网页复用 `#m-detail`),底部输入框「对 Codex 说…」直接发出,不再跳 `/compose`。
- **网页补齐直通输入框**(只对设备令牌;短链接不变)。这是网页第一次能对一件事说话,发送走 `/m/api/matter/say` 与终端说话路由,和 App 同口。
- 撤掉:话题行、「N 件事等你」定位器(名单条上的强调描边承担)。

### 4.4 话题去哪了

话题(= 项目)仍然是记忆的单位,不删数据、不改每晚整理。只是**入口从输入框上方挪走**:
- 名单每行写项目名;直通页头的项目名可点,点开那个话题(复用现有 topic 详情)。
- 记忆页顶部列话题,改名 / 合并 / 删除 / 标错都在那里(T6 已有)。
- (以后另立)CC 在对话里用到某个话题时,消息下方带一个「想起:上次迁服务器 ›」引用。现在没有任何对话消息记着「这一句召回了哪个话题」,要做就得按消息存、加迁移,所以**不在本稿范围**,和总纲第 5 条「想起来分三档」一起做。

这一条推翻了 11-05 主人定的「输入框上方一排最近话题」。理由是线上从没被打开过,而它的「项目 + 会话数」那部分(#890)已经由名单的项目名承担。

### 4.5 CC 形象与视觉语言

- **CC 形象不换。** 家族规范定了 cc 是发光小团;Blender 美术和「CC 会看你」的眼神系统已经三端统一。变化只在位置:CC 住在对话页头(桌面 40px、手机 32px),明暗仍然表示在不在身边。
- **新加一个小动作:** 名单里某一行刚变成「等你」或「完成」时,CC 往那边看一眼(复用眼神素材,1.2 秒,一天同一件事只看一次)。这让 CC 像在照看手下,也提示你右边有事。不发声、不弹窗。
- **名单空的时候**(桌面右栏没有任何活着的事),右栏中间放一个大一点的 CC 在打盹,配一句「都歇着」。家族规范说角色出现在空页面,这里正合适。
- **视觉语言保留:** 全衬线、暖纸色、一个强调色、页面不变色、没有深色模式。我按新布局重新检查过,没有要改的理由。两栏之间只用一条发丝线分开,右栏不另换底色;直通内容里的代码 / 命令用等宽字(已有 token),agent 的正文仍然用衬线。圆标仍然是唯一的厂牌露出(who-answers §3)。

## 5. 约束

- 状态词、分组只认 `packages/protocol/src/status-table.ts`;按钮词按 `docs/reference/phone-wording.md`。
- 设计守卫:`design-style.test.ts`(无深色、字重 400/500、状态是字形 + 文字)、`component-appearance.guard.test.ts`、`design-tokens.guard.test.ts` 都要继续绿。`apps/desktop/src/rail.test.ts` 钉的是旧的左侧导航,要按新结构**改写**(PR 里写进 `## 删掉/放松的测试`:改写理由 = 布局换了,新守卫钉页头导航与右栏挂载点,条数不少于原来)。
- Playwright 与截图验收只在 mini 跑(AGENTS.md 双 Mac 分工);主 Mac 只跑 `bun run verify`。
- 批准、停下、回退等写操作都只走原受保护写口;右栏 / 直通页只是换了挂载点。
- 名单路由的鉴权与现有 `/v1/matters`、`/m/api/matters` 相同,不放宽。

## 6. 拆步(每步一个 PR,从 dev 起)

## 7. 留给实施者定的

- 名单条在手机上最多几个头像(先定 5 个,真机看拥挤程度再调)。
- 右栏 360px 和 1080px 断点是起点,mini 截图后可以微调。
- 名单订阅的节流(建议 1 秒,与 App 主题节流一致)。
