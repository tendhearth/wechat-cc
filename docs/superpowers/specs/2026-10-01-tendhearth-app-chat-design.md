## 0. 这件事是什么(白话)

v1 的手机 app 把「说一句」做成了「交办一件隔离任务」:手机上写「你好」,电脑上起的是一个没有记忆、没有微信历史的 API 沙箱执行者。主人要的是跟 **CC 本人**说话 —— 就是微信里、桌面「跟 CC 说」里那个记得你、读得到你微信历史的 CC。交办任务是聊天之外的一个**明确选择**。

同时,手机上看到的东西要是真的:完整的对话(不是最近 5 条原始事件)、能往上翻的历史、「一起做」里真实最近在动的事(不被归档的自检噪声挤掉),以及一张如实说明「CC 现在连着什么、数据新不新」的卡。

## 1. 已定的决定(主人 2026-09-30)

1. **主动作 = 跟 CC 说话**:走 `companionConverse`(与微信、桌面「跟 CC 说」同一条路,带记忆 / 人设 / wechat MCP / 插件)。「交给 CC 去做一件事」(建工作台任务)降为显式选项。回复**异步**到达:daemon 收下即回(隧道约 15 秒没流量就断),回复经 `matter/<主人聊天>` 主题 + 拉取送到。
2. **主人那条 CC 对话置顶在「一起做」**,有完整对话页、按 `beforeTs` 往上翻页(复用 `messagesStore.listRange`);**微信入站要把聊天 matter 的 `updated_at` 往前推(节流)**,任务 matter 有新事件也推;`/m/api/matters` **默认不含归档**。
3. **进展页显示真实对话**(用户说的、CC 回的、工具步骤),不再只有概括 + 最近 5 条;修好「聊天 matter 进展页骨架屏永远转」。
4. **「CC 的连接」卡**:每个来源(微信历史 / wxvault、知识库、其它插件)是否已加载、数据最新到哪天;落后 ⇒ 琥珀色,没加载 ⇒ 红色;电脑在线;最近在做;成果。数据来自新的 daemon 接口(admin 档 `/v1/connections` + 手机路由 `/m/api/connections`);**admin 以下不给路径与原因原文**。手机先做,桌面卡放下一份计划。
5. **只读看主人已有的 Claude Code / Codex 会话及其历史**(复用 native-history);「接着这个会话做」放下一份计划。
6. **配对三件事**(桌面引导直接给二维码 + 改名「连接手机」;Universal Links / App Links 让系统相机唤起 app;换手机靠 iCloud 钥匙串 / 安卓备份恢复配对)放「Next plan」。

不做:云账号。

## 2. 界面(在 v1 spec §2 上的改动)

- **跟 CC 说(新页 `/chat`)**:顶部 CC 形象 + 「CC」;中间是主人那条对话(微信、桌面、手机三处说的话都在,每条小字标来源:微信 / 电脑 / 手机);往上滑到顶自动加载更早的(每页 30 条);底部输入框 + 发送。发出后立刻出现「我」的气泡,下方 CC 显示「在想…」;回复到了替换掉。没送到 ⇒ 气泡下「没送到 · 重试」(CC 正忙 / 电脑暂时不行两种措辞)。输入框上方一个次级按钮「交给 CC 去做一件事」⇒ 现在的交办页(`/compose`)。
- **此刻 / 一起做的「跟 CC 说一句」**:进 `/chat`(不再进交办页)。
- **一起做**:第一行固定是「和 CC 的对话」(最近一句的预览 + 时间),点进 `/chat`;下面是任务。其他人的微信聊天(访客的 chat matter)不在这里出现 —— 那是 CC 的社交,不是「我们一起做的事」。
- **进展页(任务)**:「CC 的进展」概括之下新增「对话」一节:用户的话(右)、CC 的话(左)、工具步骤(一行小字,可折叠成「做了 N 步」)、出错(一行红字)、系统行不显示。显示该任务最近 50 条事件里的全部对话。聊天 matter 打开 `/matter/<id>` ⇒ 直接换到 `/chat`。
- **CC 的连接(新页 `/connections`,此刻页有一行入口)**:来源一行一个(圆点 + 名称 + 「数据最新到 9 月 8 日」/「已连上」/「没加载」/「不知道」);家里的电脑(在线、开机时间、版本);最近在做(3 件);成果(最近 3 个产物)。颜色:就绪 = 绿,落后 = 琥珀,没加载 = 红,不知道 = 灰;**都配文字**。
- **电脑上的会话(新页 `/sessions`,设置页入口)**:Claude Code / Codex 两个分段,列表(标题、项目名、时间),点进去只读看对话(「继续读取」翻页)。不提供「接着做」。

## 3. 接口(daemon)

| 路由 | 档 | 作用 |
|---|---|---|
| `GET /m/api/matters` | 手机 | 不带 `status` ⇒ 默认 `open,replied,done`;带 `status` 照旧 |
| `GET /m/api/chat?before=&limit=` | 手机 | 主人对话一页:`{matterId,title,messages[],hasMore,pending,failed}` |
| `POST /m/api/chat/say {requestId,text}` | 手机 | 收下即回 `{job}`;后台跑 `companionConverse(text,'phone')` |
| `GET /m/api/connections` | 手机 | 连接卡快照(去掉 `detail`) |
| `GET /v1/connections` | admin | 同一快照,带 `detail`(插件目录、未就绪原因) |
| `GET /m/api/sessions?provider=&cursor=` | 手机 | 原生会话列表(项目只给目录名) |
| `GET /m/api/session?key=&cursor=` | 手机 | 原生会话对话一页(每条截到 4000 字) |

- **说一句的语义**:同一 `requestId` 再发 ⇒ 返回同一份结果,不说第二遍(顺手补上 v1 遗留「聊天说一句不按 requestId 去重」);上一句还在想时发新的 ⇒ 409 `chat_busy`(草稿留着);失败的那句用同一 `requestId` 重发 = 重试。任务表只在内存,daemon 重启即忘(重启中的那句按「没送到」处理)。
- **聊天主题版本** = `max(matter.updatedAt, 该 chat 最新一条消息时间)`,有句子在等回复时 `phase = 'working'`;所以微信那边一来一回、手机这边回复到达,手机都会被唤醒去拉。
- **updated_at 往前推**:微信入站(任何 chat)、工作台任务事件 ⇒ 同一个节流器(每件事至多每 5 秒写一次,保证最后一次落地)。工作台回调里只记一笔、排定时器,不同步写库(第 8 步重入规矩)。
- **连接快照的判定**(真实信号,不编):微信历史 = wxvault 插件是否 enabled+ready(没有 ⇒ 红),解密库最近修改时间超过 24 小时 ⇒ 琥珀;知识库(只在 `knowledge_enabled` 时出现)= 已建 ⇒ 看库里最新一条消息时间,超过 72 小时或为空 ⇒ 琥珀;没建起来 ⇒ 红;其它插件 enabled 且 ready ⇒ 绿,enabled 但没就绪或预期却没找到 ⇒ 红;插件快照还没出来(启动中)⇒ 全部「不知道」。
- **预算**:隧道 15 秒没流量就断 ⇒ 手机上的原生会话读取包 10 秒预算,超了回 503 `unavailable`(手机显示「电脑那边读得慢,再试一次」);对话一页上限 30 条 × 4000 字,不撑爆中继 512 KB 一帧。

## 4. app

- `Backend` 新增 `chat` / `chatSay` / `connections` / `sessions` / `session`,演示后端同样实现(演示里 CC 2 秒后回一句固定的话)。
- 错误映射:`chat_busy` ⇒ `busy`;`no_owner_chat` ⇒ `not_found`(`/chat` 显示「电脑上还没设好主人对话」);`unsupported` ⇒ `not_found`。
- 对话页的数据:最新一页走查询缓存 `chat:latest`,`matter/<聊天>` 主题版本一变就重拉;往上翻的页只在页面内存里;回到前台(epoch 前进)重拉最新一页、保留已翻的旧页。
- 发送:`requestIdFor('chat', body)` 稳定;收下后清草稿;服务端的 `pending` / `failed` 是唯一真相(不做乐观成功,但「我」的气泡以 `pending` 的形式立刻出现,因为它就是服务端回的)。

## 5. 验收

- 根:各新路由的真实返回过 `PHONE_API_SCHEMAS`(`phone-api-schema.test.ts`);`PHONE_ROUTES` 守卫扫到新文件;bun 与 node 两遍。
- app:视图模型单测(对话、置顶、骨架屏修复、连接卡、会话列表)、LiveBackend 单测、演示后端单测、根目录进程内端到端加「说一句 → 主题唤醒 → 拉到回复」。
- Maestro(演示):此刻 →「跟 CC 说一句」→ 发 → 「在想…」→ 回复出现;一起做第一行进 `/chat`;此刻 → 连接卡;设置 → 电脑上的会话。
- 主人真机:手机说「最近我和猪大哥聊了什么」⇒ CC 用 wxvault 回(前提:PR #160 的插件已在真机加载);微信里聊一句 ⇒ 手机对话页一会儿就出现;连接卡上 wxvault 的日期与 `self deploy` 后的健康输出一致。
