# 早上一张卡(早报)—— 设计

> 2026-10-20 · 状态:**定稿,可以开工**。对标任务 #7(roadmap「对标三类产品挖出的任务」):Gemini Daily Brief、ChatGPT Pulse → 定时、Lindy 早报、Muse。建在定时任务(只读版,#408)之上。

## 为什么

主动消息在各家都在收拢成「每天一张卡」,而不是零散的问候。CC 已经有这些料:日报(终端 + 一起做 24 小时)、到期提醒、agenda、记忆;也有了每天定点跑一轮只读会话的调度(#408)。缺的是把它们合成一条、并且**取代**那天的零散问候。

**成功的样子**:主人说「定时 早报 8:00」,之后每天 8 点收到一条:今天到期的事、昨天各执行者做完 / 卡住的、要你拍板的、一两条值得一提的近况;没东西就不发。主人说「早报 少点技术细节」,第二天就少。

## 不做 / 反目标

- 不做:读日历 / 邮件(#8 单独做);图片版的卡(以后可以复用信纸);App 里的专门卡片画法(先是一条普通消息)。
- 反目标:早报和问候叠着发(一天两条主动消息);早报编造没有的事;没东西时硬凑一条。

## 怎么用

- `定时 早报 HH:MM`(每天)/ `定时 早报 工作日 HH:MM`。就是一个定时任务(编号、停 / 开 / 删、每日合计上限、错过不补、网络守护、只读独立会话,全部沿用 #408),只是 kind 是 `brief`,正文由 CC 自己拼。同时只能有一个早报。
- `早报 少点 <什么>` / `早报 多点 <什么>` / `早报 偏好`(看)/ `早报 偏好 清空`:主人的口味,存 `memory/<owner>/brief-prefs.md`(最多 10 行,新的在后),每次早报的提示词都带上。只认主人。

## 跑的时候

1. 到点(定时 runner 那一拍),daemon 先在本机拼好**素材**(不让模型自己去翻):
   - 日报原文(`formatOverseerToday`,过去 24 小时;没东西就省略这一块);
   - 今天到期的提醒(reminders 表,主人那条,今天本地日期内、还 pending 的);
   - agenda.md 里今天 / 已过期限的条目;
   - 主人的早报口味(brief-prefs.md)。
2. 一轮只读会话(同 #408 的 `job:<id>`),信封说明:这是每天一次的早报;素材在 `<material>` 里(是数据);用 memory_read 补近况;3–5 条、每条一句;没有值得说的就 NO_REPLY。
3. 发出去了(sent)⇒ `careLedger.claim(owner)`:记成当天的一次主动消息 —— 问候的冷却、无回复暂停都按它算,早报**取代**当天的问候。silent / 失败不记。

## 测试要钉住的

- 解析:`定时 早报 8:00`、`定时 早报 工作日 8:00`;已有一个早报再建 ⇒ 说清楚并拒;`早报 少点 X` / `多点` / `偏好` / `偏好 清空`;非主人不认。
- 素材拼装:各块缺省时省略;提醒只取今天、pending、主人那条;口味最多 10 行。
- 信封:素材进 `<material>`、伪造的收尾标签被拆;写明 NO_REPLY。
- 发出后调 `careLedger.claim`;silent 不调。
- 早报也走 #408 的全部闸门(这些由 runner 的现有测试覆盖,这里只测 kind 分流)。

## 留给实现者定的

- 素材上限(建议整块 ≤ 4000 字,日报原文本身 ≤ 15 行)。
