# CC 桌宠的陪伴感与轻交互

2026-11-01。设计提案，尚未实施。主人提出参考其他桌宠的感觉，Codex 桌宠也可以；本稿据此给出具体取舍，不再要求主人先定义每个互动细节。研究以官方说明和本机应用静态资源为依据，没有安装体验竞品、操作主机界面或接管鼠标。

## 目的

CC 平时安静陪着，用户靠近时有回应，需要交办或决定时能顺手接上。成功标准是长时间放在桌面上仍舒服，动作含义清楚，操作方便。

沿用 Tendhearth 家族规范：CC 是 C 形发光小团；Light / Dark 表达真实连接。保持已经确定的角色、材质和两态关系。角色动作不改变任务事实，不靠用户离开、喂养、打卡或连续互动制造压力。

## 技术路线

选择现有 Tauri 窗口、精灵素材和真实状态桥，增加局部交互与动作编排。已有的眨眼、呼吸、张望、拖动、位置记忆、安静控制、权限卡和道具组合继续作为基础，不重复列成新增能力。

另外考虑了分层网格动画和实时 3D：前者需要准备新的可独立变形素材；后者需要验证实时材质、形态一致性和常驻资源消耗。当前改善陪伴感的目标可以先在现有系统内验证；需要连续转身或独立身体形变时，再制作独立样片比较。

源码基线参考已知集成提交 `3fba7813`，不能把当前研究工作区的较早代码当作最新产品。任何实现应重新确认最新 dev，在独立功能工作区进行。

## 第一版的具体体验

1. **平时。** 角色是视觉主角。将现在常显的工具排收起，在指针靠近、键盘聚焦或菜单展开时显示；键盘操作与触摸环境仍有可发现入口。已有权限与故障内容不随工具排一起隐藏。
2. **靠近。** 用一次克制的回应表示注意到了用户。保持角色轮廓和脚底稳定；移开后回到原来的真实状态。加冷却，避免反复进出导致不停招呼。安静、减少动态和隐藏时不触发、不积攒补播。
3. **点一下。** 单击角色打开现有 CC 对话/交办入口；拖动超过现有判定阈值后只移动位置，松手不误触打开。交互反馈不能把假任务或假完成写进状态机。
4. **做事。** 在同一个真实状态之下安排进入、维持和收尾的节奏，避免同一组明显动作不断重启。事实状态与装饰姿态分开；权限优先，工作状态切换及时。没有新的事实时，以当前可靠姿态安静维持。
5. **等你。** 多件事同时存在时，首先呈现需要用户决定的事，其次故障、未读回复和工作状态。每次只突出一个入口，点开进入同一个 CC；已有权限卡仍使用原来的批准与拒绝机制。

第一版先用已有可用姿态验证时机与节奏。拖动的身体受力、连续眼神与回弹需要新素材或新的局部动画能力，列为后续样片，不承诺当前 PNG 能直接产生这些效果。Light / Dark 不随指针、情绪或任务忙闲改变。

## 桌面融入的独立验收项

透明部分能点到下方应用，是单独的原生交互目标。现有全窗口矩形接收输入；PNG 的美术 mask 与 CSS 的 pointer-events 都不能单独证明跨应用点击穿透。实现前先在 Mini 的两个隔离窗口中验证命中、穿透后重新进入、拖动、焦点、工具排及权限卡，确认可用后才纳入生产。

靠近反馈与透明穿透有依赖：进入透明区域时不应出现不可退出的穿透状态，也不应为了恢复入口而持续抢焦点。若原生方案还不可靠，先交付可点击入口和工具排收起，穿透不以浏览器测试冒充原生通过。

## 验证与边界

所有交互、渲染与原生验证继续在 Mac mini 使用隔离状态和测试事件完成。主机不运行 GUI 自动化、不移动鼠标、不抢焦点。研究没有变更日常 CC，也不需要给 Mini 接真实账号或外网任务。

实现阶段检查：单击与拖动互斥；首击可用；靠近冷却；实际任务与权限优先；安静/减动/隐藏恢复不补演；两态一致；48–256px 可辨认；键盘可达；跨应用穿透的原生证据。性能以改动前后 Mini 同条件测量，先比较空闲和活跃资源占用，再决定局部动画方案。

本稿的范围是交互取舍。代码提交、Mini 验证、合入 dev 和日常部署均应各有实际证据，不能用设计完成代替实施完成。
