# 工作中的来回沟通

用户于 2026-09-13 批准继续：运行中补充、执行者提问、离页待处理提醒。沿用两栏工作台，不改变原生权限和冻结资产。

## 交互

- Codex 支持原生运行中补充时，将文字交给当前 turn，收到原生确认后标为已交付；不暗中新开会话。
- Claude 的流式输入缺少足够稳定的结果归属凭证。本轮采用服务端持久化的下一轮队列，明确写“加入下一轮”。只有本轮正常结束、同会话可恢复时才执行。停止、失败、服务重启后保留为未发送，绝不偷偷恢复。
- 提问和权限分开。提问支持选项和自由填写，明确提交后答复原请求；关闭/取消后旧回答不作用于后续任务。秘密输入暂不接入普通对话记录。
- 提问能力以原生执行器实际发出的请求为准。本机 Claude 的 AskUserQuestion 已经真实往返验证；Codex 的请求桥接有协议测试，但本机默认执行模式的模型未发出结构化提问，不能据此宣称两者能力相同，也不为触发问题而改变执行模式。
- 待处理事项在应用所有页面保持一个简短入口，系统通知仅在新增问题/权限且用户不在当前任务时发一次。通知不含命令、问题内容或文件路径。打开后回到确切任务；没有待处理事项时不占空间。

## 接口与可靠性

公共 provider 契约新增可选 steer(text) 与 requestUserInput 回调；不改变旧调用者。任务详情公开当前 runId、inputMode、questions、补充交付记录。输入携带客户端唯一 ID 和 runId，重试不得重复执行；回答绑定任务和随机请求 ID。原生接收不确定时保留未确认状态，不自动重试。

补充存 SQLite；提问的活动回调仅属于当前 run，其发起/回答/结束有事件记录。全局 attention 读取活动请求，不受任务列表分页影响。任务停止和完成都关闭对应待答回调。所有 API 继续只经本机管理权限代理，新增确切方法/路径白名单。

等待用户回答不计为执行闲置。回答提交后重新开始执行等待预算；停止仍然随时生效。待发补充在自动接续前重新确认原项目目录身份和原生会话，无法确认则保留为未发送。

## 验收

并行任务不串补充/回答/提醒；重复与过期提交不重复投递；取消/重启不自动发送；Claude 排队后保留原会话；Codex 原生拒绝不能显示已交付；问题可用键盘完整回答；刷新不丢未回答内容；离页通知去重且点回正确任务。验证原生协议、服务生命周期、接口、UI 和全仓类型检查，另作浏览器证据。
