## 为什么

## 记录本

一件事一本,三类内容,全是短句:

| 内容 | 谁写 | 例子 |
|---|---|---|
| 目标与分工 | CC 建事时写 | 谁做哪一棒、先后顺序 |
| 交接备注 | agent 做完或中途写 | 「图在 assets/login/,-dark 是深色版」 |
| 产出指针 | daemon 自动记 | 改了哪些文件、提交号、工作区路径 |

- **进**:CC 派下一棒时,把记录本(不是前一个 agent 的全部对话)放进它的开场。记录本有长度上限,超了由 CC 压成摘要,原文留着可查。
- **读**:agent 干活中途可以用工具查这件事的记录本(只读自己所在的这件事)。
- **写**:agent 用工具写一条交接备注;做完时若没写,CC 从它的最终回复里抽一条。
- **权限**:沿用 #907 的来源授权——记录本属于工作来源,只有主人自己的对话和本机能读;agent 只能读写自己被派到的那件事,读不到别的事、读不到主人的聊天。

记录本做完后照旧进话题记忆(现有的工作结果 → 话题那条路),所以以后主人聊到「登录页」,CC 能说出是谁做的、图在哪。

## 接力

- 顺序由主人那句话定;CC 拆成几棒,**开工前把拆法回给主人看一眼**(一条消息,回「好」或改)。
- 一棒做完 → CC 自动派下一棒,不再问。失败或 agent 提问 → 停在那一棒等主人,后面的不动。
- 可以并行(「Codex 和 Claude 各出一版」),并行的各用独立工作区(现有能力),记录本共用。
- 主人随时可以插话:对着这件事说的话记进记录本,当前和后面的 agent 都看得到。

## 不做

- 不做 agent 群聊 / agent 互相 @。
- 不让 agent 自己决定叫谁来帮忙(调度只在 CC)。这一条以后可以放开,先不放。
- 不改话题的组织方式(「话题=项目」先不动,等这一步跑起来再看)。
- 不加新页面;详情页多一列 agent 和一段记录。

## 分步

1. **记录本**:表 + 读写工具 + 派活时注入 + 详情页显示。先只支持顺序接力,手动(主人说「让 Claude 接着做」)。
2. **自动接力**:CC 拆棒、回给主人确认、做完自动派下一棒、失败即停。
3. **终端会话也能挂进来**:主人自己开的 Claude Code / Codex 会话,认得出属于哪件事时,读得到那件事的记录本(现在只带项目摘要)。
4. **并行**:多个 agent 同时各做一版,记录本共用。

每步都是「主 Mac 离线测试 + mini lab 真流程验收」后才交给主人试。
