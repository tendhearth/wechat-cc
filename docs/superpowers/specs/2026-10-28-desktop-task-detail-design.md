# 任务详情极简层级

用户于 2026-10-28 确认两端采用相同逻辑，并在明确任务详情尚未完整收口后要求“继续做”。本轮落实已经说明的方向，不重新选择风格：运行中看进展与补充，需要回应时看具体请求，答复后看成果并能继续。沿用既定暖纸、衬线、深绿和宽屏工作布局。

## 状态与层级

- 头部以任务标题为主，一行真实状态为辅。执行者完整信息、来源、路径、模型、分支及管理操作移入已有任务详情；不重复罗列元信息。
- 运行中：对话与实时过程仍是主体，补充输入是主要动作；不生成假摘要或百分比。沿用 runId/inputMode 对当前轮、同会话、下一轮及只保存的权威区分。
- 待回应：当前任务的权限原始操作、cwd／范围和问题正文保持直接可见，决定动作先于补充区；图标不能代替实际请求或风险说明。
- 已答复／已完成：有实际保存的交付物时，将成果列表提升到更靠前的位置，默认可发现；保留继续修改。仅含变更快照的任务仍先看改动，不把审阅记录冒充新交付物。没有文件时，真实答复仍是内容主体。
- 已停止、未完成、中断、归档、等待及未知各自表达。旧成果存在不等于本轮完成；importedOnly 不冒充执行过。
- 网络冻结、陈旧数据、额度失败、排队阻塞、执行程序未退出、后台仍在写、免审限制及脚本运行／失败／需批准等必要提示继续可见；次级信息收起不隐藏这些事实。

## 输入与审阅

输入与主要动作更克制，熟悉动作可用现有图标并有完整标签／悬停提示。常规投递说明可放按需展开的帮助；仅保存不自动发送、结束会停止后台工作、恢复方式／将带记录、失败与未知结果必须保留明确表达。

改动摘要只呈现短标题及必要数量；轮次、文件数和接受／打回统计移入展开内容。预览限量、部分／不可用、未审文件、来源及截断提示不能为了简洁而消失。保留接受、退回、项目经验、行评论、汇总、撤回与恢复功能。

## 保持行为

不改协议、状态机或轮询，不自动生成说明，不自动打开 iframe／PDF 或抢焦点。保留已有动作／字段／稳定披露 ID、请求作用域、选中成果、预览实例、阅读锚点、滚动、输入及审阅草稿、任务切换和提交锁。新增帮助披露需进入按任务保存机制。用户手动收起的成果状态应被尊重，完成态首次默认展开不覆盖此选择。

## 验收
