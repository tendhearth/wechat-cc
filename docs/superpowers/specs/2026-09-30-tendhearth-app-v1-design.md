## 0. 这件事是什么(白话)

用户电脑上住着 CC(Tendhearth 桌面端)。手机 app 让人出门在外也能「回到自己的炉火边」:看 CC 现在在忙什么、需要你决定的事一眼可见、点开看清楚再允许或拒绝、说一句话把新事交给 CC。app 本身不带 AI,所有事都在用户自己的电脑上发生;手机经官方中继端到端加密连回去。

## 1. 已定的决定

- **品牌**:对外名 **Tendhearth**;角色 **CC**(「动物管理员」,守着炉火 = 用户的电脑;不是动物)。工作室 Nate Gu & Co.,旗下动物 app(melu 狐狸)同一家族风格。bundle id `com.tendhearth.app`(iOS 与安卓相同)。商店名「Tendhearth · CC」一类。桌面端与仓库只在以后改表层名,不改 bundle id / 二进制名。
- **v1 范围 B「一起做」为主**:事项与任务、批准与回答、跟 CC 说话、交办新事、精简「此刻」、推送。**不做**:回忆浏览编辑、目标、点子、灵动岛 / 锁屏实时活动 / 小组件(子项目 4)。
- **语言**:英文 + 简体中文,跟随系统。**地区**:全部,不含中国大陆(大陆要 ICP 备案)。
- **通知批准**:点通知 ⇒ 打开那张批准卡片,看清全部上下文再「允许 / 先不做」。**通知本身从不执行任何操作**。锁屏一键批准留给子项目 4。
- **技术**:Expo(React Native、TypeScript、Expo Router),同仓库 `apps/app`;加密、协议、接口类型全部来自 `@wechat-cc/protocol`。原生代码只有 iOS 通知解密扩展(Swift)与安卓消息服务(Kotlin)。
- **前提**:app 不能单独用,必须配对一台装了桌面端的电脑;为审核提供演示模式。

## 2. 界面(以 Codex 稿为准)

- **导航**:底部固定两个标签「此刻 / 一起做」;设置从右上角头像进入;右上角同时显示「家里的电脑」在线状态点。输入入口随处可见,进入某件事后变为「接着跟 CC 说一句」。
- **01 此刻**:问候 + 一句概括 →「需要你决定」卡片(总在最上面)→ CC 一两句近况(带 CC 形象)→「一起做的事」简表 → 「跟 CC 说一句」。
- **02 交办**:自然语言输入、加图片、默认沿用合理上下文(项目、执行者,可展开调整)、保留草稿、「交给 CC」。
- **03 进展(单件事)**:标题 + 状态标签 → 「CC 的进展」概括 → 已发生的步骤 → 待决定的那一步入口 → 可展开的「查看改动 · N 个文件」与「过程与执行信息」→ 接着说一句。
- **04 批准**:「CC 想和你确认」→ 大标题(一句问句)→ 要做的事 / 作用范围 / 这一步会发生什么 → 可展开「查看具体操作」(原始命令)→「先不做 / 允许这一步」,注明「只针对这一次请求」。
- **状态词**:正在整理 / 等你决定 / 这一轮已回复 / 事情完成(失败另有措辞)。不显示虚构百分比;「本轮答完」不等于整件事完成。
- **视觉**:沿用桌面配色(浅:底 `#faf8f3`、卡片 `#fffdf9`、正文 `#493e32`、辅助 `#796f63`、边线 `#e4ddd2`、主按钮 `#58654c`、导航选中 `#f7ead2` / `#674c2d`;深:底 `#221f1b`、卡片 `#2c2823`、文字 `#f1e9dc`)。明暗只是外观,不表示在线离线。CC 直接复用已验收的 `apps/desktop/src/assets/pet/cc-v1/canonical/{lit,unlit}/front.png`,不重画。
- **可访问性**:所有状态都有文字;系统「减少动态效果」时关掉 CC 动作;失败与离线不用责备或失落表情。
- **Codex 待补的稿**(v1 必须有):首次打开(配对 / 先看看演示)、扫码与配对结果、设备管理与撤销、空状态、同一件事多条待批准时的选择页、各类通知长相、电脑离线 / 设备被撤销两种提示、设置页(语言、通知、关于、隐私)。

## 3. 状态约定(来自设计说明,工程上的做法)

| 情形 | 做法 |
|---|---|
| 电脑离线 | 显示上次同步的内容与时间;可写草稿;发送 / 批准 / 拒绝不可提交;重连后重拉状态,草稿不自动发 |
| 另一端已处理 | 保留上下文,显示「已处理」,去掉提交按钮,提供返回事项 |
| 重复点击 | 提交中锁定;以服务端返回为准,不做客户端乐观成功 |
| 旧通知 | 先定位事项、拉最新详情,再展示;请求已不在 ⇒ 显示已处理或事项最新状态 |
| 同一件事多条请求 | 展示待处理列表让用户选;通知里带请求 id 时直接定位(§5.4) |
| 设备被撤销 / 配对失效 | 停止提交、清掉本地设备令牌与推送密钥、提示重新配对;与「暂时离线」分开表达 |
| 通知解密失败 / 超时 | 显示中性提示「CC 有新动态」,点开后同步 |

## 4. app 架构(`apps/app`)

- **工程**:Expo SDK(最新稳定版)+ Expo Router(文件路由)+ TypeScript strict。EAS Build 云构建;开发用 development build(需要原生扩展,不用 Expo Go)。
- **协议层**:`@wechat-cc/protocol` 的 `makeProtocolClient`(v2:订阅、请求、重连、错误码)。React Native 适配:WebSocket → `ProtocolSocket`;随机数用 `expo-crypto` 的 `getRandomValues` 装到 `globalThis.crypto`;`TextEncoder/Decoder` 在 Hermes 可用性要验证,缺就补 polyfill。接口返回一律用 `PHONE_API_SCHEMAS` 的 zod schema 解析,类型用 `z.infer`。
- **数据流**:订阅 `home` / `approvals` / `agents` / `matter/<id>` 拿摘要与版本号;版本变了再 `req` 拉详情(与子项目 1 的约定一致)。本地用一个轻量查询缓存(按路由键存最近结果与同步时间),离线时展示它。
- **身份与存储**:配对后拿到长期设备令牌;令牌与派生出的推送密钥存 `expo-secure-store`(iOS 钥匙串,access group 与通知扩展共享;安卓 EncryptedSharedPreferences / Keystore,与消息服务共享)。撤销 ⇒ 清掉两者。
- **中继地址**:配对时从二维码链接得到 daemon id 与中继主机;`r…` id 走 `/v2/phone`,`t…` 走老 `/tunnel/phone`(与壳页同一规则)。在家同一 Wi-Fi 时可优先直连局域网(链接里有 `lan=`),连不上再走中继。
- **国际化**:文案表 `en` / `zh-Hans`,跟随系统;所有面向用户的字符串都进文案表,测试检查两份键一致。
- **目录**(拟):`app/`(路由:`(tabs)/now`、`(tabs)/together`、`matter/[id]`、`approval/[matterId]`、`compose`、`pair`、`settings`)、`src/net`(协议适配、连接状态)、`src/data`(查询缓存、订阅)、`src/demo`(演示数据与假后端)、`src/push`(注册、点通知路由)、`src/ui`(设计 token、组件、CC 形象)、`src/i18n`、`native/ios-notify`(Swift 扩展)、`native/android-push`(Kotlin 服务),通过 config plugin 接进构建。

## 5. 后端要补的(本子项目一起做)

1. **批准说明**(`explain`):权限请求今天只有原始 `tool + description`。daemon 用便宜模型把它翻成三行白话:要做的事 / 作用范围 / 这一步会发生什么,外加一句问句标题;按「任务 id + 请求 id」缓存;便宜模型不可用或超时 ⇒ 回退成原始文本(标题 = 工具名,三行 = 命令 / 工作目录 / 原始描述)。原始命令永远一键可见。随 `GET /m/api/matter` 的待批准项一起返回(新增可选字段),schema 同步。
2. **进展概括与步骤**:同样由便宜模型从事件流生成「CC 的进展」一两句 + 至多 6 条已发生步骤(每条一行标题 + 一行说明),按任务的 `version` 缓存,版本变了才重算,限频(同一任务至多每 30 秒一次);失败回退为最近几条事件的原文摘要。新增可选字段,schema 同步。
3. **手机端改动查看**:新增只读路由(拟 `GET /m/api/matter/changes?id=…`)返回该任务最近一轮改动的文件列表与每个文件的 diff(单文件与总量都有上限,超了只给摘要);登记 `PHONE_ROUTES` 与 schema。复用桌面「改动」面板的现有数据源。
4. **推送载荷定位到具体请求**:`PushPayload` 增加可选 `requestId`(待批准 / 待回答的那一条的 id);`phone-notifier` 填上;app 点通知时优先用它定位。
5. **推送的时间窗**:`openPush` 目前只接受前后 10 分钟,而 APNs / FCM 的 TTL 是 1 小时 ⇒ 迟到的通知解不开。改为:过去方向放宽到 1 小时、未来方向保持 10 分钟;每台设备记住最近见过的推送(`ts + 密文哈希`)去重。通知只显示、不执行,放宽不引入权限风险。协议包与原生两端用同一份测试向量验证。
6. **子项目 1 的遗留(app 上线前必须修)**:`auth_failed` 通知订阅者;每流队列与订阅数有上限;永不返回的来源不卡住主题。

## 6. 配对

- 用户在桌面端「手机上用」打开二维码(现有 `GET /v1/settings/link` 生成的 `https://<中继>/pset/#id=…&t=…&p=/set&lan=…` 链接)。
- app 扫码 ⇒ 解析 `id`、`t`(一次性链接令牌,10 分钟)、中继主机、`lan` ⇒ 用链接令牌建 v2 连接 ⇒ `POST /set/api/pair` 拿长期设备令牌 ⇒ 存安全存储 ⇒ 换成设备令牌重连 ⇒ 请求通知权限 ⇒ `POST /m/api/push/register`。
- 同一个二维码在没装 app 的手机上仍是网页入口(系统相机扫到的是 https 链接)。以后可加 Universal Link / App Link 让相机直接唤起 app,不在 v1。
- 设备管理:列出本机与其它已配对设备、给本机改名、在设置里「解除配对」(本机清除;撤销别的设备只能在家,沿用 `LAN_ONLY_OPS` 规则,v1 在手机上只显示提示)。

## 7. 通知

- **iOS**:APNs alert 推送,占位文字「CC 有新动态」,`mutable-content: 1`,密文在 `wcc`。通知服务扩展(Swift)从共享钥匙串取推送密钥,用与 `openPush` 相同的算法解密(HKDF-SHA256 + AES-256-GCM,CryptoKit),换成真实标题与正文;按 `kind` 设 category(批准类、问题类、完成、失败)。解不开 / 超时 ⇒ 保留占位文字。
- **安卓**:FCM data message(HIGH priority),Kotlin `FirebaseMessagingService` 解密后自己发本地通知;渠道按类别分(需要你决定 / 完成与失败)。
- **点通知**:按 `taskId` + `requestId` 路由到批准页或事项页;先拉最新详情再展示(§3)。
- **token 生命周期**:首次授权、拒绝授权(设置里给出去系统设置的入口)、token 刷新、重装后重新登记。
- **正在用 app 时**:app 在前台且订阅在线 ⇒ daemon 本来就不推(子项目 2 的规则);app 内用自己的横幅。

## 8. 演示模式

- 首次打开页提供「先看看」:加载内置的演示场景(Codex 稿里的「整理作品集手机首页」),不联网,全部页面可走一遍(此刻、进展、批准、交办、设置),批准与交办会给出模拟结果。
- 实现为 `src/demo` 的假后端,实现与真连接相同的数据接口 —— 界面代码不分支。设置里可随时退出演示去配对。
- 商店审核说明里写明演示入口;截图也从演示模式生成。

## 9. 测试与验收

1. **单元**:协议适配(RN 的 WebSocket 与随机数)、查询缓存与订阅、点通知路由、状态约定表里的每一行、文案两种语言键一致。
2. **后端**:批准说明与进展概括(便宜模型用假实现,覆盖回退与缓存)、改动路由(上限、鉴权、schema)、推送载荷 `requestId`、放宽后的时间窗与去重。
3. **原生解密**:Swift 与 Kotlin 各自跑 `packages/protocol` 的推送测试向量(正常、错密钥、篡改、过期、未来时间、重复)。
4. **界面**:演示模式下的端到端流程测试(模拟器,用 Maestro:Expo 官方文档推荐、YAML 流程好维护),截图对照 Codex 稿。
5. **真机验收**(主人参与):配对 → 此刻 → 交办一件事 → 电脑上执行 → 需要批准时手机收到通知(前台 / 后台 / 进程被杀三种)→ 点开批准 → 电脑继续;离线与撤销两种提示;iOS 与安卓各一遍。
6. **CI**:`apps/app` 的类型检查与单元测试进 CI;原生构建走 EAS,不进每次 CI。

**算做完**:两平台真机验收通过;TestFlight 与 Google Play 内部测试各发一版;演示模式可供审核;全量测试、类型检查、depcheck、CI 绿。正式提交商店审核由主人决定时间。
