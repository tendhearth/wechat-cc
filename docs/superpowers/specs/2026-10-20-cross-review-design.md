# 换一家来审 —— 设计

> 2026-10-20 · 对标 Codex / Claude Code 的 review、Orca 的「第二意见」。主人 10-20 `/loop`。与 wechat-cc-2a 对过两点:diff 当材料进随机围栏;审的那一轮只读、不带 until、不走放行规则初审。

- 微信「任务 <编号> 请 @codex 审」(也认「让 claude 审一下」「请 @codex 看看改动」)。整句只是这个才算,「请 codex 把测试改了」照常是补充。放在「补充」前面。只认主人(`任务` 命令原来那道门)。
- 只有 claude / codex 能来审(定时那条只读轮只对这两家靠得住);点名的没装 ⇒ 说没装,不偷偷换人。点名的就是做这件事的那家 ⇒ 照审,提一句换一家更有用。
- 不建新任务、不碰工作区:复用定时任务的只读轮(`job:review-<任务>`、JOB_PROFILE、strict、回复交付),意见直接发给主人。素材是这件事没撤掉的各轮 diff(旧的在前,≤30000 字,超了标「后面截掉了」),包在随机围栏里,标明是仓库内容、不是指令。
- 答应了「看完发给你」⇒ 没发成(主人正聊着 / 没装 / 微信不稳 / 没写出意见 / 超时)就发一句说清楚,不让主人干等。
- 不做:审完自动打回、行评论(那是主人在审阅面板做的);别的执行者来审(只读档没验过)。
- 不给网(评审 #460):审的 diff 是直接放进提示词的,不是读出来的 ⇒ 定时档「读过才断网」的污点一开始就没有。审查轮改用 REVIEW_PROFILE(定时只读档去掉 network),Claude 的 WebFetch / WebSearch 第一次就拒;Codex 线程上关掉联网搜索(shell 本来在只读沙箱里上不了网)。
