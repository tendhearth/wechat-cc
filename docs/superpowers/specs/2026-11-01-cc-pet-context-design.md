## 交互契约

1. **角色激活。** 鼠标仍按现有3点阈值与明确释放判定；虚拟 `click(detail=0)` 与 Enter/Space 也能打开。一次真实点击只打开一次；拖动后浏览器 click、取消、丢失抬起不打开。不使用 isTrusted 作为辅助技术门槛。
2. **靠近。** pointer 与键盘聚焦各自维持注意力；最后一个注意来源离开时，只结束这次局部招呼，不终止别的 look、转场、权限或新任务状态。保持12秒成功冷却，无补播，安静/减动/隐藏约束保留。
3. **工具排。** 悬停、键盘可见焦点、设置展开时显示。鼠标操作后移开可收起，不强行清除键盘焦点；触摸环境仍可发现。Escape 优先收起活动列表/设置，再保留既有关闭行为。
4. **活动。** 角色下方有一条有真实标题、状态和必要请求摘要的主要入口；多条时提供紧凑列表，最多8条。权限卡继续独立工作，主人聊天待批优先，不让新列表遮住它。
5. **点击只定位。** 任务目标跳到该 task/matter 同 ID 的既有工作台详情，即使目标不在当前分页。不会发消息、批准、恢复执行、丢弃草稿、自动标记全局已读。不存在的目标显示已有错误，不跳最近任务。

## 事实来源与边界

在既有 workbench view 增加窄只读投影，使用服务的可信 `ownerChatId()`。复用 store.listOwned(owner,20) 的 owner先过滤和未归档约束，补入全部属于主人的活跃 run，避免旧待决被近期记录挤走；最后排序、截断8条。缺少可信主人时为空，不读取陌生人的标题/提示。

每条为 `{taskId,title,phase,detail,updatedAt}`，taskId只接受8位小写十六进制，标题单行最多80字符，请求摘要最多120字符。phase来自真实运行状态：needs_input、failed、interrupted、paused、replied、working、queued、stopping。待批/提问优先；故障/中断/网络暂停随后；最近10分钟答复随后；进行中与排队随后。取消、归档不出现，超过10分钟的答复不持续占用桌宠。replied只表示已答复，绝不称未读。现有 journal 未读与明暗仍来自原来的事实。

投影不调用 detail()、git、脚本探测、不 touch 或创建 matter、不记录阅读/批准。task与matter同ID，但不把任意chat/companion matter当task。

扩展现有 `/v1/companion/pet` 为可选 `activities`；旧 payload、旧客户端仍可用。沿用2/10秒轮询。新的活动驱动文字、目标和相应的持续姿态（等决定/工作/安静维持），不伪造完成、收到或错误一次性事件，不改变 Light/Dark。主人聊天权限、连接提示优先。
