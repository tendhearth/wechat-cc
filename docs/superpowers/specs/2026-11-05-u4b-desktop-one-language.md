# U4b:桌面「此刻」与「全部」一套语言(2026-11-05)

> 起因(主人 11-04):「现在一起做 此刻,有点割裂,两个有点像,但又有不同,感觉不是同一套产品语言和设计」。
> 方向早已定(11-01「合成一个,不看草图,直接做」,[设计稿 §4 U](2026-10-31-one-companion-one-skeleton-design.md) §4 U);#777 只把「一起做」从主导航拿掉,点进去还是旧页面。本稿是 U4 的收尾。

## 1. 对照(改之前,dev `23bfd08c`)

| 方面 | 此刻(`now-*`,`cc-now.css`) | 点行 /「全部 →」进去的页(`wb-*`,`styles/workbench.css`) |
|---|---|---|
| 页头 | 问候 + CC,没有页名 | 侧栏顶上 `<h2>一起做</h2>`,500 字重 |
| 列表底色 | 暖纸 `--th-paper` | 侧栏 `--th-rail`,像第二条导航 |
| 行 | `now-row`:16px 状态记号 · 标题(18px)+ 一行小字(14px)· 头像;悬停标题变强调色 | `wb-task`:标题 14px 两行 + 11px 小字,头像挤在小字行尾;悬停整块变底色 |
| 状态 | 状态表的图标(`square-lock-01` / `checkmark-circle-02` …),墨灰,只有等你是强调色 | 词前一个 6px 彩色圆点(绿 / 琥珀 / 红),等你是琥珀点 + 数字「3」 |
| 状态词 | `STATUS_WORDS`(在做 / 这一轮做完了 / 完成 / 没做成 / 停下了) | 大部分已接表(#777),但仍是圆点那一套 |
| 分组标题 | `.now-group h2`:14px、500、墨灰、字距 0.04em,「等你 / 在做 / 带回来的」 | 「等你处理」14px 墨色;项目名 13px |
| 按钮 | 细线胶囊(`--th-radius-control`),次要按钮透明底 | `.wb-btn` 7px 圆角方块、12px;「交办」是实心强调色胶囊 |
| 字号 | 全走 token(item 18 / meta 14 / small 13 / caption 12) | 大量 10–12px 字面量 |
| 标题字重 | 400 | 详情标题、欢迎页标题 500,欢迎页还收紧字距 |
| 空 / 错 | 灰字说不知道,不用红 | `.wb-error` 整段红字 |
| 「一起做」字样 | — | 侧栏标题、出错页眉题、项目对话框「可在一起做中检查」、三条系统通知「一起做有回复了 / 有任务停下了 / 需要你回应」、此刻「一起做那边暂时读不到」、开发模式横条 |
| 页眉题(kicker) | 无 | 12px「一起做」「新对话」「交办一件事」 |

字体两边本来就一样(`--sans` → `--th-font-sans`),不在差异里。

## 2. 定下的终态(本 PR 做到的)

- **一个状态映射**:`modules/matter-status.js`(`taskStatusKey` / `workbenchTaskStatusKey` / `statusGlyphHtml`),此刻的行、「全部」的行、详情标题下都用它;图标与色调照协议包状态表,不再有彩色圆点(`design-style.test.ts` 守着)。
- **一种行**:「全部」的行就是 `now-row`(状态记号 · 标题 + 一行小字 · 头像),小字 = 状态词 · 项目 · 独立分支;等你写「等你决定」(多项加「共 N 项」)。选中 = 浅底细线,悬停 = 标题变强调色,和此刻一致。
- **「全部」的列**:暖纸底(不再是导航色)、标题「全部」400 字重、「＋ 交办」是细线次要按钮;分组标题与此刻同一个样式,等你那组叫「等你」(`HOME_GROUP_WORDS`)。
- **详情**:项目行与分组标题同样式;标题 400;状态 = 同一个记号 + 同一个词。按钮统一成细线胶囊(`.wb-btn`,此刻的拍板小窗本来就用它)。
- **文案**:界面上不再出现「一起做」(`one-language.guard.test.ts` 按行扫):通知改成「有一件事回复了 /N 件事回复了 / 有一件事停下了 / 有一件事等你决定」,正文去掉「待处理」(用词表不用它);此刻「其余的暂时读不到」;欢迎页「希望 CC 帮你做什么？」,项目里新开叫「新的一件事」。
- **深度区**:改动(diff 审阅、回到某一轮、行评论)、成果、交接、操作记录本来就在详情里、本来就是折叠段;这次只换皮,不搬家、不删。

## 3. 这次没统一的(有意留下)

| 项 | 为什么 | 下一步 |
|---|---|---|
| 窄屏「推入」(≤600px 只显示列表或详情之一) | 今天 ≤600px 是列表横条 + 详情同屏;`task-detail-minimal` / `reading-*` 在 390 宽下都是开着详情再点列表。改交互要在 mini 上跑过这几条,本机不能跑 | 单独一个 PR,跟着改这几条 spec |
| 「任务详情」浮层的位置(App 把执行者 / 路径 / 工作区放在「过程」折叠段) | 搬到正文里会改归档、复制微信命令、工作区按钮的找法(`workbench-worktree-fork` 等点 `#wb-task-info>summary`);这是看得见的找法变化 | **要主人点头**:要不要按 App 的顺序放进正文底部 |
| 操作记录、diff 里的小字号(10–11px)和状态圆点 | 深度区是工具,密度是功能;改字号会撑开 diff | 不动 |
| `.wb-error` 左边那道红线 | 唯一的状态色只留在线上(同「状态色只在点上」),字改成墨色 | 不动 |
| 拍板小窗(权限 / 终端)的样式 | 两页本来共用 `wb-history-dialog` 一套 | 已一致 |

本 PR 不删任何能力:搜索、已归档、按项目折叠、导入已有会话、添加项目、加载更早的、项目里交办、详情里的全部按钮都还在原处。
