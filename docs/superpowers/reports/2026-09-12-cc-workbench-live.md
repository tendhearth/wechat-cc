# 一起做：真实页面验收（2026-09-12）

保留已确认的 presence 页面。本轮接通开发页面缺失的工作台请求，不改变布局。

## 启动与范围

在仓库根目录运行 `bun scripts/dev-cc-workbench.ts`，打开 `http://127.0.0.1:4187/`。

- 复用生产工作台 service、SQLite store、内部 API 与 Codex adapter；使用本机已登录的 Codex。
- 任务数据独立保存在 `~/.claude/channels/wechat-workbench-dev/`，不会自动导入旧工作台数据。
- 其他生活页面继续读取原有后台；本轮没有重启微信服务，没有发送微信消息。
- 只有工作台写请求启用。宿主保管 token，拒绝非 loopback Host、跨站请求及未列入的接口。
- 每轮启动前从所选文件夹读取 Codex 工具配置，禁用已发现的 MCP，并关闭 plugins/apps/hooks。枚举失败、超时或未知服务名时拒绝启动。此开发配置不修改用户的 Codex 配置文件，也不是额外的文件系统读隔离；实际文件权限沿用 Codex workspace-write。
- 当前实际验收执行者只有 Codex。原生应用与后台仍需同版本一起更新；这不是接管用户任意现有会话，也未实现跨模型自动派工。

## 从真实页面完成的流程

在独立的 `cc-workbench-check` 文件夹中放置合成 CSV：笔记本 125、马克杯 275、明信片 100。资料未注明币种。

1. 在「一起做」填写文件夹和要求，点击开始，实际生成 `周报.md`、`汇总.csv`；合计为 500。
2. 在页面打开汇总预览并确认该版本。
3. 停止并重启独立服务。任务、成果和确认标记仍在。
4. 在同一任务追加销售占比要求，得到 25%、55%、20%；新成果保留为新版本，旧确认版本不变。
5. 启用显式 MCP 禁用修复后再次重启，并在同一任务询问最终结论，正确返回合计 500、马克杯占 55%。

三轮使用同一个 Codex thread；日志显示 SESSION_RESUME，没有重新创建上下文。原始 CSV 字节未变，四份成果快照的 SHA-256 均与数据库记录一致。

## 修复与回归

- 开发页原先漏接七条 workbench 请求；旧运行后台本身也没有工作台接口。本轮提供独立真实执行方式并区分错误原因。
- 相同轮询结果不再重建工作台 DOM，避免用户输入过程中控件被移除。
- Codex 会话探测增加真实的 `rollout-时间-threadId.jsonl` 文件名；保留旧格式和有界目录查找。
- 首页浏览器测试按新布局先展开「鱼缸与连接」，保留功能断言；供应商显示断言使用实际的 `Claude` 标签。

验证结果：工作台、代理、会话发现和隔离配置等 8 文件 55 项测试通过；全仓 typecheck 通过。首页和开发服务的 17 项浏览器回归通过。独立复核发现的 Host 与 MCP 配置问题已修复，复核无新增阻塞项。
