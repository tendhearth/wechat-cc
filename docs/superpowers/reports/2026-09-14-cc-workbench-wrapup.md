## 这批交付是什么

产品定位由单一微信桥接更新为「陪伴 + 统一任务入口」：此刻看 CC 正在做什么，回忆收好过去，一起做专心管理项目和任务。两栏工作台保留完整对话，公开回复穿插工具过程；结束后过程可以折叠，权限、问题、成果按需展开。

已有本批提交覆盖任务/项目隔离、同目录排队、停止与资源关闭、原生恢复确认、历史接入、明确的跨执行者检查与交回、材料与固定版本成果、模型选择、后台子助手及后续回复。微信沿用同一任务服务，补齐已知项目创建、输入与请求处理、订阅完成提醒、固定正文分页和显式索取保存成果。

收尾增加独立 API 任务执行器，复用已有 API 配置，支持文字/图片材料、受限项目读取与目录列表、新建文本成果及完整工具记录的 CC 管理续接。普通陪伴 API provider 没有直接获得工作台权限；Cursor/agy 仍未获准执行受管工作任务。

当前用户路径与能力表集中在[工作台导览](../../cc-workbench.md)。

## API 路径的关键约束与复核

- 每次文件读取、列目录和保存先形成准确的权限请求，批准后重复检查路径与取消状态；保存只创建本任务的新文件，不覆盖项目原文件。
- 使用原生文件描述符锚定路径，拒绝符号链接、危险硬链接读取、其他任务内部目录以及真实 CC 状态树。选项目根目录也不能绕过这些限制。
- 完整模型消息、调用和结果保存于 schema v58 的私有任务表；绑定任务、owner、目录身份及连接指纹，不保存原始密钥。中断回合不会静默重放文件操作。
- 本地停止中断请求并阻止后续文件作用；会话关闭未确认时保留目录占用。不保证供应商已经物理终止推理。
- 只按明确成功结束完成任务；超长、预算耗尽、传输失败或无效完成信号不能算成功。模型请求未知工具或无效文件参数时记录错误结果，让它据此恢复回答，不运行该工具。

独立审查发现并修复两项问题：启动注册曾保护状态目录的空子目录而非真实状态树；SDK 为未知工具生成的错误消息曾使整轮提前失败。注册层私有目录哨兵、真实 loopback Shell/无效 ReadFile 回归均已复核。最终独立审查未发现本路径范围内未解决 P1/P2。此结论不证明完整原生 harness 或真实模型质量。

## 本批之后仍然成立的限制

- 原生能力按验证过的适配器和运行版本生效；完整插件/Hook/Skills、通用 MCP OAuth 配置、各家 App 专属功能不在等同覆盖承诺中。
- API 任务不支持 shell、项目原文件修改、网页/MCP、后台任务、PDF/Office 输入、供应商原生历史及逐任务模型设置。文件工具仅支持 macOS/Linux，Windows 明确不支持；本批未做 Linux/Windows 实机验收。
- 多入口共用后台不等于跨电脑迁移活跃进程。目录排队不等于自动独立 worktree。交接不共享隐藏推理或后台工具内存。
- 微信无法完整展示的权限说明、过长问题集需回桌面处理；发送未确认不会默默重发。真实微信账号仍需后续验收。
- 记录本地保存，任务材料仍发送给选中的 AI 服务；本地存储不等于全部离线。角色设计板保持私有，不随本批推送；运行与源资产遵守单独资产许可。

后续按真实使用中仍需离开 CC 的具体阻碍决定，不在本次收尾继续加入口、执行者或设置表单。
