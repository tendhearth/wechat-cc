# CC：从此刻交办，在手机接着处理

日期：2026-09-22。范围是现有任务入口的衔接，不改「此刻／一起做／回忆」分工，也不引入第二套执行器。

## 借鉴的依据与取舍

本地 `meta-muse/` 中的十张手机截图用于观察入口、任务、活动与记忆的组织。产品身份和能力参考 Meta 的 [Muse 公告](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)、[产品介绍](https://introducing.muse.ai/)、[记忆管理帮助](https://www.meta.com/help/artificial-intelligence/2225571704857152/)。截图不是实现或安全契约的证明。

借鉴三点：先向一个明确的主体交代事情、点击形象查看它在照看什么、离开电脑后仍可处理同一件事。沿用 CC 的任务记录、会话、项目、权限、成果和设备配对，不复制 Muse 的导航图标或另做信息流。个人记忆仍由既有页面管理；本批不会自动将私人聊天历史混进工作项目。

## 实际行为

- 此刻的输入多了「交给 CC 做」。选择项目后进入原任务草稿，只有显式开始才创建任务；取消或失败保留输入。原项目草稿、附件和执行设置保留，新要求以明确分隔追加。没有项目时先添加文件夹，交办内容不会随失败重试丢失。
- CC 头像打开一个按需读取的小面板：等你回应、正在进行、最近五项。待处理请求来自已有全局汇总，普通记录最多读取100项并标明截断。保留中的空闲会话不显示为工作中，过期快照有说明。点击进入原任务，不生成副本。
- 手机「一件事」增加单次允许／拒绝、问题回答、同任务补充、成果查看和下载。所有操作仍经过既有设备授权；请求精确绑定任务、运行和原请求。活会话走实时补充，结束的会话走原续接和确认规则。
- 手机请求编号在重试时保留。发送中、等待接收、已送达、未确认及撤回分别显示；只有匹配的已送达回执才清除对应草稿，旧回执不能清掉后来编辑。问题草稿和补充草稿分别保存；切换任务、刷新与迟到响应不能串入另一项任务。提交问题期间锁住该组字段，避免成功回包抹掉后来编辑。重放已完成或已归档任务的回执不重新打开任务；真正开始新一轮才同步进行中。
- 成果按128KiB块取已保存版本，完整核对SHA256；支持LAN HTTP上没有 `crypto.subtle` 时的本地校验。图片仅预览PNG/JPEG/WebP，文字作为纯文本，其他文件只下载。
- 超大详情按二次JSON包装后的300KiB预算返回明确的413，给512KiB加密隧道帧保留余量。权限说明不截断；手机清除旧控件、禁用续说并保留草稿，要求到桌面处理。

## 验证范围

桌面浏览器脚本：`bun scripts/workbench-companion-browser-smoke.ts`。使用生产前端模块、真实HTTP路由、任务服务和SQLite；执行者是受控夹具。检查交办取消、项目和执行者继承、旧草稿隔离、显式开始、头像查看与返回原任务，并保存1280px和740px截图。它不等于Tauri原生窗口或真实模型验收。

这条浏览器链路发现并修复了两处单测替身没暴露的问题：列表真实读取上限是100；原生HTML select在选项尚未加载时会把设置的值变成空串，不能再把这个空串保存回草稿，否则另一个项目的执行者会回落到全局默认值。补了真实路由／SQLite契约测试及模拟真实select约束的草稿回归。

另外以隔离的DRY_RUN演示后台加载未经替换的 `main.js`，交办选择／取消与头像打开均可用，无未捕获脚本异常；该演示后台未实现的社交、插件、健康接口仍有被捕获的404，不能写成全站零控制台错误。

手机浏览器：`bun --bun vitest run -c vitest.e2e.config.ts src/daemon/__e2e__/mobile-workbench.e2e.test.ts`。真实390px Chromium，HTTP响应由夹具控制，覆盖审批、草稿恢复、陈旧响应、问题提交锁定、LAN校验回退、篡改文件拒绝和超大详情。

服务与隧道：`settings-panel-workbench.test.ts` 使用真实持久存储、任务服务、HTTP设置路由及X25519/AES-GCM加密通道，通过真实relay帧大小门限完成710KB文件读取、权限与问题处理、设备撤销和超大详情拒绝。执行者仍为夹具，不使用主人真实微信账号。
