# 微信与桌面共用任务：阶段交付

2026-09-13，`codex/cc-workbench-v1`。本记录覆盖实施计划 Tasks 1–4，属于本地开发版本，未在真实微信账号验收。

## 用户行为

- 微信发送 `任务 项目`，选择已经登记或属于当前主人的历史项目；项目编号绑定真实目录，不随列表排序变化。
- `任务 新建 <项目编号> <要求>` 直接创建桌面可见的同一项任务，可用 `用 Claude` / `用 Codex` 明确选择执行者。重复消息返回原任务，不重复执行。
- 微信创建的任务默认通知原账号、原主人。桌面任务可显式设置 `提醒我` / `静音`；重复投递旧开启命令不会撤销后来关闭的设置。
- 待处理权限、问题和本轮完成结果绑定准确任务、回合与请求。父回复结束、后台会话空闲不算全部完成。
- 长结果提供固定消息版本的正文分页；开始下一轮不改写上一轮分页内容。单页计入 UTF-16 长度限制，并保留完整 Unicode 字符。

## 可靠性边界

任务、第一条要求、执行设置、创建回执和微信订阅同一事务提交，之后才启动执行。完成状态与冻结结果的通知记录也同一事务提交；临时通知队列写入故障可以重试，整个终态事务失败则保留排队补充而不继续执行。

关闭或更换账号会抑制旧的未发送通知。重新开启生成新的订阅版本，仅通知之后的新事件和当前仍需处理的请求。发送前再次核对 owner、账号、版本和请求有效性。

通知使用一次严格发送：明确服务端确认才记为接受；已知窗口关闭可延后，响应不明、超时、发送中崩溃不自动重放。存储暂时失败不会挡住其他尚未发送通知的后续恢复。接受记录标记 `source=workbench`，保留工作与陪伴数据边界。
