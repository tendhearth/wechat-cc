# 工作台：项目与对话分层

目标：同一个项目可以有多段独立对话，新对话不等于新项目。

## 实现范围

- 新增持久化 `workbench_projects`，保存项目 ID、名称、唯一的规范目录、初始执行者及创建时间。项目目录仍是任务归属与执行隔离的键；这轮不提供项目移动或重命名。
- v63 追加迁移从旧任务目录回填项目，不改任务 ID、原生会话 ID、消息、成果或归档状态。迁移兼容既有数据库修复重放。
- 老的按目录创建任务、原生历史导入和交接入口继续可用：它们复用或登记同目录项目。
- 桌面顶层入口为“添加项目”；每个项目提供“新对话”。添加项目只登记，不调用模型；项目内新对话沿用目录和最近执行者，消息历史不会从其他对话自动注入。
- 项目列表独立于任务的分页、搜索和归档。空项目仍可见；搜索支持自定义项目名称。对话分页仍沿用全局“更多”入口，不是每个项目单独分页。
- 新接口只加入桌面 operator 凭据、开发代理和 Tauri 精确路由允许列表，不扩大 agent 权限。

## 验证

- 存储：空项目保留、同目录去重、独立消息、归档后保留、重新创建 store、项目名称搜索。
- 服务：同目录符号链接去重、无执行副作用、无效目录拒绝。
- 升级：v62 历史任务回填、原生 session ID 保留、重复迁移无副作用；Bun / Node 的迁移指纹一致。
- HTTP：operator 可添加，普通 trusted token 不可添加，非法请求拒绝。
- Rust：`allows_only_the_exact_workbench_method_route_pairs` 通过。
- 真实 Chromium → 生产桌面模块 → host proxy → internal HTTP → SQLite：添加空项目，然后经项目内入口创建两段对话，仍只有一个项目；目录自动沿用；补充、后台状态、成果收集和重连既有检查保持通过。
- 独立审查发现添加成功后旧表单草稿会被重新捕获；已修复清理顺序，浏览器验证再次添加时目录和名称为空。

## 部署边界

本轮只提交该功能，不混入工作树中其他页面、品牌和移动设置的未提交改动；未推送，未更换用户安装的桌面包。使用新“添加项目”接口需要一并更新后台和桌面宿主。
