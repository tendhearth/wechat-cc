# Memory evidence and source review implementation plan

**Goal:** 在已有「CC 眼中的你」卡片旁核对来源，并在原处改正记忆或将观察标为过时。

**Approved scope:** 2026-09-23 用户确认上一轮「建议依据＋就地改正」建议。沿用当前页面和记忆系统；不新增信息流、自动委派、人格设置中心或联网执行。

**Architecture:** 新生成画像仅引用服务端提供的来源目录。读取和校验版修改走同一 daemon；源修改后保留历史产物、使旧画像与总结失效，生成过程中发生纠正则不提交旧结果。前端在卡片旁提供按需展开的依据和小型来源编辑器。

## Constraints

- 只在既有 kit 工作树的 dev 分支实施；不带入另一协作者的未提交页面和品牌修改。
- sources 旧字符串仅展示为未核对名称，不用字符串猜文件链接。
- 新 sourceRefs 的 kind/path/id/project/label 全部来自受控目录，不信任模型返回的路径。
- 原始项目记忆及里程碑只读。用户记忆可编辑，观察可纠正或标过时。
- 校验选定 chat、源身份、读取时 revision；冲突不覆盖，前端保稿。
- 保留历史文件和已有对话；不将标过时称为彻底遗忘。
- _overview.md、_profile.json 是派生内容；profile.md 是原始记忆，不能混淆。
- summary/insight 无引用契约，不伪造来源。空白状态不预填人格结论。

## Review focus

1. 模型编造的来源 token 不能获得读取任意文件的入口。
2. 源改正后，检索、MCP 与主动评估不能继续将失效的生成总结当作最新信息。
3. 后台生成跨过一次纠正时，不覆盖或恢复旧派生内容。
4. 用户换来源、关窗口或收到迟到回包时，不错存、不清新稿。
5. 旧画像、缺失来源与无数据场景保持诚实，不能用预设人格填空。
