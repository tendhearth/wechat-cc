分界纪律:本图只记「想过什么 / 定了什么 / 还欠什么」。实现细节在代码和 commit message 里,不在这里。

用法:节点只写结论,原因写在 里。交互版把 折成点击展开;读 MD 时它就是完整的一句话。

分类原则:有替代做法的写成「做 A · 不做 B」对照;没有替代、纯禁止的进「绝对不做」;过程性收获进「教训」。

定位 3
  • 做 陪伴者 CC(有人格的熊) · 不做 工具型 bot 全部产品决策的总开关:兜底话术要像 CC 在说话、表情包要成长、画像是 CC 画的用户——每一处都在强化「这是一个活物」而不是一个命令行。工具可以被替代,伙伴不会
  • 做 数据不出厂(本地 daemon) · 不做 云端托管 记忆、消息、画像全在用户自己电脑的 state 目录里。这是信任的底座,也是后面每一个技术选型(中继盲转、E2E 加密)的约束来源——不是功能,是原则
  • 做 记忆外置于 daemon,provider 只是过路的大脑 · 不做 记忆绑死在某家 LLM 会话里 persona/profile/knowledge/facts 全在 daemon,每次 spawn 现读注入。所以换 provider 长期记忆一分不丢。字节 OpenViking(13K star)的核心论点与此一致:记忆库独立于 harness,Claude Code/Codex/Cursor 共用——我们无意中先做对了这层
移动路线 5
  • 做 微信当手机聊天面 · 不做 自建手机聊天界面 CC 本来就住在用户微信里,自建聊天界面等于跟微信打架,必输。手机 app 的价值只在微信给不了的三样:陪伴的可视化随身(待办/画像/表情)、独立推送(daemon 挂了微信恰好发不出「我病了」)、远程掌控
  • 做 台阶 A:PWA 先行 定 · 不做 直接上原生 app 零商店、零审核、零新代码栈,先验证「人们到底会不会在手机上看 CC」。台阶 B(Tauri v2 移动壳 + 桌面 Widget + 原生推送)挂在 A 验证有人用之后——Apple $99/年正好和 macOS 签名公证同一笔钱,一鱼两吃
  • 待 台阶 B:手机桌面 Widget CC 小熊住在手机桌面:今天画了新表情就换上、有逾期待办就举牌子。最贴 CC 人设的一击,也是微信永远给不了的。解锁条件:台阶 A 验证 + 决定掏 $99
  • 台阶 C:微信小程序 owner 2026-08-26 拍板:暂时不用。原始顾虑仍在(AI/远控类目审核敏感、个人主体限制多),且 PWA + 微信内置浏览器已覆盖手机场景,没有它非做不可的理由。将来若重提,从这里捡起
  • 做 设备配对长期令牌(在家扫码换一枚,加主屏永不过期) · 不做 每次回微信要新链接 10 分钟短令牌对「加到主屏随时打开」是致命摩擦。长期令牌落盘 0600、上限 20 台,后来它还成了隧道认证的绑定秘密——一个机制吃两份饭
远程中继(出门也能用) 6
  • 做 自研 E2E 隧道(经自有 relay 盲转) 定 · 不做 Tailscale 当产品方案 Tailscale 真 E2E 且零运维,但要用户装第三方 app + 注册账号——自己用完美,给小白不行。自研隧道是唯一同时满足「小白零安装」和「数据不出厂」的方案。Tailscale 保留为 owner 自用的快速通道
  • 做 中继盲转(relay 只见密文) · 不做 Cloudflare Tunnel cloudflared 零代码,但 TLS 在 CF 边缘终结,CF 理论上可见明文——与「不出厂」原则正面冲突。要在上面叠应用层加密,工作量就等于自研,那不如自研
  • 做 HKDF 把设备令牌绑进密钥派生 定 · 不做 裸 X25519 握手 安全 review 抓到的 CRITICAL:未认证握手可被恶意中继 MITM——中继各自跟手机、daemon 握手,中间透明转发看明文。绑定令牌后中继不知令牌算不出密钥,伪造帧过不了 GCM。副产品:设备令牌从此全程不上线,daemon 用已知的 ≤20 个令牌试解密识别设备
  • 做 set_remote 等流程型操作只允局域网 · 不做 隧道可翻任何配置 泄漏的设备令牌不该能远程翻配置+强制重启。危险操作留在家里,和「provider 切换等留在对话里让 CC 确认」同一姿态
  • 做 Service Worker 缓存页面壳 · 不做 只有数据面走隧道 正确性 review 抓到的红线:PWA 的源是局域网地址,出门根本加载不出页面本身——数据面通了页面打不开等于零。SW 缓存壳,在家打开一次,出门从缓存加载,API 再走隧道
  • 做 直连失败一次就记住走隧道 · 不做 每个请求都先等 2.5s 超时 出门时每次白等 2.5s 是体验灾难。preferTunnel 记忆 + 断线拒绝所有在飞请求
上下文交接(换 provider 不断片) 3
  • 做 近段原文直接交接 定 · 不做 codex 式 LLM 摘要 实现时修订:codex 摘要是为了压缩几十万 token 的工具调用噪音;我们消息库存的就是干净的用户↔CC 短消息,最近 12 条才 1-2k tokens——摘要在这里只引入损耗和异步 LLM 调用,零压缩收益。保留 codex 真正的洞见:用户原话最不能压缩失真,以及「摘要前缀框架」(交接块自称系统交接,叮嘱别重新自我介绍别重复回答)。setMode 标记 → 切换后第一条 prompt 前置 <handoff> 块,取即清
  • 做 Amp 式按需回查(chat_history 工具) 定 · 不做 纯交接块断后路 四家 harness(Claude Code/Codex/OpenCode/Amp)里只有 Amp 有事后回查机制(thread references),也被认为质量损失最小。近况块必然有限,留逃生口:chat_history(chatId, limit, query?, before?) 按时间/搜索/翻页查原文,admin tier
  • 做 交接块永远从消息库现取 · 不做 交接套交接 codex 明确警告多次压缩累积降质。切 A→B→C 时,B→C 的交接从消息库现取 B 段真实对话,天然不套娃
更新分发 3
  • 做 R2 + 自域名 + Tauri updater 全自动 定 · 不做 Cloudflare Pages 托管产物 mac 产物 91MB,Pages 单文件上限 25MB。R2 免费档 10GB 存储 + 永久 $0 下载流量,绑 dl.tendhearth.com。更新横幅点一下→下载→装好→重启,用户零命令
  • 做 Windows 只编译,签名和发布固定在 Mac 定 · 不做 Windows 上跑签名 Win32 层空环境变量等于删除——无法给 tauri 传空密码,签名步骤在无 TTY 的 SSH 里等密码挂死,这是平台死结不是配置问题。.sig 是 minisign 签名、平台无关,exe 拉回 Mac 签(publish-update --platform/--artifact 参数已固化这条流水线)
  • 做 $1 预算告警 + 每 IP 限流 + 每平台只留 3 版 · 不做 裸奔等账单 owner 原话:我担心扣费了但我不知道。告警邮件先于任何真实扣费到达
LLM 通道 4
  • 做 用户点「测试连接」才检测 定 · 不做 开机自检 / 定时探测 owner 红线原话:万一网络不稳定,你随意去检测,可能导致用户封号。无人值守的自动外呼一律不做,cached() 永不拨号,dial() 只由用户点击触发
  • 做 表单填 key,daemon 自己写文件 · 不做 让用户写环境变量 owner 原话:你让小白用户写到变量里?图形表单 → POST /v1/llm/keys → daemon 原子写 daemon.env(0600),key 永不进日志
  • 做 provider 坏时 CC 人设兜底回复 · 不做 沉默或抛错误栈 通道好但大脑坏时,用户发消息必须有回应,而且要像 CC 在说话:「我这会儿够不着自己的脑子了…弄好之后再发我一条,我就回来了。」无 emoji——owner 定调「符合 cc 身份的说法」
  • 做 cursor 走 cursor-agent CLI 订阅登录 · 不做 cursor API key owner 纠正:cursor 用户大多是订阅,不是 API key——和 claude code / agy 同一姿态,CLI 每轮 spawn + NDJSON 解析
小白阻力 3
  • 做 /set 图形设置面板 + 欢迎语自然引导 定 · 不做 让用户背命令 owner 原话:微信用户不知道怎么命令,前期一个设置面板能非常好地帮助他们。第一次打招呼简短自我介绍,自然时机只提一次「发 /set 就有设置」,让设置在像真人聊天中完成
  • 做 接入卡不拦路 · 不做 向导式强制流程 环境检测都过了说明用户装了 CLI;检测不过,让他填 llm key 也没用。卡片是信息不是闸门
  • 做 远程访问一键开关(面板点一下,自动写配置+重启) · 不做 让用户改 JSON + 手动重启 owner 手动趟出来的路(改 config、SIGTERM、绕 lockfile 守卫)必须变成用户点一下的按钮,这是「我能用」到「用户能用」最关键的一跳
表情体系 1
  • 做 初始包 + CC 每日自画补缺 + 成长曲线 定 · 不做 一次给满表情库 owner 定调:一开始克制每天一张,慢慢积攒。阶段一每日补基础情绪,阶段二每周扩展,到 40 张封顶——成长感本身是陪伴叙事的一部分
外部集成(把别家 Agent 接进来) 7
  • 做 openai-compatible 当外部 Agent 的官方接入路径 定 · 不做 再造一套自有 HTTP provider 协议 外部集成反馈 #1 (2026-08-26):本地 Agent 想接成 provider,此前只能 fork 源码或"假装成 OpenAI 端点但带副作用"。修掉两个副作用(cheap_eval_provider 显式指定防劫持、delegateOpenai:false 关 delegate peer)后,包一层 OpenAI 兼容端点就是干净的接入路径——这是生态标准做法(ollama/vllm 皆然),比自造 JSON 协议少一份文档、多一片生态
  • 待 动态 provider 注册机制(不改源码挂 out-of-tree provider) 插件系统目前只能加 MCP 工具不能加 provider。等 openai-compatible 路径被外部集成者实际用起来、暴露出它覆盖不了的需求,再决定要不要做
  • 做 cheapEval 显式指定(cheap_eval_provider) · 不做 openai 注册即静默承接全部后台评估 反馈 #2:偏好序 openai 第一,配置即劫持记忆整理/moderator/introspect——端点是特化服务时得到无意义回答或意外账单。显式指定优先;未指定时注册日志明示这个副作用
  • 做 信封带 msg_id · 不做 provider 只能信任上游去重 反馈 #4:<wechat> 信封原本没有微信消息 id,provider 侧无法端到端幂等。有才渲染,老 provider 无感
  • 做 codex-autofix 对 git checkout 默认关 · 不做 后台悄悄改源码用户的 node_modules 反馈 #7:daemon 启动后自动 bun add 弄脏 git 状态,出乎意料。检测到 .git 即跳过,WECHAT_CC_FORCE_CODEX_AUTOFIX=1 自愿打开
  • 做 access list/remove CLI · 不做 移除 allowlist 靠手编 JSON 反馈 #5:只有加人路径。移除拒绝 admin(防自锁),5s TTL 缓存内生效免重启
  • 待 dangerously 按会话生效 反馈 #6:flag 语义像"跳过工具确认",实际把所有 allowlist 会话提为 admin(全局提权)。已在启动日志明示 blast radius;按会话生效是权限模型改造,等真实需求
绝对不做 3
  • 不做 无人值守的自动外呼探测(任何形式) 封号风险是产品级灭顶风险,不是体验问题。见 LLM 通道
  • 不做 把密钥/令牌写进日志或 URL 明文 key 不进日志、设备令牌不上线、隧道令牌只参与密钥派生——一以贯之
  • 不做 危险操作(provider 切换/配对/恢复/重启)进设置面板远程侧 流程型操作留在对话里让 CC 确认上下文,或只允局域网
教训(过程性收获,防止重犯) 6
  • E2E 要测到用户真正走的第一步 远程隧道我只测了数据接口就宣布「出门可用」,review 抓出:真手机在外网连不上 LAN 源,页面本身加载不出来。测试的起点是「用户打开它」,不是「API 返回 200」
  • review 用双维度并行(安全 + 正确性) 同一批代码,安全 review 抓到 MITM,正确性 review 抓到 Service Worker 缺失——两个红线互不重叠,单一维度必漏其一
  • Windows 企业网三件套 TLS 拦 github(UnknownIssuer)→ 文件从 Mac scp 直传;无 winget → 手动布环境;NSIS 缓存要预种且失败的重下载会删光整个目录
  • Cloudflare account-owned token 的 /user/tokens/verify 会假阴性 验证端点失败但真实 API 调用能通。判断 token 有效性用真实调用,不用验证端点
  • PowerShell/Win32 给环境变量赋空字符串等于删除该变量 由此衍生出整条「Windows 只编译」的流水线决策
  • launchd 硬重启(process.exit + KeepAlive)可绕过 lockfile 自愈守卫 自愈重启保守是对的(不确定不动),但用户主动触发的重启走硬退出,两条路径并存各司其职
