# WeChat-cc 桌面陪伴动画开发计划

## 目标

将“正在陪伴”中的静态插画正式替换为可交互的鱼缸动画，并提供可拖动到电脑桌面、在主窗口隐藏后继续运行的桌面陪伴模式。

动画需要保持可持续编辑：后续可以独立增加或替换小鱼、水草、气泡、花朵、小熊动作和交互规则，而不需要重新制作整套动画。

## 最终体验

### 正式页面中的互动插画

- 原静态插画位置直接显示动态鱼缸，而不是跳转到“动画实验”页面。
- 小鱼保持在水面与泥土之间游动；鼠标接近时按性格聚集，点击水面后逃开。
- 水草漂浮、气泡上升；底部花朵在悬移时闭合、离开后展开。
- 小熊举着鱼，悬移进入和离开时挥手；文字气泡固定在头顶上方留白处。
- 页面加载或设备不支持时，显示静态首帧作为兜底。

### 桌面陪伴模式

- 主窗口隐藏后，保留独立的透明、无边框、小尺寸鱼缸窗口。
- 该窗口可拖动到桌面任意位置，持续播放与互动。
- 提供简洁控制：锁定／解锁位置、鼠标穿透（可选）、关闭陪伴。
- 记住最后一次位置和尺寸，下次启动恢复。
- 采用“透明悬浮陪伴窗口”实现，会浮在桌面与其他窗口上方；它不是嵌入 macOS 桌面图标底层的壁纸级窗口。

## 技术方案

项目当前使用 Tauri 桌面框架。保留一套共享的动画引擎和素材层，再由两个展示容器使用：

```text
动画引擎与素材层
├── 正式“正在陪伴”页面
└── 桌面陪伴透明窗口
```

动画不依赖 Rive 或 Godot 编辑器。继续使用已完成的 Canvas 分层渲染、透明 PNG 素材、局部网格形变和鼠标交互，因此后续可按元素单独修改。

## 可持续编辑结构

将现有实验代码整理为以下可配置模块：

- `scene`：鱼缸、层级、尺寸和各元素位置。
- `fish`：鱼的素材、速度、胆量、聚集和逃跑规则。
- `plants` / `bubbles` / `lotus`：独立装饰元素与运动参数。
- `bear`：身体、手臂、文字、挥手动作及命中区域。
- `interaction`：鼠标进入、悬移、点击与离开时的状态转换。
- `host`：正式页面或桌面窗口的尺寸、交互密度和兜底首帧。

这样后续需求可局部处理，例如新增一种鱼、调整水草振幅、替换小熊动作或让桌面模式隐藏文字，都不会影响其他元素。

## 分阶段实施

### 阶段 1：整理动画为正式组件（预计 2–3 小时）

- 从“动画实验”中抽出共享动画引擎、素材清单和配置。
- 消除页面专属的硬编码位置，保留当前小熊、花朵、鱼群的交互效果。
- 提供静态首帧兜底与基础性能控制。

验收：同一套动画可以在实验页和正式页面以不同尺寸运行，元素与交互不丢失。

### 阶段 2：替换正式页面静态插画（预计 1.5–2 小时）

- 在“正在陪伴”原位置接入正式动画组件。
- 适配现有页面尺寸、小窗口布局与视觉层级。
- 检查加载、悬移、点击、窗口缩放及降级静态图。

验收：用户在原静态插画位置即可完成所有鱼缸互动，页面布局与性能稳定。

### 阶段 3：桌面陪伴 Demo（预计 3–5 小时）

- 新增 Tauri 透明无边框陪伴窗口。
- 主窗口隐藏时继续显示；支持拖动、关闭和恢复主窗口。
- 接入同一套动画引擎，先验证尺寸、性能和鼠标交互手感。

验收：可将鱼缸拖到桌面任意位置，主窗口隐藏后动画持续运行且可互动。

### 阶段 4：桌面陪伴完善（预计 0.5–1 个工作日）

- 记忆位置、尺寸和显示状态。
- 加入锁定位置与鼠标穿透开关。
- 处理多显示器、重启恢复、退出应用和异常关闭。
- 完成 macOS 实机打包验证。

验收：桌面模式可日常稳定使用，状态恢复符合预期。

## 预计节奏

| 交付物 | 预计时间 |
| --- | --- |
| 可持续编辑的动画组件整理 | 2–3 小时 |
| 正式替换静态插画 | 1.5–2 小时 |
| 可拖动桌面陪伴 Demo | 3–5 小时 |
| 完整桌面陪伴模式 | 0.5–1 个工作日 |

建议顺序：先完成阶段 1 + 2，让现有页面先正式使用互动鱼缸；确认桌面尺寸和视觉方向后再做阶段 3 + 4。

## 后续可扩展方向

- 根据时间、天气或消息状态改变鱼缸氛围。
- 增加小熊眨眼、点头、送鱼等动作。
- 为不同鱼加入更明确的社交行为。
- 添加低动效／安静模式，减少持续动画。
- 扩展为多套可切换的桌面陪伴场景。
