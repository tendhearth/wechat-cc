# 画像依据与来源改正

「回忆 → CC 眼中的你」的画像卡片提供 **依据** 入口。用户可查看对应来源的当前记录、改正个人记忆，或把观察标为过时。它沿用原页面，不增加一个新的设置中心。

## 使用方式

- 新生成的倾向、偏好和记事卡片可以打开真实来源。个人记忆可编辑；观察可改正或标过时；项目笔记和里程碑只读。
- 旧画像只有模型写的来源名称，无法可靠定位。入口会说明需要更新画像，不根据名称猜文件。
- 保存前校验读取时的版本。发生冲突时保留草稿，先读取最新原文，再明确选择按最新来源继续编辑；不会自动覆盖别人刚改的内容。
- 更正后页面显示“历史画像 · 待更新”。点“更新画像”重新生成。观察的旧版本与审计记录仍保留，已有对话也不删除。
- 来源窗口展示的是当前记录，不是生成画像时的原文快照。一个可点击的引用证明来源确实存在，不等于模型的结论已经被证明正确。

## 实现边界

生成器为本轮实际提供给模型的有限内容建立来源目录。模型只能选择目录标识，路径、观察 ID、项目名和标签均由服务端解析；未知标识和模型自造对象会被丢弃。旧 `sources` 字符串仍兼容，但不会成为可访问路径。

`GET /v1/memory/source` 读取所选 chat 下的来源，并返回修订摘要与可编辑能力。`POST /v1/memory/source/review` 校验来源身份、修订摘要和操作。两条路由沿用桌面记忆模块现有的 trusted FILE 凭据；普通会话限制在自己的 chat，项目来源仅限主人。不借用可指向另一隔离实例的工作台代理。

纠正前先使派生状态失效。旧 `_overview.md`、`_profile.json` 留在原处供查看；新快照、回忆检索和模型文件读取会排除失效概要。自省也不再取已归档观察事件的推断。原始 `profile.md` 不受这个过滤影响。

概要与画像各自记录是否更新。更新画像不会假装概要也已重算；概要由已有“重新整理”入口刷新。生成器复查材料指纹和修订号，因此跨过一次更正的迟到结果不能恢复旧状态。损坏的状态文件先按过期处理，在下一次生成开始时重建保护记录。

这些保护针对后续读取与生成。已经进入运行中对话上下文的内容不会被追溯删除；没有声称彻底遗忘，也没有对任意外部进程直接改文件提供跨进程事务保证。

## 验证

- 来源目录、路径与会话隔离、修订冲突、观察更正事务及过期过滤有定向测试。
- 前端测试覆盖脏稿关闭、保留与放弃、切换来源、请求迟到、冲突恢复、归档后的只读原文及焦点。
- `bun scripts/memory-evidence-browser-smoke.ts` 使用生产页面/CSS/记忆模块、实际 HTTP 路由和临时 SQLite/文件，验证改正至再生成的闭环，并截图检查 1280/740px 页面与 390px 来源窗口。
- 该脚本的模型输出、启动挂载和 CLI 传输是夹具，不代表真实模型或原生设备已验收；不会修改主人的记忆。
