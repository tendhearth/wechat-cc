## ⚠️ 破坏性变更:已配好的「手」要重新配对一次

如果你用过 `wechat-cc hand invite` / `hand join` 把另一台机器配成「手」,
**升级后要重新配一次**。一条命令:

```
在手那台:  wechat-cc hand invite
在微信里:  (粘那串码)
```

原因是一个授权修复。`/a2a/exec`(允许远端在你机器上跑一个本地 agent)
此前**只验 bearer**,而 registry 是一张**平的**信任表,里面同时装着:

- 你自己的另一台机器(`hand invite`/`hand join` —— 两端都要 CLI 访问权)
- 朋友的 bot(六位配对码 / `a2a install` —— 社交层)

而手侧给大脑写的记录跟社交对端**长得一模一样**,路由分不出来。于是
「谁能在我机器上执行代码」的实际答案是「任何配过对的人」。

现在有了显式授权位,**缺省关闭**(fail closed),只有 `hand accept` /
`hand invite` 这条两端都需要 CLI 访问权的路径会打开它。因此旧配对失效。

要被利用需同时满足「开了 A2A HTTP 监听」+「社交对端能直连到那个端口」;
信箱传输不载 exec,所以六位码配对的对端默认够不着。**不是随手可打,
但授权模型本身是错的。**

## 派活给另一台机器:从「有代码」到「真能用」

这个功能有 CLI、有微信命令、有测试、有文档 —— 唯独没有一次端到端的真实
使用(零注册手、零 `让X执行`)。这一版真机走通了,沿途修掉七个 bug:

**配一台手:4 条命令 2 个终端 → 1 条命令 + 微信里粘一次**

```
手那台:  wechat-cc hand invite     ← 自动挑地址、开监听、重启、出码
微信里:  (粘那串码)                 ← 自动试一次,当场告诉你通没通
微信里:  让<机器名> 看看日志
```

`hand invite` 会自己挑一个对端连得上的地址(Tailscale 优先,其次局域网
网卡),**挑了哪个一定打印出来**;挑不出可达地址就明说,绝不悄悄回落到
回环 —— 那会让配对成功、派活永远失败。配对码里带上机器名,所以
`hand join` 不用再想一个 id。

**说话更像人话**:此前触发器卡的是动词(必须是「执行」或「跑」),于是
「让win想一想…」不触发。现在按**已注册的手名**认,动词随便;名字没命中
就落回正常聊天(所以「让张三跑一趟」不会被劫走)。大小写不敏感。
新增 `/hands`(也认「有哪些手」)列出已配对的手。

**修掉的**:派活此前把 provider 写死成 claude,一台不装 claude 的机器
永远当不了手,而错误是「Claude Code process exited with code 1」,看不出
因果;非 claude 的手拿到的权限档实际是「什么都读不了」(注释写的是只读);
回复的文字被按 token 切碎;对端连不上时报的是「你 URL 是不是打错了」。

## /chat 与 /both

`/chat` 从「对称自由辩论」改成有引导的匿名互评:

- **互评前抹掉作者名** —— 模型对着名牌客气、对着陌生名字挑刺,这是白送的
  偏见。裁决那一拍同样匿名(裁判也是模型)
- **先抽争点,只打争点;没有实质分歧就整拍跳过**(并明说跳过了,免得看起来
  像坏了)
- **每人一个批判视角**(事实与证据 / 假设与推理 / 遗漏与代价)—— 相同指令
  必然产出相同角度
- **互评名次**:各方给出排名,Borda 计票、**不算自投**,裁决末尾一行
  `📊 互评`

`/both` 末尾补一条可以直接用的收口 —— 此前是 N 条答案并排丢给你,合并的活
全推给人。

## 匿名社交层:自愈

- **揭晓投递失败会永久毒化这次连接** —— 本地记下「我已同意」但没送出去,
  之后重试直接短路报「已连接」,一个字节都不再发。现在把「同意」和「送达」
  分开记,没送到的会自动补投(14 天有界)
- **明信片、以及介绍人替两端跑的腿**,同样有了欠账与补投
- **2 跳连接里后揭晓的一方曾被永久晾着** —— 信箱传输没有同步返回值,而
  介绍人只补先揭晓的那一条腿

真机验证:两台机器,断网一夜之后重启,**没有手工干预**,补投自己把连接
补上并完成了 E2E 加密信件往返。

## 看得见:一条回答是「查来的」还是「想出来的」

CC 用 Gemini 大脑时会联网检索,而此前日志里只有 `chunks=3 dur=39190ms` ——
**39 秒里发生了什么,一个字都没有**。

现在每轮记下调过哪些工具(**只有名字,不含参数**——参数里是搜索词、文件
路径、消息正文),落库可查,日志面板新增筛选框(打 `tools=` 就只剩联网查过
的那些)。

同类修复还有:

- **登录真的失效时,唯一负责通知你的那处判定说「你等着」** —— 它不认识本
  仓库自己的 `auth_failed` 错误码,于是 claude 登录死掉时你收到的是「暂时
  无法正常工作,恢复后会再通知你」
- **连接失败的判定照着 Node 的错误词汇写,而 daemon 跑在 Bun 上** ——
  两套措辞,于是你收到过 Bun 的原文「Was there a typo in the url or port?」
- 派心愿此前**时灵时不灵**地报 checker_unavailable:脱敏闸门写死 12 秒,
  而 Gemini 大脑单次实测 10.3–14.3 秒。延迟预算改由各家 provider 自己声明
