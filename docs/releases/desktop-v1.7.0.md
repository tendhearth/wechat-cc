## 一起做：Claude / Codex 任务留在 CC

两栏工作台集中项目与任务，回复、工具过程和待处理请求按顺序呈现，结束后
可以收起过程。支持材料上传、成果阅读与差异检查、任务搜索归档、原会话续接，
以及带选定上下文和成果版本的 Claude ↔ Codex 检查与交回。不同项目可以并行，
同目录冲突任务排队；未自动创建独立 worktree。

原生适配器补齐已验证的项目规则、直接配置 MCP、模型选择和后台生命周期。
独立 API 任务适配器用于读取文字/图片材料和生成文本成果；它不带原生 shell、
MCP 或后台进程。Cursor / agy 的原有聊天接入保留，尚不作为受管工作执行者。

微信可在已知项目新建任务、补充要求、处理权限和问题、订阅完成提醒，查看
固定版本结果并明确索取文件，与桌面使用同一份任务记录。新路径通过隔离
HTTP 验证，真实微信账号与全平台验收仍需单独完成。

当前范围、能力边界和参考项目见[工作台导览](../cc-workbench.md)。

## ⚠️ 升级后行为会变的三处

1. **`agent-config.json` 里写的默认 provider 现在真的算数。** 此前配置解析手写
   了五家、漏了 `agy`,写着 `provider: "agy"` 的安装会被**静默当成 claude** 跑。
   升级后尊重配置 —— 如果你的默认曾被静默改掉,现在会切回你写的那家。开机
   日志会说一句。想改:设置面板「默认大脑」、微信 `/set provider cc`、或对
   CC 说「把默认换成 claude」。
2. **`/api <模型>` 只对当前对话生效**,不再改全局默认。这个群钉 DeepSeek,
   别的群不受影响。全局默认在面板或 `/set` 里改。
3. **访客对话不能再切到 cursor**(`/agy` 早就拒,`/cursor` 之前漏了)。两家都
   是订阅 CLI,所有对话共用一把 trusted 钥匙,分不了权限。管理员/信任对话照旧。

## 模型与后端:一处看全、一处改全

此前模型相关的事散在四处:聊天档位在 `/set`,各家模型只能对着 CC 说「换成
xx」,后台评估用哪家**只能手改 JSON**,API key 手改 `daemon.env` 再重启,哪几家
活着要看 boot log。设置面板现在多一整块「模型与后端」:

- 六家一行:接入了没、上次体检通不通(只读缓存,面板绝不主动外呼)、当前
  模型、没接入的怎么配;订阅 CLI(agy / cursor)标 🔑 共享钥匙
- **默认大脑**下拉,改完 CC 自己重启
- 自配 API(`/api`):地址、默认模型、**key 直接在面板填**(和桌面「大脑」卡
  同一条落盘路,值不进日志、不进 audit、不回显)、短名增删
- 后台评估(记忆整理 / 辩论主持 / introspect)走哪家;**非管理员能用哪些**
  provider 勾选

微信里同样的事一条命令:

```
/api list                  网关上现在挂着哪些模型(你发命令才拨,60s 缓存)
/api alias ds=DeepSeek     起短名;之后 /api ds
/api ds                    这个对话切到 DeepSeek(只对本对话)
/set cheap agy             后台评估改走 agy,下一次评估生效,不用重启
/set providers claude,openai   非管理员对话只能用这两家
/set provider cc           全局默认大脑,改完自动重启
```

## CC 知道自己是谁,也能自己换

- **问「你是哪个模型」能如实答**:模型 id 直接写进系统提示的身份行
  (`你是 claude(当前模型 …)`),任何权限档都能答,不用调工具。此前它只知道
  自己是 claude,版本靠猜;在 `/agy` `/api` 对话里问,`model_get` 报的还是
  claude 的。
- **「换成 opus 5」**:CC 调 `model_set`,改的是自己这家(此前在 `/api` 对话
  里说换模型,改的是 claude 的字段还回你 ok),写完释放活会话 —— 下一句就在
  新模型上,不是「改了但没生效」。
- **「用 DeepSeek」/「用 Gemini 试试」**:新工具 `provider_switch`,只切当前
  对话;DeepSeek / Kimi / Qwen 这类走 `/api` 那扇门的映射写在提示里,你不用
  记哪个词对哪家。
- **记忆与人格跨 provider 是同一份**(按构造保证,不靠各家自觉):系统提示
  一处生成、六家都吃 —— 修掉了唯一漏网的 gemini(API key 那条一直是没人格没
  记忆指引的裸模型);长期记忆走同一个 MCP;换 provider 有交接块;
  **openai / gemini 这两家不能续线程的,daemon 重启后现在也会前置一段近况**,
  不再从零开始。

## 外挂 CLI:出了错要有人告诉你

**agy 每一轮都双发。** 正文之后总跟一条模型的旁白(「已回复用户的问候。」)。
根因:agy 只读自己的全局 MCP 配置,我们的条目带命名空间,它回报的 server 名
是 `wechat-cc-wechat` 而不是 `wechat`,回复判定认不出 → 每轮都走 fallback 把
旁白当第二条发出去。log 里 claude 全 `reply=true`、agy 全 `reply=false`,而
同一行 `tools=` 明明写着 `wechat-cc-wechat/reply`。

**cursor 从没解析出过一个 tool_call。** 解析器照 claude-code 类推,读顶层
`name`;真实 envelope 是 `tool_call.mcpToolCall.args.{serverIdentifier,toolName}`,
顶层根本没有 `name`。四条 fixture 换成现场抓的原文。

**codex 死了半个月,是被过时的守卫误杀的。** 两次真机探测:我们的 SDK 0.144.4
驱动用户的 CLI 0.153.4 **正常**;SDK 自带的同版二进制被 OpenAI 服务端以
「这个模型需要更新的 Codex」**拒掉**。结论:版本号判不出能不能用,能跑新模型
的只有用户那个更新的 CLI。现在找到 CLI 就注册,版本不同只记日志,**第一次
用到时真跑一句探测**;探测没过把原因用人话发给你(此前 spawn 阶段的失败一路
沉默)。claude 同样套上探测。不打包内置二进制。

**三个新哨兵**,把「静默」变「可见」:

- `[PROVIDER_ANOMALY]`:某家连续 3 轮「有文字、零 reply 工具」→ 日志 + `/mode`
  标「像是流格式变了」。agy / cursor 的流格式再漂移,不用等你截图
- `[CODEX_PROBE]` / `[CLAUDE_PROBE]`:每次 daemon 起来后第一句
- `bun run test:live-cli`:真跑一句让 CLI 调 wechat MCP 的 `ping`,过我们的
  解析器比形状;默认跳过,升级 agy / cursor 之后跑一下

同类清理:provider 名单曾抄了 7 份(唯一事实源 `lib/provider-ids.ts`,能力矩阵
测试钉死同键);写死的模型名只许出现一处;后台评估显式给 `max_tokens`(思考型
模型把思维链算进预算,吃光就回空串,看着像不回话);`/help` 只列真能用的。

## CC 新形象与首页水族箱

桌宠采用统一的 Light / Dark 形象，眨眼、睡觉、表情与双向明暗转场共用
角色模型。首页也使用同一套定稿角色：水彩鱼缸保留游鱼跟随、点击散开，
荷花开合和螃蟹换位改用柔和水彩素材；离线时由 Dark CC 安静陪在鱼缸旁。
首页单独处理落地阴影和光晕，让角色在浅色纸面上轮廓清楚，不改变桌宠资产。

## 随身 CC:首屏改成「伙伴的一天」

链接协议本地兜底。

## 版本号统一(2026-09-22)

此前同一个产品有四个版本号:发版认 `tauri.conf.json`(1.6.6)、`wechat-cc --version` 报根 `package.json`(0.6.4,自 PR #58 起就没动过)、`apps/desktop/package.json` 写 0.5.18(没人读)、ACP 的 clientInfo 里还硬编码着 `'0.6.4'`。

这一版起**四处对齐成同一个号**,由 `scripts/version-consistency.guard.test.ts` 钉住;`--version` 同时带上构建的 git 短 sha(形如 `1.7.0 (a1b2c3d)`)—— 因为 `self deploy` 的健康门打印的就是这行,没有 sha 就看不出新构建到底起没起来。

对使用者的影响:`wechat-cc --version` 的输出从 `0.6.4` 变成 `1.7.0 (<sha>)`。插件的 `requires wechat-cc >= X` 只会更容易满足(号变大了),不会因此被挡。
