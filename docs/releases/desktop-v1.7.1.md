# wechat-cc desktop v1.7.1

**Date**: 2026-09-28
**Tag**: `desktop-v1.7.1`(配套 CLI 同号)
**Scope**: 第一版用公司 Developer ID 签名并经 Apple 公证的 macOS 包;桌面与手机的交办入口统一;其余是不改行为的大拆分与发版链加固。

> 走 patch:距 1.7.0 一天,只有一块对使用者新增的能力(交办入口),按 roadmap「每合一批就发一版」的纪律发。

## macOS 包签名并公证了

从这一版起,macOS 包由 **Nate Gu & Co LLC(Team ID 9Y6JAPDP7A)** 的 Developer ID 签名,并通过 Apple 公证、票据已钉进 .app:

- 下载打开不再被 Gatekeeper 拦成「无法验证开发者」,也不用右键打开或去「隐私与安全性」里放行。
- .app 与里面的 `wechat-cc-cli` 都开了 hardened runtime,带 JIT 所需的 entitlements。
- 系统隐私授权(「完全磁盘访问」等)记在签名身份上,而 Developer ID 的身份是「bundle id + team」,**以后升级不会再把授权弄丢**。

**升级时可能要再点一次授权**:从 1.7.0 及更早(ad-hoc 签名)升到这一版,macOS 可能把它当成一个新 app,「完全磁盘访问」或「访问文稿文件夹」会再问一次。点允许即可,之后的升级不会再问。如果 wechat-cc 升级后在后台没反应、微信也不回,先看屏幕上有没有权限对话框。

Windows 与 Linux 包不变。

## 交办:桌面与手机一个入口

- **不必先选项目。** 桌面聊天里确认要求、勾选讨论摘录,交给 CC;可以指定执行者或已有项目,不指定就给这件事开一个**独立的受管工作目录**。
- **手机能直接新建,也能上传图片或文件**,在同一件事里继续补充。大文件分块上传,断网后重选原文件可以续传。
- 断线重试会按回执回到原来那件事,不会重复创建。

升级会跑两个数据库迁移(v68 创建回执、v69 目录与材料归属 / 上传预约),自动完成,不动已有数据。

尚未验收的部分:真实 Tauri 窗口里的新入口、Safari / 微信相册 / 软键盘 / 网络切换下的手机上传、云端模型看图;「打开工作位置」目前只支持 macOS。

## 不改行为的内部改动

- `cli.ts` 拆成命令登记表;daemon 的 `bootstrap/index.ts` 全部走 `wire-*`;工作台服务 `service.ts` 从 1965 行拆成 12 个按域的模块(十个 PR,每个都真机自检过)。
- 发版链:`publish-update` 在 R2 令牌失效时直接红,不再「降级暂存」还报绿;公证变量只在证书就绪时存在;e2e 作业装浏览器。
- `self deploy`(维护者本机部署)会用钥匙串里的 Developer ID 重签 sidecar 与整个 .app;签名失败在换上线之前止损。
- 测试在 Windows 满载下的超时放宽。

**对使用者可见的变化**:只有上面两节。
