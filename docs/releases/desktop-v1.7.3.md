# wechat-cc desktop v1.7.3

**Date**: 2026-10-04
**Tag**: `desktop-v1.7.3`(配套 CLI 同号)
**Scope**: CC 怎么把话发给你,换了一套根本做法;网络守护只拦真正需要保护的调用;各家模型的报错不再当成回复发出来;外部 CLI 自动升级;一批稳定性与安全修复。

> 走 patch:距 1.7.2 两天。改动面大,但每一步都过了隔离实验、真机自检,并在维护者本机跑过。

---

## 回复:一轮最后说的话就是回复

以前 CC 必须通过一个 `reply` 工具说话。有些模型(尤其是 Qwen / Kimi 这类)说完了不知道怎么收住,会连发「(停，不再发了)」「(真的停了)」;Cursor、agy 偶尔会把过程旁白重复发一遍;工具调用失败时你可能一条都收不到。

现在五家执行者(Claude Code、Codex、Cursor、agy、openai 兼容的 Qwen / Kimi)都改成:**这一轮最后说的话由 daemon 统一发给你**。

- 聊天型模型(Qwen / Kimi / agy):一轮里说的话按顺序发出,按空行分条,最多 4 条。
- 编码型执行者(Claude Code / Codex / Cursor):只发最后的结论;中间「我先看看仓库」这类过程不发微信,任务超过 2 分钟会发一句进度。
- 语音、表情、文件跟着这一轮的回复一起发;在桌面 / 手机上跟 CC 聊时,它们不会再漏到微信里。
- 桌面和手机能看到语音、表情、文件,以及默认收起的「过程」。
- 后台主动关怀里,CC 想说的话写不出值得发的内容时可以不发(`NO_REPLY`)。

要退回旧方式:在 `agent-config.json` 里加 `reply_delivery: { <执行者>: 'legacy' }` 再重启。

## 网络守护:只管需要保护的调用

- 只拦连官方接口的调用(Anthropic / OpenAI / Google / Cursor 指定了 Claude、GPT、Gemini 的模型);国内模型(DeepSeek、Kimi、通义、智谱)、自部署模型、自定义网关、Cursor `auto` 网络怎样都照常用。
- 装了 bx 就以 bx 为准(保护中才放行);没装 bx 用 daemon 自己访问 Google 的探测。
- 回 y/n、取消、切换模型这些控制操作网络不安全时也能用。
- 没装 bx 的机器:网络连续两次判断不安全时,在跑的任务**暂停**(不是杀掉),恢复后接着跑,最长 30 分钟。
- Codex 连哪里按它自己的配置判断(不再看 `OPENAI_BASE_URL`)。
- `wechat-cc guard status` 能看到每个模型被判成需要还是不需要保护。

## 报错不再当成回复

Claude 的 401/403、Codex 断网、Qwen 网关超时、Cursor 写进回答里的「Agent Looping Detected / Upgrade your plan」等,现在都按出错处理:你收到一句说明原因的提示(认证没通过 / 网络 / 额度),而不是报错原文。Codex 断网不再等 400 秒没反应;openai 兼容接口有了超时。

## 外部 CLI 自动升级(默认开)

每天检查一次 Claude Code、Codex、cursor-agent、agy;遇到「客户端太旧」类报错也会立刻检查。只在空闲时用各家官方的更新命令升级,升完马上自检,不兼容就自动退回旧版本并通知你。`wechat-cc cli status | upgrade | rollback`。

## 稳定性与安全

- 一个插件启动慢不再拖垮整个对话;wxvault 插件启动快了很多(需要 wxvault 1.4.1)。
- 部署后启动时 agy / Cursor 偶尔没登记上的问题修好了(会自动重试补上)。
- 安全:会话只能把回复发回自己的聊天;往别的聊天发只能用主人专用的 `message` 工具。
- 手机:额度用完可确认交给另一个执行者继续;重发不再重复执行;电脑上的会话可在手机上阅读、显式接着做。
- Markdown 强调在中文字体下看得见了。

## 升级须知

会跑两个数据库迁移(v71:记录每一轮实际发出了什么;v72:桌面 / 手机那一轮的附件与过程),自动完成,不动已有数据。手机 app 需要更新到包含 `expo-audio` 的新版本才能播放语音附件。
