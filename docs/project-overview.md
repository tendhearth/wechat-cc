# Tendhearth 项目总览：从微信入口到个人 CC

> 2026-10-01 整理快照。主产品已合入基线：`dev d8141c14`（#167；原整理基线 #163 后补核验 #165–#167）。附属仓库依据本机现有源码与 Git 历史，未核验远端及当前运行环境。当前任务进展继续看 [roadmap](roadmap.md)，具体能力看 [INDEX](INDEX.md) 中的现行参考文档。

## 现在是什么

**Tendhearth CC 是住在用户自己电脑上的个人 AI。** 用户认识的是 CC：跟它说话，让它记住重要的事，交办工作，需要决定时再回来拍板。Claude Code、Codex、Cursor 和 API 模型是它调用的能力。桌面、微信与原生手机访问同一个常驻后台，浏览器/PWA 也保留。

这句话归纳了六个月的产品变化；不是说所有设想都已验收。长期记忆、真实微信资料与执行能力已经有实现；跨设备真实使用、恢复、权限与发布仍须分别验收。

本地优先指持久化与控制权在自己的电脑。手机中继转发加密数据；调用模型时，选定上下文仍会送到用户配置的 AI 服务。不能把这些合并表述为「所有处理都离线」或「数据绝不发送给模型」。见 [architecture](architecture.md) 与 [手机隐私要求](../apps/app/README.md)。

## 四月到现在：重点变了什么

现存主仓库 Git 历史从 **2026-04-06（洛杉矶时间）**开始。这是历史记录的起点，不代表此前没有构想或仓库外工作。

| 阶段 | 当时要解决的问题 | 留到今天的东西与变化证据 |
|---|---|---|
| 4 月初—中旬：微信连接 Claude Code | 离开电脑还能与正在运行的 Claude 会话交互、确认权限 | 微信渠道仍在。起点 `7ecfc438`；早期 README `70764955` 明写 Channel plugin。产品当时依赖现有 Claude 会话 |
| 4 月下旬：常驻服务与记忆 | 对话不能跟着终端进程消失，需要主动性、记忆和桌面入口 | Agent SDK daemon、memory-first 陪伴、安装器与记忆视图。`4917d4e8`；[RFC01](rfc/01-architecture.md)、[陪伴记忆设计](specs/2026-04-24-companion-memory.md) |
| 5—6 月：多执行者与权限边界 | 用户可以选不同能力，记忆与工具不能绑在某一家模型上 | Claude / Codex 对等、后来加入 Cursor 与隔离权限。`bfebdecd`、`8cb5ae73`、`00267395`；[RFC03](rfc/03-multi-agent-architecture.md)。它证明对话协作已有实现，不等于后来的持久协调账本已完成 |
| 7—8 月：关系、活人感与真实资料 | 能力之外，CC 应该懂用户、适时出现，生活资料应留在本机 | 活人感与本地知识；8 月 PWA、设备配对和加密中继。`004432a3`、`280a3f37`、`986bb968`；[当时战略](design/roadmap.md)。微信逐渐成为入口之一 |
| 9 月：能交出去做完的工作 | 一句话之后要看见执行、回答问题、批准权限、审阅成果和恢复 | 原生执行者、工作台、matter、文件夹占用、自维护。`70a61ae4`、`dc4de4eb`、`b7ea6bff`；[工作台能力](cc-workbench.md)。9 月中旬源码交付和后来公开发版是两件事 |
| 9 月末—10 月初：原生手机与一致体验 | 手机既能找 CC 说话，也能继续同一件事；两端看起来像同一个产品 | 协议包 → 中继 → Expo → 通知 → 手机聊天 → 设计统一；#153–#163，随后配对体验 #165、手机续接 #166、发送拒绝文案 #167 也已合入。当前不是「等决定是否做原生」，而是已有实现、继续做使用与发布验收 |

历史文档按作者当时的日期保留；月份级归纳采用洛杉矶时间。比如工作台 `70a61ae4` 是本地 9 月 13 日，报告文件名用 UTC 的 9 月 14 日。

这条变化可以归纳为：**渠道连接 → 常驻个人后台 → 多执行者能力 → 陪伴与真实记忆 → 统一事项与执行 → 跨设备的 CC。** 增加的不是互不相干的几个 app，而是同一个 CC 的连续使用方式。

## 附属项目也在收敛

**hearth** 的 4 月起点是聊天驱动的 LLM Wiki / second brain runtime；同月收敛为 agent-native vault 治理层与 vendor-neutral substrate（`b28eca1`、`e1b9fe1`、`30a2f1d`）。8 月实现受信任渠道写入、联邦查询、consumer permission broker、文件 source 与 Spotlight 检索（`93a3913`、`360ee05`、`34faa6d`、`1bb6839`、`0415e72`）。所以它更接近有权限的知识入口，而不是要求把所有资料搬进同一个 wiki。现有验证记录包括两个真实文件 source 的权限与审计，不能扩大为微信与文件两类真实源均已验收。

**wxvault / 插件库** 从解密与独立 MCP 工具，演变为按需同步、资料接入与后台知识能力。插件库的 manifest 明确：`wxgraph`、`wxfacts`、`wxperson` MCP 工具已退役并保留库代码；`wxsearch` 保留 embedding 子进程与模型策略，`wxmedia` 仍声明媒体工具。能力所有权应以当前 manifest 和 daemon 为准，不能按旧插件设计数出一套重复的知识系统。

上述是源码与历史核查，不是运行健康检查。尤其 #160 修复了打包版找不到内置插件的问题；合入修复后仍须确认真实部署里的插件加载及 wxvault 调用。

## 现在的形象与入口约定

正式产品名 **Tendhearth CC**；对话和角色仍称 **CC**，不是把 CC 展开成 Claude Code。[命名规范](reference/product-naming.md)规定技术标识兼容边界。

10 月 1 日的新决定已经取代最初手机深色预览：**暖纸底、全站衬线、一种深绿动作色；界面不切深色，只有 CC 根据真实在场信号切换 Light / Dark。** Token 出处是 `packages/design-tokens/src/index.ts`，原则见[设计统一 spec](superpowers/specs/2026-10-01-tendhearth-design-unify-design.md)。9 月 30 日简报与早期可点击设计保留作历史，不继续当成当前实施规范。

当前主动作是「跟 CC 说」，交办是显式选项。编码执行者、项目路径、模型与连接详情按用户需要展开；它们继续承担真实功能，但不要求普通用户先理解整套 agent 架构。

## 整理建议与文档分工

以下是本次归纳建议，不是新增的已批准产品决定：

1. **主线围绕同一个 CC 的使用闭环。** 先把当前手机配对、聊天、通知、决定和恢复收口；单独记录真机与发布证据。
2. **知识与资料底座各守职责。** hearth 管治理与多源权限，wxvault 管资料取回，daemon 管自己的记忆与执行。后续接入以具体数据流和权限验收，不因同属 Tendhearth 就直接合仓。
3. **探索单独排期。** 社交、Widget / Live Activities、完整跨 agent 协调仍有价值，但不与已实现手机能力混写成同一种交付状态。
