# CC 一起做 · 协作现场交互样板

预览：<http://127.0.0.1:4186/apps/desktop/art/cc-agent-workspace/preview.html>

这是已确认的三栏界面方向的**合成内容交互样板**。没有连接模型、调用执行接口、读取项目文件、申请真实权限或停止真实进程。页面禁止网络请求。刷新会重置所有样例状态；不会保存用户输入到服务器。

## 可以检查什么

- 左侧切换「CC 桌面应用」「个人网站」；各自保存本页内的草稿、会话补充、选中节点、流程展开与滚动位置。
- 中间显示 CC 分派给执行者的主流程。Claude 与 Codex 的子任务默认收拢，明确归属于各自主执行者，可展开并单独查看。
- 右侧显示所选执行者/子任务的活动、文件差异、原始会话和交接信息。窄窗口改为可收起的抽屉。
- 顶部演示条切换执行中、子任务待授权、成果就绪、连接中断四个状态。
- 授权操作只改变样例；拒绝后显示受阻，不把工作标为完成。
- 停止操作先显示范围，再模拟发出请求。主流程上的「模拟收到停止确认」完成确认过程。单个子任务只停止自身与后代；停止整件事覆盖未结束步骤；已有成果保留。
- 完成场景提供 CC → Claude 的复核交接。未开始的复核没有接收回执，不能显示另一执行者的回执。
- 输入框与「补充要求」只记录示例消息，明确提示未发送给真实执行者。添加项目、附件、语音等只展示设计说明。

## 后续接真实数据的边界

现有 `src/core/workbench/store.ts` 的 Task/Event 仍是一层任务和文字事件。本轮没有修改它，也没有实现多 Agent 调度。

真实接入需要明确的项目、会话、运行和父子节点身份，以及接收确认、权限请求、取消确认、成果版本等事件。提供方不暴露的子任务信息应标为不可见，不通过输出文本猜测出一棵树。父子会话隔离不能替代文件工作区隔离。当前可点击控件并不代表每家提供方都支持同样的操作。

## 文件

- `fixtures.js`：两个项目、提供方主步骤及子任务的合成内容。
- `model.js`：项目内状态、后代范围、停止/确认、权限与交接记录。
- `preview.js` / `preview.css` / `preview.html`：交互与界面。
- `model.test.js`：操作范围和可信状态回归检查。
