# 一张慢慢变顺手的桌子 · 设计研究 04

设计稿，不接入正式页面。本轮旨在确定工作区的产品交互，不能用它证明后台已具备音乐创作或多助手派工能力。

从仓库根目录提供静态服务后，打开 `apps/desktop/art/cc-growing-workspace/preview.html`。顶栏可切换两个项目、三个阶段。

## 推荐设计

沿用「此刻 / 一起做 / 回忆」的稳定外层。一起做以作品为中心，CC 在旁边保留判断、解释下一步和协调执行。工作区不要求用户先选择职业、模型、插件或填任务表。

1. 一个念头：已有一段旋律或一张草图。CC 提议一个具体的小步骤。
2. 第一版：音乐可试听，游戏可试玩。工具因当前需要出现，用户可以明确留下。结果先被感知，再讨论取舍。
3. 越来越顺手：作品、上次判断和用惯的工具留在原处。CC 接上未完成的问题，用户也可以改变方向。

音乐：试听、A/B、时间标记。游戏：试玩、问题位置、改动检查。它们共享操作原则，但呈现的工作对象不同。

## 取舍

- 不选纯职业模板：一个人可能跨领域；同一项目的不同阶段也需要不同工具。
- 不选任意自生成页面：不断重排会破坏肌肉记忆，生成控件也难以保证稳定。
- 选择经过验证的组件组合。先临时出现、再由用户保留；布局可固定和撤回。需要定制工具时，单独预览、验证后加入。
- 不把 CC 变成只会报进度的客服。工作里的陪伴来自一起做过的选择及连续性；独立生活仍在此刻和回忆。

## 这份样稿可以操作什么

- 两个项目 × 三个阶段切换，项目中的选择、草稿、保留工具互不影响。
- A/B 试听：浏览器合成 16 秒简单音调；A 多一个伴奏音，B 留白。不是模型生成的音乐。
- 试玩：先点击「开始试玩」，用左右方向键或画面上的按钮移动。场景是 HTML/CSS 示意，不是用户游戏工程。
- 保留工具、选择方向、记录意见、查看过程与项目范围。
- 对话提交产生明确标注的固定示例回应，无模型调用。
- 刷新重置，不读取、上传或修改本机文件。

复用冻结的 CC 正身与实体 mask，不改变资产。生产 `src/` 和后台未修改。
